# 多文件系统磁盘挂载测试指南

## 一、文档目的

用于执行接口测试用例「挂载文件系统为 ext2、ext3、ext4、exFAT、vfat、btrfs、NTFS、hfsplus 的磁盘成功」时，准备一块**包含多种文件系统分区的测试磁盘**，并完成挂载验证。

对应接口：`POST /v2/disk/MountDisk/{name}`（挂载硬盘，参数 name 为**分区名**，如 `sdd1`）。

核心思路：**一块盘划分多个分区，每个分区格式化为一种文件系统，逐个挂载验证**。

## 二、磁盘规划

以一块 128GB（实际约 119.2GiB）空闲盘 `/dev/sdd` 为例，划分为 8 个分区：

| 分区 | 文件系统 | 标签(LABEL) | 分区名(PARTLABEL) | 大小 |
|------|----------|-------------|-------------------|------|
| sdd1 | ext2     | ext2fs      | ext2fs            | 14GiB |
| sdd2 | ext3     | ext3fs      | ext3fs            | 14GiB |
| sdd3 | ext4     | ext4fs      | ext4fs            | 14GiB |
| sdd4 | exfat    | exfatfs     | exfatfs           | 14GiB |
| sdd5 | vfat(FAT32) | vfatfs   | vfatfs            | 14GiB |
| sdd6 | btrfs    | btrfsfs     | btrfsfs           | 14GiB |
| sdd7 | ntfs     | ntfsfs      | ntfsfs            | 14GiB |
| sdd8 | hfsplus  | hfsplusfs   | hfsplusfs         | 14GiB |

> 说明：用例标题中 btrfs 出现了两次，实际为 8 种文件系统；vfat 即 FAT32。

## 三、操作步骤

### 第 1 步：确认目标磁盘

```bash
lsblk -f /dev/sdd
```

确认 sdd 为空闲盘（无分区、无挂载），**务必确认不是系统盘、不在存储池中**。

### 第 2 步：划分 8 个分区

```bash
parted -s /dev/sdd mklabel gpt
parted -s /dev/sdd mkpart ext2fs 1MiB 15GiB
parted -s /dev/sdd mkpart ext3fs 15GiB 29GiB
parted -s /dev/sdd mkpart ext4fs 29GiB 43GiB
parted -s /dev/sdd mkpart exfatfs 43GiB 57GiB
parted -s /dev/sdd mkpart vfatfs 57GiB 71GiB
parted -s /dev/sdd mkpart btrfsfs 71GiB 85GiB
parted -s /dev/sdd mkpart ntfsfs 85GiB 99GiB
parted -s /dev/sdd mkpart hfsplusfs 99GiB 113GiB
```

**命令解释：**

- `mklabel gpt`：建立 GPT 分区表；若磁盘存在旧的 dos 分区表或残留文件系统签名（fdisk 会提示 `The device contains 'dos' signature`），此命令会一并清除；
- `mkpart <分区名> <起始> <结束>`：创建分区。**第一个参数即分区名（PARTLABEL）**，TOS 识别磁盘依赖 PARTLABEL，这一步直接设置到位；
- `-s`：脚本模式，非交互执行，每行一条命令逐行粘贴执行即可。

> **为什么不建议用 fdisk 交互 + heredoc 批量输入？** 终端粘贴多行 heredoc 时容易丢行（实测第 8 个分区 `+14G` 丢失导致分区未创建，且 fdisk 可能直接退出不写盘）。parted 单行命令无此问题。

### 第 3 步：格式化分区（格式化时直接设置文件系统标签）

```bash
mkfs.ext2 -L ext2fs   /dev/sdd1
mkfs.ext3 -L ext3fs   /dev/sdd2
mkfs.ext4 -L ext4fs   /dev/sdd3
mkfs.exfat -n exfatfs /dev/sdd4
mkfs.vfat -F 32 -n vfatfs /dev/sdd5
mkfs.btrfs -f -L btrfsfs /dev/sdd6
mkfs.ntfs -f -L ntfsfs /dev/sdd7
mkfs.hfsplus -v hfsplusfs /dev/sdd8
```

**命令解释：**

- `-L` / `-n` / `-v`：分别为 ext 系列、exfat/vfat/ntfs、hfsplus 设置**文件系统标签（LABEL）**，与 parted 设置的 PARTLABEL 保持一致，TOS 识别磁盘需要 LABEL 和 PARTLABEL **同时存在**；
- `mkfs.btrfs -f`：btrfs 必须加 `-f` 覆盖旧签名，否则拒绝格式化；
- `mkfs.ntfs -f`：NTFS 快速格式化，避免全盘清零耗时；
- `mkfs.vfat -F 32`：明确指定 FAT32。

**工具缺失时报 `command not found` 需先安装对应软件包：**

| 工具 | 软件包 |
|------|--------|
| mkfs.exfat | exfatprogs |
| mkfs.vfat | dosfstools |
| mkfs.btrfs | btrfs-progs |
| mkfs.ntfs | ntfs-3g |
| mkfs.hfsplus | hfsprogs |

### 第 4 步：向每个分区写入测试文件

```bash
mkdir -p /mnt/tmp
for p in 1 2 3 4 5 6 7 8; do
  mount /dev/sdd$p /mnt/tmp
  echo "tos mount test fs_$p" > /mnt/tmp/test_file_$p.txt
  umount /mnt/tmp
done
```

写入测试文件的目的是：挂载成功后，文件管理里能看到分区内的文件，用于验证"文件管理能看到挂载分区中的文件"。

### 第 5 步：验证分区准备结果

```bash
lsblk -f /dev/sdd
blkid /dev/sdd*
```

预期看到 8 个分区，`FSTYPE` 分别对应 ext2 / ext3 / ext4 / exfat / vfat / btrfs / ntfs / hfsplus，`LABEL` 均为对应标签。

## 四、挂载验证

### 方式一：TOS 文件管理 UI

1. 刷新 TOS 文件管理（或磁盘管理），确认系统识别出 sdd 的 8 个分区；
2. 逐个分区点击「挂载」；
3. 进入文件管理，确认每个挂载点下能看到 `test_file_x.txt`。

### 方式二：Apifox 接口

对 `POST /v2/disk/MountDisk/{name}` 逐个传入 `sdd1` ~ `sdd8`（请求头需携带有效 Cookie 和 X-Csrf-Token，Content-Type 为 `application/x-www-form-urlencoded`），断言响应：

```json
{
  "code": true,
  "code_num": 0
}
```

再通过文件列表接口确认分区内文件可见。

## 五、判定标准（预期结果解读）

用例预期为「挂载该硬盘**所有能挂载**的分区，文件管理能看到挂载分区中的文件」，注意措辞是"**能**挂载"：

| 分区文件系统 | 预期结果 |
|--------------|----------|
| ext2 / ext3 / ext4 / vfat / NTFS / exFAT / btrfs | 挂载成功，文件管理可见测试文件 → 符合预期 |
| hfsplus | 大概率挂载失败（系统不支持），如实记录失败响应即可，**不算用例失败** |

**已知业务约束（前置条件）：**

1. 系统中**必须存在卷（Volume）**才能执行挂载，无任何卷时挂载失败；
2. 同一分区**重复挂载会失败**（已处于挂载状态），执行前确认各分区均为"未挂载"状态；
3. 磁盘只读模式下，读写挂载失败、只读挂载成功。

## 六、注意事项与常见坑

1. **fdisk heredoc 批量输入易丢行**：多行粘贴时个别行丢失，导致分区创建失败且 fdisk 直接退出不写盘，应改用 `parted -s` 单行命令；
2. **残留文件系统签名**：磁盘上原有的 ext4 等签名会残留在新分区上（lsblk 仍显示旧 FSTYPE），`parted mklabel gpt` 重建分区表可清除，或格式化前执行 `wipefs -a`；
3. **LABEL 与 PARTLABEL 缺一不可**：TOS 识别磁盘依赖两者同时存在，格式化和分区时一步设置到位；
4. **ext 系列设备设标签前必须先卸载**：对已挂载设备执行 mkfs/tune2fs 会报 `is mounted; will not make a filesystem here!`；
5. **格式化不可逆**：操作前务必确认目标磁盘无数据、非系统盘、不在存储池中。


如实记录每个分区的真实响应，不推测、不模拟。
