# 系统盘格式化判定跳过问题交接文档

- 文档日期：2026-09-08
- 涉及设备：`10.18.15.120`、`10.18.15.160`、`10.18.15.136`
- 关键现象：在线安装选择 GPT 四分区旧系统盘时，未触发格式化，旧系统分区残留并引发后续系统盘迁移失败
- 判断标准来源：`D:/WXWork/1688855297808048/Cache/File/2026-09/磁盘格式化判定逻辑.md`
- 当前文档仅用于交接和开发定位，不包含对磁盘、RAID 或系统配置的修改指令

## 一、一句话结论

当前格式化判定逻辑把“存在任意一个 TOS/RAID 标记 + GPT + p2 为 8G/32G”的 GPT 四分区旧系统盘判定为 `NeedPartition=1`，即“不需要重新分区”。因此安装流程跳过重新分区，旧分区和旧标记继续保留，后续系统盘迁移因目标盘尺寸不匹配失败。

## 三、当前格式化判断标准

判断标准的四个维度如下：

| 维度 | 判断条件 | 通过条件 |
|---|---|---|
| ① TOS 分区标记 | `blkid`/`mdadm` 检查 sdX1~sdX4 | `UTOSDISK`、`UTOSCORE`、`UTOSSWAP`、`UTOSUSER` 四个标记中**任意一个**命中 |
| ② 分区表类型 | `parted` 检查 | 必须是 GPT |
| ③ 第 2 分区大小 | 读取 GPT 表项 | 必须在 `8192±500` 或 `32768±500` MB |
| ④ ForceCoreSize | 内存状态 | 未设置，或设置值与检测到的 core size 一致 |

结果含义：

```text
NeedPartition = 0：需要重新分区
NeedPartition = 1：不需要重新分区，沿用原分区
```

只有四个维度全部通过，才会返回 `1`。

## 四、为什么 GPT 四分区旧盘跳过了格式化

### 4.1 判定条件全部被满足

一块 GPT 四分区、带旧 TOS/RAID 标记的磁盘会同时满足：

```text
① 有 UTOSCORE 或 UTOSSWAP 或 UTOSUSER 标记 → 通过
② GPT 分区表 → 通过
③ p2 = 32,768 MB → 通过
④ ForceCoreSize 未设置或匹配 → 通过
```

因此：

```text
needPartition() = 1
FSM checkDisk 不返回 -5
StartPartitionDisk() 跳过 partitionDisk()
旧 GPT 四分区和旧标记被保留
```

### 4.2 还有一个更容易漏掉的分支

判断标准中标记维度是“四选一”。同时判断标准明确提到：

```text
ClearUnCheckDiskLabel 清理 sdX1、sdX2、sdX3
但不清理 sdX4
```

如果一块盘之前作为“未选中的 TOS 盘”被清理，可能会出现：

```text
sdX1：UTOSDISK 已清除
sdX2：UTOSCORE 已清除
sdX3：UTOSSWAP 已清除
sdX4：UTOSUSER 仍保留
```

即使它已经是“半残盘”，因为 `UTOSUSER` 仍存在，`needPartition()` 仍返回 `1`，再次选中时依然跳过格式化。标准文件记录的生产测试结果也提到，仅在 `sdX4` 标记存活时仍会被判定为可沿用盘。

### 4.3 现有标准没有检查的部分

当前判断标准没有把下面这些作为“必须重新分区”的直接条件：

```text
GPT + 4 分区
存在旧系统分区标签
存在 linux_raid_member
存在 mdadm superblock
存在旧 TOS 系统盘成员关系
sdX3 是否满足当前 md8 尺寸要求
```

因此：

```text
系统不是没有检测
而是把“符合旧 TOS 布局的盘”误认为“已经可用的系统盘”
从而跳过了格式化
```

## 五、实际失败链

```text
在线安装选中 GPT 四分区旧盘
→ needPartition = 1
→ 跳过重新分区
→ 旧分区和旧系统标记保留
→ 后续系统盘迁移
→ 目标盘 sdc2 加入 md9
→ 目标盘 sdc3 加入 md8
→ mdadm 报错：
   mdadm: /dev/sdc3 not large enough to join array
→ 迁移失败，系统盘页面仍显示目标盘为系统盘
```

十六进制之外的字节计算：

```text
md8 数据区 = 2,045,902,848 B
正常 p3 扣除 2,097,152 B 后 = 2,045,771,776 B
旧 sdza3 扣除 2,097,152 B 后 = 2,045,902,848 B
正常 p3 少 131,072 B
```

因此：

```text
正常布局的 p3 对于 15.136 当前 md8 来说偏小
```

## 六、修复建议

### 6.1 标记判断不能“四选一”

建议区分：

```text
完整系统盘：
sdX1 有 UTOSDISK
sdX2 有 UTOSCORE
sdX3 有 UTOSSWAP
sdX4 有 UTOSUSER

部分/异常旧系统盘：
只有 UTOSUSER，或只有 UTOSCORE，或标记不完整
=> 必须重新分区
```

### 6.2 增加“部分旧系统盘”状态

例如：

```json
{
  "device": "/dev/sdc",
  "need_partition": true,
  "reason": "partial_tos_markers",
  "old_markers": [
    "UTOSUSER"
  ],
  "gpt_partition_count": 4
}
```

### 6.3 清理未选中盘时同步处理 sdX4

`ClearUnCheckDiskLabel` 应同时清理：

```text
sdX1 UTOSDISK
sdX2 UTOSCORE
sdX3 UTOSSWAP
sdX4 UTOSUSER
```

避免只在 sdX4 保留一个标记后再次被误判。

### 6.4 增加 p3 尺寸校验

在 `needPartition()` 或迁移前增加：

```text
校验 sdX3 实际字节数
校验当前 md8 数据区大小
校验 RAID metadata offset
若 sdX3 < md8 要求，必须返回 NeedPartition = 0
```

### 6.5 FSM 增加部分标记拦截

当前 FSM 只在 `NeedPartition=0` 时中断。建议：

```text
NeedPartition = 1 但存在部分 TOS 标记
=> 仍记录 -5 错误
=> 界面提示“磁盘存在旧系统分区，需要格式化”
```

### 6.6 迁移增加事务性保护

```text
先校验目标盘 p3
再添加 md9 成员
再添加 md8 成员
任意一步失败：
回滚已加入 md9 的成员
标记 migration_state=failed
不将目标盘展示为正常系统盘
```

## 七、验收标准

1. 使用 GPT + 4 分区且包含旧系统/RAID 标记的磁盘执行在线安装，必须触发格式化提示或自动格式化。
2. 格式化后旧 `UTOSDISK`、`UTOSCORE`、`UTOSSWAP`、`UTOSUSER` 和 `linux_raid_member` 必须消失。
3. 安装完成后目标盘应只有新的 TOS 布局，不能保留旧系统分区。
4. 磁盘只残留 `sdX4` 标记时，也必须判定为需要格式化。
5. 目标盘 p3 大小不能满足当前 `md8` 要求时，应在添加 `md9` 前失败。
6. 迁移失败后，`GetSysDiskLists` 不能把目标盘作为正常系统盘返回。
7. 迁移失败后界面应显示“迁移失败/待处理”，而不是“系统盘/正常”。
8. 正常 15.120/15.160 布局与 15.136 旧布局应作为回归测试用例同时保留。
