## 二、操作前确认

必须先确认磁盘身份和存储栈：

```bash
hostname
date
cat /etc/installed_disk.json
lsblk -o NAME,MAJ:MIN,SIZE,TYPE,FSTYPE,LABEL,MOUNTPOINTS,MODEL,SERIAL
cat /proc/mdstat
mdadm --examine /dev/sda2
mdadm --examine /dev/sda3
mdadm --examine /dev/sda4
pvs
vgs
lvs -a
findmnt | grep -E '/dev/md0|/dev/md1|vg0|vg1|/Volume'
```

本次确认：

- HDD1 是 `/dev/sda`，序列号 `1A128GE314Q00247`。
- `md0` 唯一成员是 `/dev/sda4`。
- `sda2`、`sda3` 是旧 RAID 超级块，不属于当前 `md8/md9`。
- `vg0/lv0/lv1` 均未激活，`md0/vg0` 未挂载。
- 当前系统使用 `sdza/sdzb` 上的 `md8/md9`。

该设备上 `test` 用户 UID=0，`root` 用户 UID=9999。因此 LVM 命令直接由 `test` 执行，不要用 `sudo`；`sudo` 会切换到 UID 9999，LVM 会提示 `Running as a non-root user`。

## 三、实际删除命令

按顺序执行：

```bash
lvremove -f vg0/lv0
lvremove -f vg0/lv1
vgremove -f vg0
pvremove -f /dev/md0
mdadm --stop /dev/md0
mdadm --zero-superblock /dev/sda4
mdadm --zero-superblock /dev/sda2
mdadm --zero-superblock /dev/sda3
udevadm settle
systemctl restart StorageManager.service
```

实际输出：

```text

Logical volume "lv1" successfully removed
Volume group "vg0" successfully removed
Labels on physical volume "/dev/md0" successfully wiped.
mdadm: stopped /dev/md0
StorageManager.service: active
```

## 六、复用流程

后续遇到同类磁盘时，按以下顺序处理：

1. 通过 `/etc/installed_disk.json`、序列号、by-path 确认目标磁盘。
2. 通过 `/proc/mdstat` 排除系统盘、swap 和已有存储池。
3. 通过 `findmnt` 确认目标 LV 没有挂载。
4. 删除目标 VG 的所有 LV。
5. 删除目标 VG。
6. 清除目标 md 设备的 PV 标记。
7. 停止目标 md 阵列。
8. 清除目标磁盘各分区的 RAID 超级块。
9. 执行 `udevadm settle`。
10. 重启 `StorageManager.service`。
11. 清理 `/etc/mdadm/mdadm.conf` 中失效的 md 行。
12. 复查 md、LVM、挂载、文件系统标签和 StorageManager 日志。

## 七、风险说明

1. 上述命令不可逆，执行前必须确认目标磁盘不需要保留数据。
2. 不能只按 `HDD1`、`md0` 或 `vg0` 判断，必须同时核对序列号、by-path 和 `/proc/mdstat`。
3. 本次未删除分区表。如果 StorageManager 仍不接受 HDD1，需要另行确认是否清理分区表和 `/dev/sda1` 的 `UTOSDISK` 标记。
4. LVM 历史归档仍保留在 `/etc/lvm/archive/vg0_*.vg`，不影响 HDD1 释放。
