# 跨平台同步指南（macOS ↔ Windows）

## 同步原理

```
┌─────────────────┐         GitHub          ┌─────────────────┐
│   家 (macOS)     │ ←── git push/pull ──→  │  公司 (Windows)   │
│                  │                         │                  │
│  代码 ✓ 同步     │                         │  代码 ✓ 同步      │
│  配置 ✓ 同步     │                         │  配置 ✓ 同步      │
│  数据 ✓ 同步     │                         │  数据 ✓ 同步      │
│  报告 ✓ 同步     │                         │  报告 ✓ 同步      │
│  笔记 ✓ 同步     │                         │  笔记 ✓ 同步      │
│  venv ✗ 不同步   │                         │  venv ✗ 不同步    │
│  （本地重建）     │                         │  （本地重建）      │
└─────────────────┘                         └─────────────────┘
```

**核心原则**：除了 `venv/` 虚拟环境以外，代码、配置、数据、报告等内容都同步。`venv/` 在每台机器上各自重建即可。对于机器间的配置差异（如服务器地址），通过 `local.yaml` 本地覆盖解决。

## Windows 首次设置（在公司电脑上做一次）

### 1. 安装必要软件

#### Python 3.12+
- 下载：https://www.python.org/downloads/
- 安装时 **勾选 "Add Python to PATH"**
- 验证：打开 PowerShell，输入 `python --version`

#### Git
- 下载：https://git-scm.com/download/win
- 安装时选择默认选项即可
- 验证：`git --version`

#### Chrome 浏览器（UI 自动化需要）
- 确保安装了最新版 Chrome

### 2. 克隆仓库

```powershell
# 在 PowerShell 中执行
cd C:\Users\你的用户名\Desktop
git clone https://github.com/你的用户名/test_dev_projects.git
cd test_dev_projects
```

### 3. 创建虚拟环境并安装依赖

```powershell
# 创建虚拟环境
python -m venv venv

# 激活虚拟环境（Windows 用 Scripts\activate）
.\venv\Scripts\activate

# 安装所有依赖
pip install -r requirements.txt
```

### 4. 创建本地覆盖配置（解决服务器地址差异）

```powershell
# 复制模板为本地配置
Copy-Item ui_automation\config\local.yaml.example ui_automation\config\local.yaml
Copy-Item api_testing\config\local.yaml.example api_testing\config\local.yaml
```

然后编辑 `local.yaml`，填入本机的服务器地址（详见下方「本地覆盖配置」章节）。

### 5. 验证环境

```powershell
python --version       # 应该显示 Python 3.12.x
pytest --version       # 应该显示 pytest 9.x
pytest --collect-only  # 应该能收集到测试用例
```

## 跨平台注意事项

### 1. 路径问题（已处理）
项目代码中使用了 `os.path.join()` 构建路径，自动适配 `/` 和 `\`，**不需要手动修改任何代码**。

### 2. ChromeDriver
Selenium 4.x 自带 ChromeDriver 管理器，会自动下载匹配的驱动，**两个平台都不需要手动安装 ChromeDriver**。

### 3. 换行符
Git 默认会处理 LF（macOS）和 CRLF（Windows）的转换。如果遇到问题，在 Windows 上执行：
```powershell
git config --global core.autocrlf true
```

### 4. 编码
所有文件使用 UTF-8 编码，YAML 文件的中文在两个平台都能正常读取。

## 本地覆盖配置（local.yaml）

### 为什么需要 local.yaml？

两台机器的 TOS 服务器地址不同：
- **Mac（家里）**：`http://localhost:8181`
- **Windows（公司）**：`http://192.168.64.7:8181`

如果每次都改 `environments/test.yaml` 再提交，会导致冲突。`local.yaml` 方案让每台机器维护自己的覆盖配置，完全不进入 Git。

### 配置加载优先级

```
environments/{TEST_ENV}.yaml  (Git 同步，团队共享)
        ↓ 被覆盖
config/local.yaml             (本地文件，.gitignore 排除)
```

### 首次设置（在新机器上做一次）

#### Mac

```bash
# UI 自动化模块
cp ui_automation/config/local.yaml.example ui_automation/config/local.yaml

# API 测试模块
cp api_testing/config/local.yaml.example api_testing/config/local.yaml

# 编辑 local.yaml，填入本机配置
nano ui_automation/config/local.yaml
nano api_testing/config/local.yaml
```

#### Windows

```powershell
# UI 自动化模块
Copy-Item ui_automation\config\local.yaml.example ui_automation\config\local.yaml

# API 测试模块
Copy-Item api_testing\config\local.yaml.example api_testing\config\local.yaml

# 编辑 local.yaml，填入本机配置
notepad ui_automation\config\local.yaml
notepad api_testing\config\local.yaml
```

### Mac 端 local.yaml 示例

**ui_automation/config/local.yaml**:
```yaml
base_url: "http://localhost:8181"
```

**api_testing/config/local.yaml**:
```yaml
base_url: "http://localhost:8181/api/v1"
```

### Windows 端 local.yaml 示例

**ui_automation/config/local.yaml**:
```yaml
base_url: "http://192.168.64.7:8181"
```

**api_testing/config/local.yaml**:
```yaml
base_url: "http://192.168.64.7:8181/api/v1"
```

### 验证配置是否生效

```bash
# 在项目根目录运行（Mac 和 Windows 语法相同）
python -c "from ui_automation.config.settings import settings; print(settings)"
python -c "from api_testing.config.settings import settings; print(settings)"
```

输出应该显示你 local.yaml 中的地址，而非 environments YAML 中的地址。

### 关于 local.yaml 的常见问题

**Q: 我没有创建 local.yaml 会怎样？**
A: 完全没问题，系统会直接使用 environments/{env}.yaml 的配置，行为与之前完全一致。

**Q: local.yaml 能覆盖哪些配置项？**
A: 能覆盖 environments YAML 中的任何字段。支持深度合并——例如你只覆盖 `browser.headless: true`，其他浏览器配置不受影响。

**Q: 我想临时测试另一个环境怎么办？**
A: 用 TEST_ENV 环境变量切换即可，local.yaml 会在新环境配置的基础上继续覆盖。

## 常见问题

### Q: Windows 上 `python` 命令找不到？
A: 重新安装 Python，确保勾选 "Add Python to PATH"。或者用 `py` 命令代替。

### Q: Windows 上激活虚拟环境报错 "无法加载文件...因为此系统上禁止运行脚本"？
A: 在管理员 PowerShell 中执行：
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

### Q: 两边的 Python 版本不一致怎么办？
A: 建议两边都用 Python 3.12+。只要大版本一致（3.12.x），小版本差异不影响使用。

### Q: venv/ 为什么不能同步？
A: 虚拟环境中包含编译好的二进制文件（.so/.dll），这些是平台特定的。macOS 的二进制在 Windows 上无法运行。所以每台机器各自用 `pip install -r requirements.txt` 重建即可，效果完全一样。

### Q: 报告和截图同步会不会太大？
A: 如果截图和报告文件积累太多导致 git push 变慢，可以编辑 `.gitignore` 取消注释最后几行来排除它们。通常刚开始不会有这个问题。
