# TOS5 → TOS7 升级链路复现结论（10.18.15.123 / F4-423）

> 记录时间：2026-08-20 16:10 CST  
> 结论：**未复现“两个系统盘 TOS6/TOS7 并存导致进不去系统”的问题**。

## 1. 执行链路

| 阶段 | 动作 | 版本 |
| --- | --- | --- |
| 1 | 安装 TOS 5 | 5.1.24 |
| 2 | 更新 TOS 5 新系统 | 5.1.145 |
| 3 | 更新 TOS 6 新系统 | 6.0.530 |
| 4 | 更新 TOS 7 新系统 | 7.0.747（用户记录的升级包；现场版本文件见下文） |

## 2. 执行现象

TOS6 升级 TOS7 后，设备重启进入初始化界面；拔掉旧的引导 USB（主板内置小 U 盘 / initboot）后，系统可正常进入 TOS7。

## 3. 现场证据（2026-08-20 16:02 复查）

| 检查项 | 结果 |
| --- | --- |
| 系统版本 | 现场 `/etc/tos/config/version` 实测为 `TOS_X642.0_7.0.023` |
| 内核 | `6.12.63+` |
| 根 `/boot/.tosloader` | `V6.1.56` |
| `md9` | 4/4 成员 active sync，clean，idle |
| `md8` | 4/4 成员 active sync，clean，idle |
| `md0` 数据卷 | `sdza4` 单盘，btrfs `/Volume1` 正常挂载 |
| EFI | 无 USB 引导项，`BootCurrent 0008`，BootOrder `0008,0005,0006,0007,0001` |
| 系统分区 | 四块盘 2 号分区逐块只读挂载均为 TOS7 内容，无 TOS6/TOS7 并存 |
| 引导分区 | SATA 两块一致、NVMe 两块一致，但两类盘 `bzImage` 不同；均为 TOS7 升级后产物 |

## 4. 未复现项

- 未出现叶总机器“系统完全进不去”的情况。
- 未出现“删除 TOS6 内核后发现两块 TOS6 + 两块 TOS7 系统盘”的情况。
- 四块原 TOS6 系统盘升级后全部为 TOS7 系统分区，不存在两套系统并存。

## 5. 本次现象根因判断

卡初始化界面的直接触发点是旧 initboot USB 的引导优先级高于系统盘；拔掉该 USB 后，系统从 SATA 盘 `UTOSDISK` 正常引导并完成 TOS7 启动。该现象与官方 F4-423 系列“NVMe 系统盘 + 旧 BIOS/USB 引导优先”的已知问题一致。

## 6. 版本备注

现场版本文件显示为 `TOS_X642.0_7.0.023`，与链路中记录的 `7.0.747` 不一致。如执行包确为 7.0.747，需要确认该平台版本文件与包名的对应关系，避免报告口径不一致。

## 7. 后续建议

- 暂时不要插回旧 initboot USB；如需要恢复 USB 引导，按官方 423 系列指引更新 BIOS 或调整启动顺序。
- 如需彻底验证叶总场景，可补充构造“两块盘保留 TOS6 系统分区、另两块升 TOS7”的用例后再升级对比。
- 升级前继续备份 `/Volume1`；当前数据卷仍为 `md0` 单盘。

## 8. 引导分区专项核查（是否残留 TOS6 引导）

2026-08-20 16:20 对四块盘 `sdx1` 引导分区逐块只读检查：

| 盘 | `boot/bzImage` 内核 | `boot/vmlinuz` 内核 | `grub.cfg` md5 | `EFI/BOOT/BOOTX64.EFI` md5 |
| --- | --- | --- | --- | --- |
| `sda1` | 6.1.120+（TOS6 遗留） | 6.12.63+（TOS7） | `5a281ff4...` | `f7a57b08...` |
| `sdb1` | 6.1.120+（TOS6 遗留） | 6.12.63+（TOS7） | `5a281ff4...` | `f7a57b08...` |
| `sdza1` | 6.1.58+（旧内核遗留） | 6.12.63+（TOS7） | `5a281ff4...` | `f7a57b08...` |
| `sdzb1` | 6.1.58+（旧内核遗留） | 6.12.63+（TOS7） | `5a281ff4...` | `f7a57b08...` |

四盘 `grub.cfg` 与 EFI 引导程序完全一致，且 `grub.cfg` 实际启动路径为：

```text
set root=(md/UTOSCORE-X86-S64)
linux /boot/vmlinuz type=raid hpet=disable security=
initrd /boot/initrd.img
```

即四块盘都是加载 `md9` 根文件系统中的 TOS7 `vmlinuz`（6.12.63+），不会加载引导分区里的旧 `bzImage`。

结论：四块盘存在旧内核文件残留（SATA 两块为 TOS6 的 `6.1.120+`，NVMe 两块为旧 `6.1.58+`），但**没有可被当前引导流程使用的 TOS6 引导分区**；随机选择任一盘的引导分区，都会进入相同的 TOS7 `vmlinuz` + `md9` TOS7 系统，不会出现“旧引导 + TOS7 系统”的启动失败。

## 9. 阵列构成与单盘测试策略

当前阵列构成：

| 阵列 | 用途 | 级别 | 成员 | 说明 |
| --- | --- | --- | --- | --- |
| `md9` | 系统根分区 | raid1，72 槽 | 4 块盘：`sda2/sdb2/sdza2/sdzb2` | 4/4 active，每块盘都有完整 TOS7 系统副本 |
| `md8` | 交换分区 | raid1，72 槽 | 4 块盘：`sda3/sdb3/sdza3/sdzb3` | 4/4 active |
| `md0` | 数据卷 | raid1，1 槽 | 仅 NVMe `2025102300225` 的 4 号分区（当前设备名 `sdzb4`） | 单盘数据卷，无冗余 |

策略结论：

- 单盘开机测试**仍然可以做**，因为 `md9/md8` 是多盘镜像，每块盘都自带完整系统副本；单盘启动验证的是“该盘独立引导 + 单成员 md9 能进 TOS7”。
- 但单盘测试排除了“多盘都在时随机选引导分区”的条件；若要复现叶总场景，需要四盘全部接上后反复重启或切换 BIOS 引导项观察。
- 判断盘身份不要用 `sda/sdb/sdza/sdzb` 设备名，本次已经出现 SATA 名称互换、NVMe 名称互换。应使用序列号：SATA `WCT1YJT8`/`Z52A4CEK`，NVMe `2025102300225`/`2025102300226`。
- 测试非数据盘时 `/Volume1` 不可用属于正常现象；只有 NVMe `2025102300225` 在机时数据卷才会挂载。
- 单盘测试会把 md9 变成 degraded 状态；四盘装回后 TOS7 启动时应自动 re-add，若没有恢复，先记录状态，不要手动 `mdadm --zero-superblock` 或格式化。
