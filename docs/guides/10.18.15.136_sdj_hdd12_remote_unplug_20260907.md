## 3. 拔盘/重新插回结果

系统已经通过内核/udev 层把 `/dev/sdj` 移除：

- `/dev/sdj` 不存在
- `/sys/block/sdj` 不存在
- `lsblk` 不再显示 `sdj`
- TOS 只显示 HDD1-HDD11，不显示 HDD12
- nginx/StorageManager 后端仍因 `sdj` 的 udev worker 超时和 `md0` 停止而卡住

当时 `mdadm --fail` 不适用，因为目标不在活跃 md 阵列中。后续已通过 `host37` 重新扫描恢复：


用法：

```bash
# 先只做校验
bash /path/to/nas_hdd_hot_remove.sh /dev/sdX --dry-run

# 目标不在系统盘、无挂载、非活跃 md 成员时执行内核删除
bash /path/to/nas_hdd_hot_remove.sh /dev/sdX --execute

# 仅当目标确实在活跃阵列且明确要模拟 RAID 故障时
bash /path/to/nas_hdd_hot_remove.sh /dev/sdX --execute --raid-fail

# 模拟插回：先 dry-run，确认 host37 和目标
HOST=host37 EXPECTED_SERIAL=ZGY7DDD2 \
  bash /path/to/nas_hdd_hot_insert.sh /dev/sdj --dry-run

# 真正执行 host37 重新扫描，等待 /dev/sdj 回来
HOST=host37 EXPECTED_SERIAL=ZGY7DDD2 \
  bash /path/to/nas_hdd_hot_insert.sh /dev/sdj --execute
```
