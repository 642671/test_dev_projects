# 10.18.15.136 系统盘布局对比与 sdza 完整性结论

- 日期：2026-09-07
- 目标设备：`10.18.15.136`（hostname `TNAS`）
- 对比设备：`10.18.15.120`、`10.18.15.160`
- 数据来源：标准机分区大小由用户提供的终端输出确认；`10.18.15.136` 当前状态由只读 SSH 现场采集
- 本报告只记录已核实的证据；未修改磁盘、RAID、分区或系统配置

## 1. 结论摘要

1. `10.18.15.120` 和 `10.18.15.160` 的系统盘分区布局一致，属于“标准/新布局”。
2. `10.18.15.136` 的旧系统盘 `/dev/sdza` 是另一种“旧布局”，主要区别在 `sdza3` 比标准机大 131,072 B。
3. `10.18.15.136` 的 HDD1 `/dev/sdc` 在迁移失败后，`p1/p2/p3` 与标准机布局一致，但 `p4` 不存在，且 `sdc3` 没有加入 `md8`。
4. 从我们记录的格式化快照开始到今天，`/dev/sdza` 没有被格式化、没有被重新分区、没有被清零。HDD1 迁移过程中所有分区和 RAID 操作都只作用于 `/dev/sdc`。
5. 当前 `md9` 仍保留 `sdza2` 和 `sdc2`；`md8` 仍只有 `sdza3`。`sdza` 仍作为旧系统盘成员存在。

## 3. 关键异常差异

标准机与 15.136 `/dev/sdza` 的差值为：

| 分区 | 标准机 | 15.136 sdza | 差值 |
|---|---:|---:|---:|
| `p1` | 298,844,160 B | 299,982,848 B | 标准机小 1,138,688 B |
| `p2` | 32,768,000,000 B | 32,768,000,000 B | 0 |
| `p3` | 2,047,868,928 B | 2,048,000,000 B | 标准机小 131,072 B |
| `p4` | 92,919,562,240 B | 92,884,000,256 B | 标准机大 35,561,984 B |

其中 `p3` 的差异是迁移失败的直接原因：

```text
2,048,000,000 - 2,047,868,928 = 131,072 B = 128 KiB
```

## 4. 为什么标准机的 p3 会导致 15.136 迁移失败

`/dev/md8` 当前信息：

```text
Array Size: 1997952 KiB
Array Size: 2,045,902,848 B
```

RAID 成员数据偏移：

```text
Data Offset: 4096 sectors = 2,097,152 B
```

旧系统盘 `sdza3`：

```text
2,048,000,000 - 2,097,152 = 2,045,902,848 B
正好等于 md8 可用数据区
```

标准机 `sdzb3/sdze3`，以及 15.136 HDD1 `sdc3`：

```text
2,047,868,928 - 2,097,152 = 2,045,771,776 B
比 md8 要求少 131,072 B
```

因此：

```text
如果标准机的 p3 作为目标盘加入 15.136 当前 md8：
mdadm: /dev/sdX3 not large enough to join array
```

这不是标准机或硬盘损坏，而是两套系统盘布局之间的分区边界差异：

```text
标准机：新布局，p3=2,047,868,928 B
15.136 旧系统盘：旧布局，p3=2,048,000,000 B
HDD1：按新布局创建，p3=2,047,868,928 B
```

## 5. sdza 是否曾经被格式化

结论：**没有。** 从可确认的格式化前快照到今天，`/dev/sdza` 都没有被格式化、重建分区或清除 RAID 签名。

## 6. 迁移失败后的状态

```text
HDD1 迁移前：
GPT，0 个分区

HDD1 迁移过程中：
StorageManager 自行创建 3 个系统分区

HDD1 迁移失败后：
sdc2 已加入 md9
sdc3 未加入 md8
sdc4 不存在
旧系统盘 sdza 未变化
```

因此界面当前显示两块系统盘，是因为 `md9` 同时有 `sdza2` 和 `sdc2`；但 HDD1 并不是完整系统盘。

## 7. 给开发的判断建议

系统盘列表不能只依据“是否在 `md9`”判断。建议增加以下强判断：

```text
一块盘显示为正常系统盘，必须同时满足：
1. sdX2 是 md9 的活动成员
2. sdX3 是 md8 的活动成员
3. sdX1 引导分区有效
4. 迁移状态不是 failed/partial
```

特别规则：

```text
sdX2 在 md9
但 sdX3 不在 md8
=> 判定为系统盘迁移失败
=> 不应出现在正常系统盘列表
```

建议后端增加：

```json
{
  "device": "/dev/sdc",
  "migration_state": "failed",
  "failure_stage": "add_swap",
  "failure_reason": "partition_too_small",
  "partial_member_in_md9": true,
  "display_as_system_disk": false
}
```

同时建议调整迁移顺序：

```text
先计算并校验目标 p3 尺寸
→ 满足 md8 需求后再创建/添加 md9 成员
→ md9 和 md8 都成功后才返回成功
→ 任何一步失败都回滚已添加的 md9 成员
```
