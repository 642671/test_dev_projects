# TOS API / CLI / Skill 测试工具 - 一屏显示优化方案

## Context

**当前问题**: 界面在1920x1080全屏模式下,顶部区域过高(约180px),双栏面板无高度约束,导致页面超出视口需要垂直滚动。

**优化目标**: 让1920x1080标准显示器全屏(F11)时,整个界面(顶部+左侧面板+右侧结果)无需滚动即可完整显示。

**核心策略**: 系统性压缩垂直空间(节省约70-90px),使用flex布局精确控制高度分配。

---

## 优化方案

### 一、视口空间重新分配

**1920x1080全屏可用高度**: 约1040px

| 区域 | 当前高度 | 优化后高度 | 节省 |
|------|----------|------------|------|
| 顶部区域 | ~180px | ~110px | **70px** |
| 主布局间距 | 14px | 10px | 4px |
| 面板头部 | ~46px | ~42px | 4px |
| 搜索区域 | ~110px | ~68px | **42px** |
| 结果卡片间距 | 12px | 8px | 4px |
| 输出区域最小高度 | 180px | 120px | **60px** |
| **总节省** | - | - | **~180px** |

## 预期效果

**优化前**: 顶部~180px + 双栏无约束 → 超出视口需滚动

**优化后**: 顶部~110px + 精确高度分配 → 一屏完整显示

**空间节省统计**:
- 顶部区域: 节省70px (39%)
- 面板布局: flex精确控制,左右等高
- 结果卡片: 输出区域从180px→120px (节省60px)
- **总可用滚动高度**: 从~690px→~810px (增加17%)

## 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 字体偏小 | 18px标题/11px标签在1080p下可能偏小 | 已提供900px/768px降级方案 |
| 输出截断 | max-height:200px需滚动查看长输出 | 保留overflow:auto,用户可滚动 |
| 暗色模式 | 新增样式需确保继承 | 使用CSS变量自动适配,需测试 |
| 高分辨率 | 2K/4K下可能过于紧凑 | 当前针对1080p,更高分辨率可恢复部分间距 |
