## 模型命名规则

1. 菜单显示名（`display_name`）可以自由命名，例如 `9007deepseek-v4-flash`。
2. 目录 ID（`id` / `slug`）是选择器和路由使用的稳定 key，例如 `deepseek-v4-flash-noontec-9007`。
3. 真正发给上游的模型名由 `upstreamModel` 或路由的 `modelMap` 决定，例如上游名必须是 `deepseek-v4-flash`。
4. 路由 `match.models` 必须填目录 ID，而不是显示名或上游名。

## 如何新增一个第三方模型

1. 在 CCSwitchMulti 中添加/确认上游 Provider（Base URL、API Key、模型列表）。
2. 确认模型目录（`cc-switch-model-catalog.json`）出现对应条目；`model`、`id`、`display_name` 必填，仅当上游模型名与目录 ID 不同时才需要 `upstreamModel`（或在路由上配置 `modelMap`）。
3. 在 `codex-multirouter` 的 `codexRouting.routes` 中新增一条路由：`enabled = true`，`match.models = [目录 ID]`；上游模型名不同时配 `modelMap`。
4. 在 CCSwitchMulti 中刷新模型目录/缓存，完全重启 Codex。
5. 用 `D:\test_dev_projects\ccsm_route_test.ps1` 或查看 `codex-router.log` 验证新模型是否路由到预期上游。

完整可照做的实例见 `06_ZhipuGLM接入实录.md`。
