| 现象 | 原因 | 处理 |
| --- | --- | --- |

| GPT 模型报 502 | OpenAI 域名没走代理或代理组失效 | 检查 Clash 规则模式下 `openai.com`/`chatgpt.com` 是否走有效代理组 |

## 左侧历史记录缺失

### 现象与根因

左侧列表由 `C:\Users\twm\.codex\sqlite\codex-dev.db` 的 `local_thread_catalog` 表驱动。`state_5.sqlite` 里即使有会话记录，只要 `local_thread_catalog` 缺行、或 `model_provider` 与当前 provider 标签不一致，左侧就只会显示很少的记录。

### 修复流程（推荐，在线完成，不退出 Codex）

使用 Skill `codex-history-repair`：

```powershell
python C:\Users\twm\.codex\skills\codex-history-repair\scripts\repair_history.py --status
python C:\Users\twm\.codex\skills\codex-history-repair\scripts\repair_history.py --apply
```

1. `--status` 只读诊断：比较 `catalog_visible_threads` 与 `state_unarchived_threads`。
2. `--apply` 先做时间戳备份，再在单个事务里把有效未归档会话写入 `local_thread_catalog`，统一 provider 标签，并递增 `catalog_revision`，让 Desktop 应用服务重载列表。
3. 修复后用 Codex 的线程列表接口验证旧会话 ID 是否重新出现；仅数据库计数非零不算成功。

### 约束与备份

- 不删除会话、不重写 `state_5.sqlite`、不动 `auth.json`、不打印凭据。
- 备份位于 `C:\Users\twm\.cc-switch\backups\`：Skill 生成的备份形如 `codex-history-repair-<时间戳>`；旧手工修复留下的备份是 `codex-sidebar-catalog-repair-<时间戳>`。
- 旧版脚本 `D:\test_dev_projects\fix-catalog.ps1` 会强退 Codex 再写库，是 Skill 的前身；日常优先用 Skill，不要随意反复退出 Codex。

## 其他提示

- 路由日志是排查模型可用性的第一证据：看 `model`、`provider`、`upstream_url`、`status` 四列。
- 修改目录、路由、config 后，先验证再重启；如果 CCSwitchMulti 或 Codex 升级改变了 `codex-dev.db` 的 schema，历史修复 Skill 需要同步适配。
