# Codex 接入公司 9007 模型（Noontec DeepSeek V4 Flash）操作手册

> 适用机器：本机（Windows）。记录日期：2026-08-11。
> 公司模型仅在公司网段内可达：`http://10.18.10.140:9007/v1`
> 本文档已统一归档到 `docs/codex-model-integration/`，配套总览见同目录 `README.md`。

## 1. 总体架构

Codex 并不直接请求公司地址，而是先经过 CCSwitchMulti 的本地代理，再由代理按路由分组转发到公司网关：

```text
Codex
  -> CCSwitchMulti 本地代理  http://127.0.0.1:15721/v1
      -> 路由分组  Codex GPT + DeepSeek
          -> 上游 Provider  Noontec 9007（路由日志中显示 Noontec_9007）
              -> 公司网关  http://10.18.10.140:9007/v1
                  -> 实际模型  deepseek-v4-flash
```

两个关键结论：

1. CCSwitchMulti 必须保持运行，关闭它 Codex 就无法通过本地代理访问任何模型（包括 GPT）。
2. 选择器里显示的 `9007deepseek-v4-flash` 只是显示名，真正发给公司网关的模型名是 `deepseek-v4-flash`。把带前缀的显示名直接发给远端会失败。

## 4. 首次配置步骤（从零开始）

### 4.1 在 CCSwitchMulti 中添加公司 Provider

1. 打开 CCSwitchMulti，进入 Codex 相关的 Provider 管理。
2. 新增 Provider：
   - 名称：`Noontec 9007`（旧文档和路由日志中也有 `Noontec_9007` 写法，指的是同一个 Provider）
   - Base URL：`http://10.18.10.140:9007/v1`
   - API Key：公司认证 Key
   - 模型列表：添加 `deepseek-v4-flash`（可先点“获取模型列表”自动拉取，失败时手动添加）
3. 保存后确认能连通，再继续下一步。

### 4.2 把模型加入路由分组

不需要新建独立分组，直接把公司模型挂到现有 `Codex GPT + DeepSeek` 分组即可，原有 OpenAI/SiliconFlow/DeepSeek 路由保持不变。

模型条目的关键字段：

```json
{
  "model": "deepseek-v4-flash",
  "upstreamModel": "deepseek-v4-flash",
  "display_name": "9007deepseek-v4-flash",
  "id": "deepseek-v4-flash-noontec-9007"
}
```

注意 `model` / `upstreamModel` 必须是 `deepseek-v4-flash`，只有 `display_name` 显示为 `9007deepseek-v4-flash`。

### 4.3 确认 Codex 配置生效

`C:\Users\twm\.codex\config.toml` 中应包含：

```toml
model_provider = "codex_model_router_v2"
model = "deepseek-v4-flash"

[model_providers.codex_model_router_v2]
name = "Codex GPT + DeepSeek"
base_url = "http://127.0.0.1:15721/v1"
wire_api = "responses"
http_headers = { x-cc-switch-proxy-mode = "router" }
```

注意：`model = "deepseek-v4-flash"` 是遗留默认值，模型目录中不存在该 ID；新会话要默认走 9007 应写 `model = "deepseek-v4-flash-noontec-9007"`。

### 4.4 重启并选择模型

1. 保持 CCSwitchMulti 运行。
2. 仅在模型菜单刷新失效时才需要完全退出 Codex（包括托盘进程），重新打开；历史记录修复不要用退出方式，请走 `codex-history-repair` Skill。
3. 在底部模型选择器中选 `9007deepseek-v4-flash`。
4. 如果列表里没有：确认模型目录已同步，再彻底退出重启 Codex；或使用 CCSwitchMulti 的“解锁模型菜单 / 刷新模型”入口。

## 5. Clash Verge 网络分流

公司内网必须直连，国外网站走代理，中国网站直连。

1. Clash Verge 使用**规则模式**（不要用全局模式，全局模式会把公司地址也送进代理导致失败）。
2. 在 `Merge.yaml` 的 `rules` 中，把以下规则放在最前面（必须在 `MATCH` 之前）：

```yaml
rules:
  # 公司模型网关直连
  - IP-CIDR,10.18.10.140/32,DIRECT,no-resolve
  # 内网直连
  - IP-CIDR,127.0.0.0/8,DIRECT,no-resolve
  - IP-CIDR,10.0.0.0/8,DIRECT,no-resolve
  - IP-CIDR,172.16.0.0/12,DIRECT,no-resolve
  - IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
  # OpenAI / ChatGPT 走代理组（替换为你实际代理组名）
  - DOMAIN-SUFFIX,chatgpt.com,曲面空间
  - DOMAIN-SUFFIX,openai.com,曲面空间
  - DOMAIN-KEYWORD,openai,曲面空间
  # 中国站点直连
  - GEOSITE,cn,DIRECT
  - GEOIP,CN,DIRECT
  # 其余流量走代理
  - MATCH,曲面空间
```

3. 保存后重启 Clash Verge 或让其重新加载配置。

## 6. 日常使用

建议启动顺序：

1. CCSwitchMulti（已配置开机自启、静默启动）
2. Clash Verge（规则模式）
3. Codex

在 Codex 底部模型选择器中选择 `9007deepseek-v4-flash` 即可使用公司模型。一个已经打开的会话会继续使用它启动时选择的模型，切到公司模型后，后续请求才会走公司网关。

## 7. 验证方法

### 7.1 验证公司网关连通性

```powershell
curl.exe -s -o NUL -w "%{http_code}" http://10.18.10.140:9007/v1/models -H "Authorization: Bearer <公司认证 Key>"
```

返回 `200` 说明网关可达且认证有效。

### 7.2 验证本地代理

```powershell
$auth = Get-Content "$env:USERPROFILE\.codex\auth.json" -Raw | ConvertFrom-Json
curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:15721/v1/models `
  -H "Authorization: Bearer $($auth.tokens.access_token)" `
  -H "x-cc-switch-proxy-mode: router" `
  -H "ChatGPT-Account-Id: $($auth.tokens.account_id)"
```

裸请求不带认证头会返回 `403`；带齐上面三个头后实测返回 `200`。

### 7.3 验证实际转发

发送一次请求后查看：

```text
C:\Users\twm\.cc-switch\logs\cc-switch.log
```

尾部应出现：

```text
[Codex] >>> 请求目标: http://10.18.10.140:9007/v1/responses (model=deepseek-v4-flash)
```

`codex-router.log` 中对应请求应显示 `upstream_url=http://10.18.10.140:9007/v1/responses` 且 `status=200`。

## 8. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `获取模型列表失败 ... /v1/models` | 公司地址被代理接管、网络不通，或本地代理未运行 | 切到规则模式；确认 `10.18.10.140/32 DIRECT` 规则存在；确认 CCSwitchMulti 运行；ping 公司网关 |
| `502 Bad Gateway: CC Switch local proxy failed` | CCSwitchMulti 退出或 `15721` 端口被占用 | 重启 CCSwitchMulti；确认 `config.toml` 的 `base_url` 仍是 `http://127.0.0.1:15721/v1` |
| 选择器里没有 `9007deepseek-v4-flash` | Codex 模型缓存未刷新 | 在 CCSwitchMulti 中刷新模型目录；必要时才完全退出 Codex（含托盘）后重启（历史修复请用 Skill，不要用退出方式） |
| 请求把 `9007deepseek-v4-flash` 发给远端后失败 | 上游模型名没映射 | 确认模型条目的 `model`/`upstreamModel` 为 `deepseek-v4-flash`，显示名才用 `9007deepseek-v4-flash` |
| 关闭 CCSwitchMulti 后 Codex 全部不可用 | 本地代理 `15721` 是必经链路 | 保持 CCSwitchMulti 运行（已设开机自启），不要关闭 |
| 用 GPT 模型时报 502 | OpenAI 域名没走代理，或 Clash 用了全局模式 | 确认规则模式下 `openai.com`/`chatgpt.com` 走代理组；检查代理组可用 |
| 公司内网地址走了代理导致失败 | 全局模式或规则顺序错误 | 使用规则模式；把 `IP-CIDR ... DIRECT` 放到 `MATCH` 之前 |

## 9. 注意事项

1. 认证 Key 属于公司内网凭据，本手册不明文保存完整值；完整值在 CCSwitchMulti 的 Noontec 9007 Provider 中。
2. 不改动现有 OpenAI/SiliconFlow/DeepSeek 路由，公司模型只是新增了一个 Provider 并加入现有分组。
3. 公司地址 `10.18.10.140` 只在公司网段可达，离开公司网络后该模型不可用，Codex 应切回 GPT 等可用模型。
4. 修改 `config.toml` 或模型目录后需要重启 Codex 才生效。
5. 公司另有 NewAPI 网关 `newapi.noontec.net`（内网 `10.18.2.100`），接入方式与路由见 `02_模型目录与路由.md`。
