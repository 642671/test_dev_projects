## 2. 关键机制（后续维护必读）

### 2.1 谁生成什么

cc-switch 在**启动时**用 `cc-switch.db` 重新生成下面两个文件，所以源头是 DB：

- `C:\Users\twm\.codex\config.toml`
- `C:\Users\twm\.codex\cc-switch-model-catalog.json`（即 `model_catalog_json` 指向的选择器目录）

**直接改这两个文件会在下次重启被覆盖**，必须改 DB。

### 2.2 可见模型是怎么算出来的

- 官方路由 `modelSelection.mode = "all"` → 取 `codex-official.modelCatalog` 全部
- 其它路由 `mode = "include"` → 取 `route.modelSelection.models` 与目标 provider
  `modelCatalog` 的**交集**
- `route.aliases` 会额外生成一个可见别名条目

所以「删官方模型」= 改 `codex-official.modelCatalog`；
「加一组模型」= 给目标 provider 加模型定义 + 新增一条路由。

### 2.3 官方模型缓存会回灌

`C:\Users\twm\.cc-switch\codex-official-models-cache.json`（上游 `github.com/openai/codex`）
里原本仍列着旧 GPT 和重名项。只要在 cc-switch 里手动「同步官方模型」，
被清掉的条目就会回来。因此清理脚本**同时清这个缓存**。
