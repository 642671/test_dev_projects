# 跨应用接口权限方案（应用授权模型）

> 适用：TOS 系统所有应用（存储管理、iSCSIManager、用户管理等）

---

## 一、背景与问题

### 1.1 现状

- 权限模型为"用户 — 接口归属应用"绑定：接口归属哪个应用，就按用户对该应用的权限放行；
- 存储管理应用对普通用户一刀切：普通用户不可访问存储管理应用、不可调用其接口。

### 1.2 问题场景

```
普通用户（被授予 iSCSIManager 应用使用权限）
        │ 使用 iSCSIManager 前端
        ▼
iSCSIManager 前端 ──调用──► GET /v2/storage/list/volume
                                   │ 该接口归属存储管理应用
                                   ▼
                        存储管理按"接口归属应用"校验：
                        普通用户？拒绝 ✗
```

iSCSIManager 前端会借调存储管理的接口（如 `GET /v2/storage/list/volume`）。用户使用被授权的 iSCSIManager 时，借调请求被存储管理按普通用户拒绝，导致应用无法正常使用。

### 1.3 根因

1. 权限校验只认"接口归属应用"，没有"调用方应用身份"维度；
2. 接口可被多个应用调用，但授权模型不支持"跨应用借调"；
3. 原设计未考虑"普通用户被授权某应用后，该应用需要调用其他应用的接口"。

---

## 二、方案目标

1. **普通用户被授予某应用权限后，该应用使用过程中调用的所有接口（含借调的其他应用接口）均可正常调用**；
2. 授权边界不扩大：普通用户直接访问未授权应用的接口，仍被拒绝；
3. 以现有接口 `GET /v2/desktop/list` 返回的应用作为权限唯一来源：**返回的应用即视为有权限使用的应用**；
4. 敏感应用支持细粒度授权（不默认给予超管权限），由产品定义权限等级；
5. 不引入接口白名单机制，规则统一、无维护成本。

---

## 三、核心概念

| 概念 | 说明 |
| --- | --- |
| 应用 | 权限授予的最小单元，如存储管理、iSCSIManager、用户管理等 |
| 调用方应用 | 发起接口调用的应用（前端所在应用） |
| 接口归属应用 | 接口所属的应用（仅用于展示/入口，不参与权限判定） |
| 应用授权 | 服务端维护的用户-应用授权关系，与 /v2/desktop/list 返回结果同源 |
| 权限等级 | 应用被授权时指定的操作范围（如只读/常规操作/完整管理），由产品定义 |
| 敏感应用 | 涉及数据安全或危险操作的应用（如存储管理），不可默认授予完整权限 |

---

## 四、权限模型

### 4.1 核心规则

1. **权限来源唯一**：用户登录后，`GET /v2/desktop/list?AllApplication=undefined` 返回的应用列表 = 该用户有权限使用的应用（服务端按应用授权过滤，无权限应用不返回）；
2. **默认放行**：凡是 /v2/desktop/list 返回的应用，作为"调用方应用"调用接口时默认放行（含借调其他应用的接口）；
3. **拒绝规则**：未出现在授权中的应用，作为调用方调用接口时拒绝（403）；
4. 权限校验**只看"当前用户对调用方应用是否有授权"**，与接口归属应用无关；
5. 超管/管理员：默认返回全部应用；普通用户：仅返回被授予的应用。

### 4.2 应用权限等级（产品定义）

普通应用与敏感应用区分授权：

| 等级 | 名称 | 说明 | 适用 |
| --- | --- | --- | --- |
| L1 | 只读 | 仅查看类接口 | 敏感应用默认档 |
| L2 | 常规操作 | 查看 + 常规配置操作 | 敏感应用可选档 |
| L3 | 完整管理 | 全部接口（含危险操作） | 普通应用默认档；敏感应用需管理员显式提升 |

- **普通应用**：授权即完整使用（L3），不做细分；
- **敏感应用**（存储管理、用户管理、系统设置等）：**不可默认授予 L3**，默认 L1，需管理员在授权时显式选择等级；
- 借调接口的权限随调用方应用的授权等级：调用方应用为 L1 时，其借调接口中涉及写操作的同样受限。

## 五、鉴权流程

### 5.1 应用入口获取（现有接口，无需新增）

登录后前端调用 `GET /v2/desktop/list?AllApplication=undefined`：

- 服务端按"应用授权"过滤，**只返回当前用户有权限的应用**；
- 超管/管理员：返回全部应用；普通用户：仅返回被授予的应用；
- 返回结果同时作为前端菜单/入口展示依据。

### 5.2 调用阶段

```
前端调用 ──► 统一鉴权中间件
                 ├─ 1. 从会话取出用户身份
                 ├─ 2. 从请求取出"调用方应用标识"（前端声明）
                 ├─ 3. 服务端校验：该用户对调用方应用是否授权（与 /v2/desktop/list 同源）
                 ├─ 4. 校验授权等级是否满足接口操作类型（敏感应用）
                 ├─ 5. 未授权 / 等级不足 → 403；已授权 → 放行
                 ▼
              业务接口（业务代码无感）
```

### 5.3 场景验证（iSCSIManager 借调）

```
普通用户（被授予 iSCSIManager）登录后
  │ 调用 /v2/desktop/list?AllApplication=undefined
  ▼
返回：仅包含 iSCSIManager（存储管理等未授权应用不出现）

普通用户使用 iSCSIManager 前端
  │ iSCSIManager 前端调用
  ▼
GET /v2/storage/list/volume + 调用方应用标识 = iSCSIManager
  ▼ 校验：用户对 iSCSIManager 已授权 → 放行 ✓
─────────────────────────────────────────────
普通用户直接调存储管理接口 + 调用方应用标识 = storage_manager
  ▼ 校验：用户对 storage_manager 未授权 → 403 ✓
```

## 六、实现方法（供评估选择）

### 方法一：统一鉴权中间件 + 调用方应用标识（推荐）

- 前端每个请求携带调用方应用标识（header，如 `X-App-Id`）；
- 后端统一中间件：token 鉴权 → 查应用授权（与 /v2/desktop/list 同源）→ 已授权放行，未授权 403；
- 优点：改动集中（一处中间件）、业务接口零改动、授权变更实时生效；
- 缺点：前端需全量补齐应用标识（存量改造工作量）。

### 方法二：网关层注入应用身份（前端无感）

- 网关根据请求来源（URL 前缀 / 入口路由）自动识别调用方应用并注入应用标识；
- 后端校验逻辑同方法一；
- 优点：前端零改动；
- 缺点：依赖网关能力，应用间互调或 URL 不规范的场景识别可能不准。

### 方法三：会话内置应用授权

- 登录 / token 刷新时，将用户的应用授权列表写入会话（或 token claims）；
- 后端直接读会话判断，无需每次查授权表；
- 优点：校验快、不依赖授权表查询；
- 缺点：授权变更需会话刷新（或 token 过期）才生效；token 体积增大。

> 三种方法校验规则一致（与 /v2/desktop/list 同源），可组合：方法一/二选其一做身份来源，方法三作为性能优化。

## 七、接口覆盖范围

| 接口类型 | 是否走鉴权 | 说明 |
| --- | --- | --- |
| 所有应用的业务接口 | 是 | 统一中间件覆盖，接口代码无感 |
| /v2/desktop/list（入口） | 服务端按应用授权过滤 | 仅返回当前用户有权限的应用 |
| 登录/鉴权链路接口 | 否（发起点） | 登录、刷新 token、登出、验证码获取 |
| 公开基础接口 | 否（显式登记例外） | RSA 公钥、图片验证码、健康检查等 |
| 服务间调用接口 | 走服务凭证（不走用户权限） | 应用后端直连其他应用后端时 |

**兜底规则：未登记为"公开例外"的接口，默认全部走鉴权（默认拒绝）。**

## 八、访问权限产品定义（怎么给权限）

### 8.1 授权入口与对象

- 授权入口：权限管理界面（管理员操作）；
- 授权对象：用户（或用户组）× 应用 × 权限等级；
- 授权数据与 /v2/desktop/list 返回同源，一处维护、入口与接口校验同时生效。

### 8.2 授予流程

1. 管理员在权限管理界面选择用户；
2. 勾选可使用的应用；
3. 敏感应用需选择权限等级（L1/L2/L3），普通应用默认 L3 可调整；
4. 保存后即时生效（无需用户重新登录，会话刷新即生效）。

### 8.3 默认规则

- 超管/管理员：默认拥有全部应用 L3；
- 普通用户：默认无任何应用，由管理员按需授予；
- 普通应用：授权即 L3（完整使用）；
- 敏感应用：默认 L1（只读），授予 L2/L3 需管理员显式选择（**不能默认直接给予超管/完整权限**）。

### 8.4 敏感应用清单（示例，以产品确认为准）

| 应用 | 原因 | 默认等级 |
| --- | --- | --- |
| 存储管理 | 涉及存储池/卷删除等危险操作 | L1（只读） |
| 用户管理 | 涉及账号与权限 | L1（只读） |
| 系统设置 | 涉及系统级配置 | L1（只读） |
| iSCSIManager 等普通应用 | 常规功能 | L3 |

### 8.5 前端配合

- 菜单/入口按 /v2/desktop/list 返回展示；
- 权限等级低于 L3 的应用，前端隐藏写操作入口（按钮/菜单），后端仍做最终校验。

---

## 九、落地步骤

1. **梳理应用授权数据**：明确授权表结构、维护界面/接口（权限管理）；
2. **/v2/desktop/list 接入授权过滤**：仅返回有权限的应用；
3. **定义公开例外清单**：登录、验证码、RSA 公钥、健康检查等；
4. **实现统一鉴权中间件**（按选定方法）：默认拒绝，未授权一律 403；
5. **前端全面排查**：所有应用的前端调用补齐"调用方应用标识"（方法二可豁免）；
6. **灰度验证**：先在存储管理、iSCSIManager 启用，跑权限验证矩阵，再全量推广。

## 十、风险与边界

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 授权粒度是应用级 | 授权一个应用 = 该应用身份可调全部接口（L3 时） | 普通应用预期行为；敏感应用通过权限等级控制 |
| 伪造调用方身份 | 前端伪造应用标识提权 | 应用标识由服务端校验；调用方应用标识与授权校验同源 |
| 入口与校验不一致 | 能看到但调不通 / 看不到但能调通 | /v2/desktop/list 与接口校验必须同源（同一授权数据） |
| 存量前端遗漏 | 老接口未带应用标识被默认拒绝 | 前端逐应用排查清单 + 灰度期日志监控 403 来源 |
| 服务间调用误走用户通道 | 后端直连被用户权限误杀 | 服务凭证通道与用户权限通道分离 |
| 敏感应用误授 L3 | 普通用户获得危险操作权限 | 默认 L1 + 管理员显式提升 + 授权操作审计日志 |
