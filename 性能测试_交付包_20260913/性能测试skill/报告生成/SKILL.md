# 报告生成

> **一次数据，两种格式，三种体裁。** 格式固定是 `.md` + 自包含 `.html`；
> 体裁按**对比轴**选：比的是「使用 vs 空闲」「空闲 vs 负载」还是「多应用横向」。
> 骨架全文见 `references/report-skeletons.md`，模板在 `../templates/`。

---

## 一、三种体裁：选错骨架，读者会读到一堆对不上号的表

| 体裁 | 对比轴 | 监控层级 | 统计量 | 回答什么问题 |
|---|---|---|---|---|
| `monitor` **监控报告** | 同一应用 **使用期 vs 空闲期** | **进程树级**，PSS 为中心 | 峰值 / 均值（+P95） | 「这个应用占多少」 |
| `perf` **性能报告** | 同一进程 **空闲 vs 负载**（2~3 场景） | **系统级 + 进程级并列** | 峰值 / 均值 / P95 / P99 | 「负载带来多少开销、瓶颈在哪一维」 |
| `summary` **汇总报告** | **多应用横向** | 系统 + 进程 | 峰值 / 均值 / 稳态均值 / P95 / P99 | 「跨服务对比、方法学是否成立」 |

三种体裁的标题由脚本内置决定：`应用资源监控报告` / `性能测试报告` / `性能测试汇总报告`。

---

## 二、`perf_report.py` 完整 CLI

| 参数 | 说明 |
|---|---|
| `--kind monitor\|perf\|summary` | **必填**，选体裁 |
| `-i, --input <json>` | 统计 JSON（`perf_analyze.py` 产物）；**可多次**，每个场景一份 |
| `--labels a,b,c` | 给每个 `-i` 配标签，逗号分隔，与 `-i` 顺序一一对应 |
| `--md <路径>` | Markdown 输出路径 |
| `--html <路径>` | HTML 输出路径（自包含） |
| `--from-k6 <json>` | 直接吃 k6 `--summary-export` 的 JSON（不用先转 stats.json） |
| `--from-jmeter <jtl>` | 直接吃 JMeter `.jtl` / `.csv` |
| `--thresholds <json>` | 用项目验收标准覆盖默认参考阈值 |
| `--fail-on FAIL\|WARN` | 判定达到该级别即**非零退出**（可挂 CI） |

```bash
# ① monitor：单应用 使用期 vs 空闲期
python scripts/perf_report.py --kind monitor -i "perf-out/P2_stats.json" \
  --md "perf-out/报告.md" --html "perf-out/报告.html"

# ② perf：空闲 + 负载两个场景，标签自定义
python scripts/perf_report.py --kind perf -i idle.json -i load.json --labels 空闲,4路转码 \
  --md r.md --html r.html

# ③ summary：多应用横向，统一到同一内存口径
python scripts/perf_report.py --kind summary -i emby.json -i jellyfin.json -i qb.json \
  --labels Emby,Jellyfin,qBittorrent --md r.md --html r.html

# ④ 自定义阈值 + 不通过即非零退出（CI 门禁）
python scripts/perf_report.py --kind perf -i load.json --thresholds my.json \
  --fail-on FAIL --html r.html
```

> ⚠️ `-i` 与 `--labels` **必须顺序一一对应**，数量不等时标签会错位。
> ⚠️ 缺 `--md` / `--html` 时对应格式不产出——**两个都要给**，双格式是本技能的固定交付。

## 三、报告的固定章节

Markdown 实际输出（章节**随数据存在与否条件出现**）：

| # | 章节 | 内容 |
|---|---|---|
| 一 | **结论概览** | 总判定 + 通过/待确认/不通过/未采集计数 + 未通过项点名 |
| 二 | 监控概况 | 场景数 · 样本数 · 坏行剔除 · 采集窗口 · 进程组窗口 |
| 三 | 指标统计 | N 个场景，均值列 + 阈值 + 判定 |
| 四 | **峰值与发生时刻** | 每项峰值**必带 `peak_time`** |
| 五 | 使用期间 vs 空闲期间 | 有使用/空闲拆分时才出现 |
| 六 | **空载 → 负载 放大倍数** | 有 P2/P3 两场景时才出现 |
| 七 | **内存回落与泄漏判定** | 有 churn / 增长检验时才出现 |
| 八 | **采集覆盖度与未测项** | 逐条 ✅ 已采 / ⚠️ 口径降级 / ❌ 未采集 + 统计 |
| 九 | **口径声明** | 网络 / RSS / CPU / 阈值来源四条 |
| 十 | **已撤回的结论** | 有纠错记录时才出现（summary 体裁） |
| — | 瓶颈分析与建议 | 内容来自 `<分析定位>/SKILL.md` |

HTML 把「结论概览」渲染成**统计卡**（替代表格），并在「指标统计」前多一节**趋势图**——
其余章节与上表对应。

> ⚠️ **第八、九、十章不能省。** 采集覆盖度决定报告可不可信，口径声明决定数字可不可比，
> 纠错记录决定下一个读者会不会把已经想清楚的问题重新推翻一遍。

## 四、HTML 是自包含的（零外部请求、内联 SVG、断网可看）

| 特性 | 怎么做到的 |
|---|---|
| 图表 | **手绘内联 SVG**，不引任何图表库 |
| 样式 | 全部内联 `<style>`，无外链 CSS |
| 字体 / 图标 | 用系统字体与字符，不拉网络资源 |
| 结果 | **单文件、零外部请求、断网可看、可直接发邮件** |

**自包含断言**（生成后跑一遍，确认没有外部依赖）：

```bash
# ✅ 正确写法：只匹配 src/href 属性里的外部 URL
grep -oE '(src|href)="(https?:)?//[^"]*' 报告.html

# 期望输出为空（无外部资源引用）
```

> ⚠️ **不能用裸 `grep https?://`** —— 内联 SVG 的 `xmlns="http://www.w3.org/2000/svg"`
> 会被误判成外部请求，报出假阳性。**必须限定在 `src` / `href` 属性上。**

## 五、阈值判定：三级 + 一个不升级

| 判定 | 显示 | 含义 |
|---|---|---|
| `PASS` | ✓ 通过 | 在阈值内 |
| `WARN` | ! 待确认 | 接近阈值（脚本按容差带宽给），需要人看 |
| `FAIL` | ✗ 不通过 | 超阈值 |
| `NA` | – 未采集 | **没有数据**，不作判定 |

**总判定取最差**：有 `FAIL` 就是 `FAIL`，否则有 `WARN` 就是 `WARN`，
**全部 `NA` 时总判定为 `NA`**（而不是 `PASS`）。

> ⚠️ **缺失指标判 `NA`，不许升级成 `FAIL`。** 采不到 Full GC ≠ Full GC 超标。
> ⚠️ **采不到的指标不许填 0。** 0 会被读成「实测值是 0」——一律显示「未采集」并写清原因。
>
> ⚠️ **默认阈值是业界参考值，不是业务验收标准。** 报告里固定回显：
> 「阈值来源：**默认参考值（业界参考，非业务验收标准）**」，并支持 `--thresholds` 覆盖。

## 六、写完报告之后

| 检查项 | 判据 |
|---|---|
| 双格式都在 | `--md` 与 `--html` 两个文件都存在 |
| HTML 自包含 | 上面的断言命令输出为空 |
| 覆盖度章节有统计 | 形如「共 12 项：✅9 / ⚠️2 / ❌1」 |
| 峰值都带时刻 | 第「四」章每行都有 `peak_time` |
| 阈值来源已回显 | 第九章口径声明里有 |
| 跨应用对比口径统一 | 内存一律 `private_Dirty`，不混用 RSS / PSS |
