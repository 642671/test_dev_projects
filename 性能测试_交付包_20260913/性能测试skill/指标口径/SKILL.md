# 指标口径

> 全技能指标定义、计算公式、参考阈值与采集方式的**唯一基准**。
> 完整表见 `references/metrics.md`（两张源表均已核对完整），内存专章见 `references/memory-accounting.md`，

## 一、八类指标，一句话分工

| 类别 | 关心什么 | 代表指标 | 在哪采 |
|---|---|---|---|
| 用户感知 | 快不快、稳不稳 | 响应时间 RT、错误率 | 压测工具 |
| 系统处理能力 | 扛不扛 | TPS、QPS、吞吐量、并发用户数、拐点 | 压测工具 |
| 整机资源 | 累不累 | CPU、内存、磁盘 I/O、网络带宽、Load Average | `/proc/*` |
| 应用进程 | 这个应用吃多少 | PSS、private_Dirty、RSS、应用 CPU、进程树规模 | `/proc/<pid>/*` |
| 中间件 / 数据库 | 后端是否拖后腿 | 连接数、慢查询、死锁、GC | 中间件自身 |
| 稳定性 | 长跑会不会崩 | 稳定性时长、TPS 平稳度、资源泄漏 | 长稳窗口 |
| 前端 | 用户看到得多快 | FCP、LCP、FID、CLS | Navigation Timing |
| 质量元 | 这份数据可不可信 | 采样点、坏行剔除、完整率、稳态占比 | 采集器统计 |

> 前四类**必报**；中间件与前端**按被测对象选报**；质量元**每次都要报**——见 `<报告生成>/SKILL.md`。

## 二、内存五件套（最容易误读，先看这节）

```
                  ┌─────────────────────────────────────────┐
                  │              RSS（常被误读）              │
                  │  ┌───────────────┬───────────────────┐  │
                  │  │   RssAnon     │     RssFile        │  │
                  │  │  （匿名内存）  │  （文件映射页缓存） │  │
                  │  │               │   ← 内核可随时回收   │  │
                  │  └───────────────┴───────────────────┘  │
                  └─────────────────────────────────────────┘
                        PSS = 私有 + 共享 ÷ 共享进程数
                        USS = Private_Clean + Private_Dirty
                        private_Dirty ≈ RssAnon  ← 判压力的第一口径
```

| 口径 | 是什么 | 读取位置 | 什么时候用 |
|---|---|---|---|
| **PSS** | 私有 + 共享 ÷ 共享进程数 | `/proc/<pid>/smaps_rollup` → `Pss:` | **推荐首选**；多进程求和才不虚高 |
| **private_Dirty** | 进程私有、不可回收的脏页 | `smaps_rollup` → `Private_Dirty:` | **判内存压力的第一口径** |
| **RSS** | 私有 + 共享的完整大小 | `/proc/<pid>/status` → `VmRSS:` | **仅作对照**；会被页缓存严重放大 |
| **USS** | 只算独占，不含任何共享 | `Private_Clean + Private_Dirty` | 判「进程退出能释放多少」 |
| **RssAnon / RssFile** | 匿名内存 / 文件映射页 | `/proc/<pid>/status` | 拆构成；`RssFile` 是**页缓存，可回收** |

> ⚠️ **判压力用 `private_Dirty` / `PSS`，不要用 `RSS`。**
> 实测某做种应用 RSS **5918 MB**，看着吃掉整机 37%；拆开看 `RssFile` 占 **5778 MB（97.6%）**，
> 真实匿名仅 **140 MB** 且全程恒定。据此撤回的「限制写缓存 512MB~1GB」建议，别再重犯。
>
> ⚠️ **页缓存不参与 swap** —— 「A 应用的残留写缓存污染了 B 应用的 swap 统计」这种因果**不成立**。
> ⚠️ **swap 换出 ≠ 内存压力** —— 实测 155 MB swap 配 PSS 仅 30 MB、CPU 0.01%，是「深度空闲」，
> 代价只是首次请求有一次**换入延迟**，报告里要写出来。
> ⚠️ **空闲期内存不归零属正常设计** —— 判据是「有无**单调爬升**」，不是「是否归零」。

应用有 systemd unit 时，第六个口径 **cgroup v2** 按需采：
`/sys/fs/cgroup/system.slice/<unit>/memory.current` 与 `memory.stat`。
它**含内核 slab / socket 缓冲**，fork-per-connection 应用（pptpd 这类）应优先用它。

## 三、整机资源指标

| 指标 | 口径 | 参考阈值 | 采集方式 |
|---|---|---|---|
| **CPU 使用率** | 处理请求的时间占比；拆 `%us` / `%sy` / `%iowait` / 软中断 | **≤70%**（70 好 / 85 坏 / **90+ 很差**）；警戒值 75%~80%（表 1） | `/proc/stat` 两次采样差值 |
| **内存使用率** | 物理内存或堆内存使用比例 | 系统 **≤70%**，无页交换；**JVM 堆 ≤70%** | `free` / `/proc/meminfo` |
| **磁盘 I/O** | `%util`、`await`、IOPS | `%util` **≤80%**（**<30% 为好**）；`%iowait` **≤20%-30%**，**>40% 可能成瓶颈** | `iostat -x`；无 sysstat 用 `/proc/diskstats` |
| **网络带宽** | 流量占可用带宽比例 | **≤30%** 且无丢包；千兆 ≈ **119 MB/s** | `/proc/net/dev` |
| **Load Average** | 运行 + 等待状态进程的平均数 | **≤ 核数 × 0.7** | `/proc/loadavg` |

> ⚠️ **网络是整机口径。** Linux **没有逐进程网络计数**（`/proc/<pid>/net/dev` 属于整个网络命名空间）。
> 每个进程 CSV 里的网络列取自同一份数据、**数值完全相同**，**不可归因给单个应用**——报告必须显式声明。
>
> ⚠️ **Load 高但 CPU 不高** → 大量进程在等 I/O，去看磁盘，别去优化 CPU。

## 四、应用进程指标（应用侧核心）

| 指标 | 口径 | 采集方式 |
|---|---|---|
| **应用 CPU** | **单核口径**：`100% = 1 个核`，4 核跑满 = 400%；另给「折合核数」= CPU% ÷ 100 | `/proc/<pid>/stat` 的 `utime+stime` 差值 ÷ `CLK_TCK` |
| **磁盘读 / 写速度** | 进程级归属；写速度**必须扣 `cancelled_write_bytes`**，否则虚高 | `/proc/<pid>/io` 差值 |
| **swap 占用** | 进程被换出的内存 | `/proc/<pid>/status` → `VmSwap:` |
| **进程树规模** | 父进程 + **全部子孙**的数量（均值 / 最大） | `ps -eo pid,ppid` 递归 / `/proc/<pid>/task/*/children` |
| **内存是否随窗口增长** | 是 / 否；空载基线与长稳**必答** | 首尾水位对比 + 单调性检验 |
| **放大倍数** | `负载期均值 ÷ 空载期均值`，CPU 与内存各一份 | 两份 `stats.json` 相除 |

**使用 / 空闲判定**（口径来自实测脚本）：

```
活跃（使用中） = CPU > 2%  或  磁盘读写合计 > 0.5 MB/s  或  网络收发合计 > 0.5 MB/s
空闲           = 以上都不满足
传输类应用另有窄口径：进程网络收发合计 > 0.5 MB/s = 使用
```

> ⚠️ **必须按进程树统计**（父 + 全部子孙）。转码跑在 `ffmpeg` 子进程里、fork-per-connection 服务的内存
> 长在子进程上——只盯主进程会得到「CPU 接近 0」的假象。实测反例：某监控只盯常驻父进程，
> **漏掉 77% 的开销**。进程树规模本身就是一个独立指标，别漏。

## 五、两套阈值口径（**确认过的原文，别再改**）

源材料有**两张指标表**，阈值口径不同，**两张都已由人工核对原文补齐**：

| 表 | 分类 | 给的是 | 代表阈值 |
|---|---|---|---|
| **表 1** 核心性能指标速览 | 3 大类 9 项 | **警戒值**（该警惕了） | CPU **75%~80%**、磁盘繁忙率 **<70%**、错误率趋近 0% |
| **表 2** 性能测试关键指标汇总表 | 5 大类 17 项 | **达标线**（超了不合格） | CPU **≤70%**、`%util` **≤80%**、错误率 **≤0.2%** |

### 关键阈值速查（**均为原文**）

| 指标 | 达标线（表 2） | 补充口径 |
|---|---|---|
| **响应时间 RT** | 视业务而定 | **核心操作 ≤200ms**；**普通页面加载 ≤3s**；**只读查询 ≤10ms** |
| **CPU** | **≤70%** | 通用标准：**70% 好 / 85% 坏 / 90%+ 很差**；用户态 `%us` 与系统态 `%sy` 分别关注；表 1 警戒值 **75%~80%** |
| **内存** | 系统 **≤70%**、无页交换 | **JVM 堆 ≤70%** |
| **磁盘 I/O** | `%util` **≤80%** | **<30% 为「好」**；`%iowait` **≤20%-30%**，**>40% 可能成瓶颈**；表 1 另有「繁忙率 <70%」 |
| **网络带宽** | **≤带宽 30%** | 且**无丢包、延迟和阻塞** |
| **数据库连接数** | **(当前/最大)×100% ≤ 85%** | — |
| **慢查询 / 死锁** | **不应出现** | — |
| **GC** | Full GC **不应过于频繁（如大于平均半小时 1 次）** | 时长应足够短，**压测中不应因 FGC 导致响应时间急剧升高** |
| **错误率** | **≤0.2%** | 理想情况趋近 0% |
| **Load Average** | **≤ CPU核数 × 0.7** | 更宽松：`Load < 核数 × 2` |
| **稳定性时长** | **8 小时系统 ≥8h；7×24 系统 ≥24h** | — |

> ⚠️ **两套口径别混用**：说「**逼近瓶颈**」用表 1 的警戒值，说「**不达标**」用表 2 的达标线。
>
> ⚠️ **默认阈值是业界参考值，不是业务验收标准。** 报告里必须回显来源，并支持 `--thresholds` 覆盖。

## 六、快速判定卡（可直接贴给业务方）

| 维度 | 指标 | 达标线 |
|---|---|---|
| 快不快 | 平均响应时间 / P95 | **核心操作 ≤200ms**；页面 ≤3s；只读查询 ≤10ms |
| 稳不稳 | 错误率 | ≤0.2%（成功率 ≥99.5%） |
| 扛不扛 | TPS 曲线 | 目标并发下平稳，不出现拐点 |
| 累不累 | CPU（**单核口径**） | ≤70% |
| 吃不吃内存 | 内存（**private_Dirty 口径**） | ≤70%，无页交换，不持续增长 |
| 磁盘忙不忙 | `%util` / `%iowait` | ≤80%（<30% 好）/ ≤20%-30%（>40% 成瓶颈） |
| 网卡满没满 | 带宽占用（**整机口径**） | ≤30%；千兆 ≈119 MB/s |
| 排队长不长 | Load Average | ≤ 核数 × 0.7 |

## 七、超标排查速查

| 现象 | 先怀疑 | 下一步查什么 |
|---|---|---|
| 响应慢 + CPU 高 | 计算瓶颈 | 拆 `%us` / `%sy`；看热点函数、GC 频率 |
| 响应慢 + `%iowait` 高 | 磁盘 I/O | `iostat -x` 的 `%util` / `await`；慢查询日志 |
| 响应慢 + 资源都不高 | 应用逻辑 / 慢 SQL / 外部依赖 | 链路打点；SQL 条数；第三方接口耗时 |
| 内存只增不减 | 内存泄漏 | `private_Dirty` 单调性 + churn 复测（见 `<泄漏检测>/SKILL.md`） |
| RSS 巨大但 `RssFile` 占比高 | **页缓存，不是压力** | 算 `RssFile ÷ RSS`，改用 `private_Dirty` 判压力 |
| swap 增长但 PSS 很小 | **深度空闲，不是压力** | 看 CPU / 磁盘是否近零 |
| 网络贴住线速 | 网卡 | 对比带宽上限；确认整机口径不可归因单应用 |
| 错误率非零 | 先分三类 | 超时 / 连接拒绝 / 5xx——三者根因完全不同 |

> 后三条是「看着像问题、其实不是」的经典误判——要么给出辩解，要么别写进报告。
