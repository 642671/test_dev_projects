# 性能测试

**两条业务线 + 三个共用底座。** 被测对象要么是**接口/服务**，要么是 **TOS 的功能/已安装应用**；
后者的完整闭环是「**未安装 → 安装 → 空载 → 负载 → 泄漏检测 → 卸载**」六阶段。

```
                      ┌──────────── 共用底座 ────────────┐
                      │  指标口径 · 分析定位 · 报告生成   │
                      └───────────────┬─────────────────┘
                                      │
        ┌─────────────────────────────┴─────────────────────────────┐
        │                                                           │
   【线一】接口 / 服务                                        【线二】TOS 功能 / 应用
   场景设计 → 接口压测(k6/JMeter) → 分析定位              生命周期 P0→P5 → 采集监控 → 泄漏检测
   TPS/QPS/P95/错误率                                      进程树 PSS/private_Dirty/CPU/磁盘
```

## 一、三种报告体裁（都要出，各两种格式）

| 体裁 | 对比轴 | 监控层级 | 统计量 | 回答的问题 |
|---|---|---|---|---|
| `monitor` **监控报告** | 同一应用 **使用期 vs 空闲期** | 进程树级，PSS 为中心 | 峰值 / 均值（+P95） | 「这个应用占多少」 |
| `perf` **性能报告** | 同一进程 **空闲 vs 负载**（2~3 场景） | 系统级 + 进程级并列 | 峰值 / 均值 / P95 / P99 | 「负载带来多少开销、瓶颈在哪一维」 |
| `summary` **汇总报告** | **多应用横向** | 系统 + 进程 | 峰值 / 均值 / 稳态均值 / P95 / P99 | 「跨服务对比、方法学是否成立」 |

**每种都能出 `.md` 与自包含 `.html` 两份**（HTML 单文件、零外部请求、断网可看、图表是手绘内联 SVG）。

## 二、六阶段应用生命周期（线二核心）

| 阶段 | 做什么 | 谁触发 | 产出 |
|---|---|---|---|
| **P0** 未安装 | 断言应用确实没装 + 记整机基线 + 记已装应用清单（防串味） | 脚本 | `P0_host.csv` |
| **P1** 安装 | 全程 1s 采样，记耗时、CPU/磁盘峰值、**进程出现时刻** | **人工**触发安装 | `P1_install_host.csv` |
| **P2** 空载 | 静置后采**安装后默认占用** | 脚本 | `P2_<app>.csv` |
| **P3** 负载 | 有任务/运行时采，与 P2 同比出**放大倍数** | **人工**发起任务 | `P3_<app>.csv` |
| **P4** 泄漏 | 停任务后回落曲线 + **5 轮 churn** + 长稳 | **人工**停任务 | `P4_churn.json` |
| **P5** 卸载 | 卸载后残留复查（**默认不跑**） | **人工**卸载 | `P5_host.csv` |

> ⚠️ **安装与卸载一律人工触发，技能只负责监控与打点。** 不同应用安装方式不一，卸载还可能丢配置/数据。
> 本技能的所有采集都是**只读**的：只读 `/proc/*`、`/proc/net/dev`、`/proc/diskstats`，不在被测机装任何东西、不改任何配置。

## 四、指标速查（完整表见 `指标口径/SKILL.md` 与 `references/metrics.md`）

| 维度 | 指标 | 达标线 |
|---|---|---|
| 快不快 | 平均响应时间 / P95 | **核心操作 ≤200ms**；页面加载 ≤3s；只读查询 ≤10ms |
| 稳不稳 | 错误率 | ≤0.2%（成功率 ≥99.5%） |
| 扛不扛 | TPS 曲线 | 目标并发下保持平稳、不出现拐点 |
| 累不累 | CPU（**单核口径**，100% = 1 核） | ≤70% |
| 吃不吃内存 | 内存 **用 `private_Dirty` 判** | ≤70%，无页交换，**不持续增长** |
| 磁盘忙不忙 | `%util` / `%iowait` | `%util` ≤80%（<30% 好）；`%iowait` ≤20%-30%（>40% 可能成瓶颈） |
| 网卡满没满 | 带宽占用（**整机口径**） | ≤30%；千兆 ≈119 MB/s |
| 排队长不长 | Load Average | ≤ 核数 × 0.7 |

> **两套阈值口径别混**：源材料有「警戒值」表（CPU 75%~80%、磁盘繁忙率 <70%）与「达标线」表
> （CPU ≤70%、`%util` ≤80%）两张，**说「逼近瓶颈」用前者，说「不达标」用后者**。完整表见 `references/metrics.md`。

## 五、硬约定（踩过的坑，务必遵守）

1. **报告能力不依赖任何压测工具。** `perf_report.py` / `perf_collect.py` / `perf_analyze.py` **纯标准库**，
   没有 k6 / JMeter 也照样出报告。只有 `接口压测` 那条线需要它们，且会自举。
2. **必须按进程树统计**（父 + 全部子孙）。转码在 `ffmpeg` 子进程里、fork-per-connection 服务的内存
   长在子进程上 —— 只盯主进程会得到「CPU 接近 0」的假象。实测反例：某监控只盯常驻父进程，**漏掉 77% 的开销**。
3. **内存判压力用 `private_Dirty` / `PSS`，不要用 `RSS`。** RSS 含 `RssFile`（mmap 文件页缓存，可回收）：
   实测某做种应用 RSS 5918 MB 里 5778 MB（97.6%）是页缓存，真实匿名仅 140 MB。
4. **网络是整机口径。** Linux 没有逐进程网络计数，`/proc/<pid>/net/dev` 属于整个网络命名空间 ——
   报告里必须声明「不可归因单应用」。
5. **采不到的指标不许填 0。** 一律标 `❌ 未采集` / `⚠️ 口径降级`，并写清原因。
   报告固定带「采集覆盖度与未测项」章节。
6. **缺失指标判 `NA`，不许升级成 `FAIL`。** 采不到 Full GC ≠ Full GC 超标。
7. **CPU 必须声明单核口径**（100% = 1 个核，4 核跑满 = 400%），否则跨报告不可比。
8. **峰值必须带发生时刻**，否则会把一次性尖峰（转码收尾落盘）误读成持续压力。
9. **重复测试前清缓存 + 保证请求唯一**，否则命中缓存测出「CPU 接近 0」。
10. **默认阈值是业界参考值，不是业务验收标准** —— 报告里必须回显，并支持 `--thresholds` 覆盖。

## 六、环境要求与自举（Step 0）

> **进技能后第一件事：跑环境自检。** 缺的能自动补就自动补，补不了的给出可复制命令 —— 不要让人对着 `ImportError` 猜。

```bash
python ".claude/skills/性能测试/scripts/selftest.py" --check-env
```

退出码 `0` = 必需依赖齐备；`1` = 缺必需依赖（输出里逐条写了怎么办）。

### 依赖清单

| 依赖 | 是否必须 | 用在哪 | 缺了怎么办 |
|---|---|---|---|
| **Python ≥ 3.8** | **必须** | 全部脚本 | 脚本无法自举解释器，需手动升级 |
| **paramiko** | **必须**（远程采集） | SSH 到被测机 | **自动 `pip install`**；失败时给三选一（`--user` / `--break-system-packages` / `apt install python3-paramiko`） |
| k6 / JMeter / Locust | 可选 | **仅**「接口压测」那条线 | 各自自举；装不上给可复制命令。**不做接口压测就完全不需要** |
| sshpass | **禁用** | — | Windows 下对 TOS sshd 送不进密码，还会触发 PAM 锁账号；**一律走 paramiko** |

被测机侧：Linux + `python3`（TOS 自带）+ SSH 可达（默认端口 9222），能读 `/proc/<pid>/stat`、`/proc/smaps_rollup`、`/proc/net/dev`。

### 三个关键性质（决定「缺了要不要慌」）

1. **报告能力零依赖** —— `perf_report.py` / `perf_analyze.py` 纯标准库；**没有 k6/JMeter 也照样出报告**，只要手上有 CSV/JSON。
2. **采集能力只差 paramiko** —— 缺它自动装；装不上给命令。**本机跑（脚本直接放被测机上执行）连 paramiko 都不需要。**
3. **凭据走模板不入库** —— `.env.local.example` 给模板，真实值写 `.env.local`（已被根 `.gitignore` 排除）。变量名：`TOS_HOST` / `TOS_USER` / `TOS_PASS` / `TOS_PORT`。

```bash
# 关掉自动安装（只提示不装）：设 SKILL_NO_AUTO_INSTALL=1
SKILL_NO_AUTO_INSTALL=1 python scripts/selftest.py --check-env
```

### 复制到别的项目时

整个 `性能测试/` 目录复制到目标项目的 `.claude/skills/` 下即可（**目录名不要改**），
路径全部相对 `__file__`，无写死的工作区绝对路径。复制后跑一次 `--check-env` 确认。

## 七、一次典型跑法（TOS 应用/功能）

```bash
# 0. 环境自检（缺依赖会自动补；退出码 1 = 缺必需依赖）
python ".claude/skills/性能测试/scripts/selftest.py" --check-env

# 1. 查这个功能该盯哪个进程（功能↔进程对照表）
#    见 references/tos-feature-process-map.md

# 2. 六阶段生命周期（安装/卸载由你人工触发，脚本只监控与打点）
TOS_HOST=10.18.15.179 TOS_USER=<用户> TOS_PASS=<口令> TOS_PORT=9222 \
  python ".claude/skills/性能测试/scripts/perf_lifecycle.py" \
  --app "MultimediaServer|mediaindex" --phases P0,P1,P2,P3,P4 \
  --remote --out-dir "999-临时文件存放/多媒体服务器-性能"

# 3. 单独补采某阶段（数据可拼接）
python ".../perf_lifecycle.py" --app MultimediaServer --phases P2 --out-dir <同上>

# 4. 分析 + 出双格式报告
python ".../perf_analyze.py" --in "<out-dir>/P2_MultimediaServer.csv" \
  --app MultimediaServer --tag P2 --out "<out-dir>/P2_stats.json"
python ".../perf_report.py" --kind monitor -i "<out-dir>/P2_stats.json" \
  --md "<out-dir>/报告.md" --html "<out-dir>/报告.html"
```

## 八、脚本

| 脚本 | 作用 |
|---|---|
| `scripts/perf_collect.py` | 采集器：`--scope tree`（进程树）/ `--scope host`（整机），`--remote` 经 SSH 到被测机跑并取回 |
| `scripts/perf_analyze.py` | CSV → 统计 JSON：峰值/均值/P95/P99、峰值时刻、使用vs空闲、内存增长、采集质量 |
| `scripts/perf_report.py` | 三体裁 → `--md` + `--html`（自包含、内联 SVG）；`--from-k6` / `--from-jmeter`；`--fail-on` 挂 CI |
| `scripts/perf_lifecycle.py` | P0→P5 六阶段编排（安装/卸载人工触发） |
| `scripts/perf_run.py` | k6/JMeter 执行与自举（仅线一需要） |
| `scripts/sshcommon.py` | SSH 连接与文件传输；**SFTP 优先、不可用自动回退 base64**（有些 TOS 机关了 sftp 子系统） |
| `scripts/selftest.py` | 自检：环境 + 三体裁跑通 + HTML 自包含 + 缺字段不崩 + NA 不升级 FAIL |

环境自举：缺 `paramiko` 会自动 `pip install` 并打印 `[自举] …`；设 `SKILL_NO_AUTO_INSTALL=1` 只提示不安装。
**技能目录整体复制到别的 Claude 项目即可用。**
