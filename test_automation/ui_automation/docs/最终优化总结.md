### 显式等待策略

采用了 4 种显式等待模式:

1. **元素出现等待**: `wait_for_element_visible()`
   - 适用: 页面加载、面板打开
   - 示例: 等待用户名输入框、设置面板选项

2. **URL 变化等待**: `wait_for_url_contains()`
   - 适用: 页面导航、登录完成
   - 示例: 等待 URL 包含 'desktop'

3. **状态变化等待**: `WebDriverWait(lambda: state_change)`
   - 适用: 按钮状态、复选框勾选
   - 示例: 等待钉住按钮变 active、等待 checkbox.checked

4. **位置变化等待**: `WebDriverWait(lambda: location_change)`
   - 适用: 拖动操作
   - 示例: 等待元素 x/y 坐标变化超过阈值

## 🎓 最佳实践总结

### 1. 数据驱动测试
- 使用 YAML 管理测试数据
- 通过 @pytest.mark.parametrize 实现参数化
- 测试代码与数据分离,易于维护

### 2. BDD 风格
- Given: 前置条件 (环境、状态、数据)
- When: 用户操作或系统事件
- Then: 预期结果 (可验证的断言)
- 保持简洁,每部分 1-2 行

### 3. 显式等待原则
- 优先等待业务相关元素,而非通用容器
- Timeout 设置: 页面加载 15-20s, 元素出现 5-10s, 状态变化 3-5s
- 使用 WebDriverWait + lambda 实现复杂等待条件
- 捕获 TimeoutException 避免阻塞

### 4. 风险驱动测试
- P0 (critical): 阻塞性故障,核心功能,CI 必跑
- P1 (high): 重要功能,影响用户体验
- P2 (medium): 次要功能,边界场景
- P3 (low): 锦上添花,UI 细节
