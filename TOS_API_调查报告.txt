五、API 命名规范和模式分析
================================================================================

1. 路径规范:
   - 大多数 API 使用 /v2/ 前缀（表示 API 版本 v2）
   - 少数 API 使用 /v1/ 前缀（向后兼容的内部接口）
   - 部分消息中心接口使用无版本前缀的简短路径

2. HTTP 方法使用:
   - GET: 查询、获取资源 (读操作)
   - POST: 创建、执行操作、复杂查询 (写操作、动作)
   - PUT: 更新、设置 (更新操作)
   - DELETE: 删除资源 (删除操作)

3. 参数位置:
   - 路径参数: /resource/{id}, /resource/{uuid}
   - 查询参数: ?key=value (通常在 GET 中)
   - 请求体: JSON 格式 (POST/PUT/DELETE)

4. 典型接口对:
   - GET /resource/list          获取列表
   - POST /resource/create       创建资源
   - GET /resource/{id}          获取详情
   - PUT /resource/{id}          更新资源
   - DELETE /resource/{id}       删除资源
