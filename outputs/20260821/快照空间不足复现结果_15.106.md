# 快照空间不足复现结果（10.18.15.106）

测试时间：2026-08-21 12:23 - 12:26 CST  
设备：TNAS，TOS 7.0.1169，Volume1 为 10G Btrfs  

## 环境构建结果

- 预分配文件：`/Volume1/codex_fill_test.bin`（约 8.8G）、`codex_fill_tune.bin`（63M）、`codex_fill_zero.bin`（1M）。
- 满盘状态：`df` 可用 0 字节、Use 100%；`Data 100.00%`；`Metadata 1.83%`；未分配空间 0。
- 满盘下创建快照成功：`TakeSnapshot` 返回 `code:true`，生成 `GMT+08-2026.08.21-12.23.37`。

## 实际结果

### 1. 快照还原（空间不足）

还原接口 `POST /FileSystemSnapshot/RestoreSnapshot` 返回 `data:0` 开始还原，随后 `QueryStatus` 返回：

```json
{"code":true,"data":{"status":7,"progress":100},"is_login":true}
```

`status:7` 即前端映射的 `noSpace`（还原空间不足）。服务端日志：

```text
saveLockData err: insufficient space on /var/subvols/8vEbTxkKvwa: need 241 bytes, available 0 bytes
patVolumeSnapshots: lock new snapshot failed, cleanup
prepareSelfRestore err: check writable space: insufficient space ... available 0 bytes
```

结论：满盘时还原在“加锁/写可写空间检查”阶段即失败，前端表现为空间不足类错误。

### 2. 编辑快照数量后应用

`SetSnapShootConf`（`max_quantity` 30 改为 31）返回：

```json
{"code":false,"msg":"write snapshoot conf: write /usr/local/FileSystemSnapshot/etc/snapshot.conf: no space left on device","data":false,"code_num":119,"code_msg":"Insufficient disk space"}
```

随后 `snapshot.conf` 被截断为 0 字节，`GetSnapShootConf` 报：

```text
json unmarshal error: invalid character '\u0000' looking for beginning of value
```

`GetVolumeSnapShoot` 返回 `data: []`，即前端表现为“数据获取失败、已有快照不展示”。

## 期望结果对照

1. 还原因空间不足失败时，应由产品补充明确的空间不足提示弹窗；当前实际只走到后端 `noSpace` 状态，无产品级文案。
2. 编辑设置后点击应用时，应提示“更改任务设置/数量限制所需空间不足”类提示，且不得把 `snapshot.conf` 写坏，快照清单应继续展示；当前实际会写失败并截断配置，导致快照清单获取失败。
