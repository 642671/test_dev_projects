# StorageManager 性能与内存泄漏专项测试准备

> 状态：测试方案已准备，尚未连接实机、尚未产生测试结论。
> 原则：先做只读基线，再做业务负载；任何格式化、建池、删卷、删快照、拔盘、填满空间等操作，必须由用户逐项授权。

## 1. 测试目标

1. 获取 StorageManager 在空闲、普通操作、高频循环和长稳场景下的 CPU、内存、磁盘 I/O、网络和接口响应基线。
2. 识别慢接口、长时间阻塞、错误率上升、磁盘扫描放大、日志洪泛等性能问题。
3. 区分正常缓存/Go 运行时保留与真实内存泄漏。
4. 检查 goroutine、文件描述符、SQLite、后台任务和 `mdadm` / `mkfs` / `lvm` 子进程是否泄漏或残留。
5. 输出可复现的 CSV、趋势图、HTML 报告、异常时间线和缺陷提交材料。

## 2. 开测前需要确认

| 项目 | 需要的信息 |
|---|---|
| 当前 NAS | 本次测试的动态 IP；只作为本次连接目标 |
| 产品信息 | NAS 型号、TOS 版本、StorageManager 版本、CPU/内存 |
| 监控对象 | 实机上的服务名、主进程 PID、子进程关系；不能只按名称猜测 |
| 业务入口 | API、Unix Socket、界面操作或现有 JMeter/Apifox 场景 |
| 测试存储 | 测试盘、存储池、卷、RAID、文件系统及允许操作范围 |
| 数据保护 | 哪些数据必须保留，哪些盘/卷允许做破坏性测试 |
| 测试时长 | 快速冒烟、2 小时循环或 24 小时长稳 |

连接时先检查本机 SSH 配置、当前主机指纹和远端 `hostname`，确认目标身份后再采集。默认使用账号 `test`、端口 `9222` 和 `C:\Users\twm\.ssh\id_ed25519_codex`。

## 3. 监控指标

### 3.1 进程级

- CPU：瞬时值、均值、峰值、P95、P99。
- 内存：PSS、RSS、Private Dirty、Swap、VmSize。
- Go 服务（若开放 pprof）：heap、alloc、goroutine、mutex、block；重点看 GC 后仍存活对象。
- 资源：线程数、文件描述符数、Socket 数、SQLite/WAL 文件大小、后台任务数量。
- 子进程：`mdadm`、`mkfs`、`lvm`、`smartctl` 等是否超时、僵尸或操作结束后残留。

### 3.2 系统级

- NAS 总 CPU、load average、可用内存、Swap、内存压力和 OOM 记录。
- 块设备吞吐、IOPS、平均等待、队列长度、I/O util、错误和超时。
- 网络收发、丢包、重传（涉及 iSCSI 或远端访问时）。
- StorageManager 日志、内核日志、systemd 状态及测试操作时间点。

### 3.3 接口级

- 请求总数、成功率、错误码分布。
- 平均响应、P50、P90、P95、P99、最大响应时间。
- 吞吐量和不同并发下的拐点。
- 操作完成时间不能只看 HTTP 返回；异步任务需持续轮询到终态。

## 4. 测试阶段

### 阶段 A：只读基线

1. 确认实际进程、PID、启动时间、版本和系统资源。
2. 空闲采集 15 分钟，记录初始 PSS/RSS、goroutine、FD、SQLite、任务数。
3. 对健康检查、磁盘列表、存储池列表、卷列表、RAID 状态等只读接口做单用户基线。
4. 确认采集本身不会明显改变被测服务负载。

### 阶段 B：接口和业务性能

按 `1 → 5 → 10` 并发逐级执行，每级先预热再正式采样；具体并发和次数根据 NAS 配置调整。

优先覆盖：

- 磁盘/存储池/卷/RAID/文件系统列表与详情查询。
- SMART、健康状态、容量和拓扑扫描。
- 异步任务创建、状态轮询、完成或失败收敛。
- 多磁盘、多池、多卷、大量历史任务时的页面/API 性能。
- iSCSI 映射/取消映射、快照创建/删除、USB 热插拔等场景，仅在明确授权后执行。

### 阶段 C：短周期泄漏测试

1. 空闲基线 15 分钟。
2. 执行一批固定业务循环，例如 100 次查询或 20～50 次创建/删除配对操作。
3. 停止负载后空闲 15 分钟；若 pprof 和安全的 GC 触发方式可用，保存 GC 前后 heap profile。
4. 采集 PSS/RSS、heap、goroutine、FD、SQLite、任务数和子进程。
5. 连续执行 3 个相同的“基线 → 负载 → 停止 → 回落”周期，比较每轮回落平台是否持续抬高。

### 阶段 D：异常与恢复

- 请求取消、超时、重复提交和客户端断开。
- StorageManager 任务失败、重试、服务重启后的任务恢复。
- 慢盘、I/O Error、容量不足、快照 ENOSPC、iSCSI 断网、USB 插拔等仅在专用测试环境和逐项授权后执行。
- 每个场景检查资源能否释放，失败任务能否进入有限、明确的终态，不允许无限重试。

### 阶段 E：24 小时长稳

- 业务操作按固定节奏循环，进程/系统指标每 5 分钟留一份长期样本；性能关键区间保留 1 秒级数据。
- 至少记录 0h、1h、2h、4h、8h、12h、24h 的资源快照。
- 结束业务后继续空闲观察 15～30 分钟，再做最终比较。

## 5. 内存泄漏判定

不能因为一次 RSS 高就判定泄漏。至少同时观察以下证据：

1. 多个相同业务周期结束后，PSS 或 Go 活跃堆的回落平台持续单调抬高。
2. GC 后 heap-in-use / heap profile 中同类对象持续增长。
3. goroutine、FD、Socket、任务记录或外部命令子进程随循环累计且不释放。
4. 24 小时趋势呈持续增长，且增长无法由缓存、任务留存、日志/SQLite 正常数据增长解释。
5. 相同操作量下响应时间变差、GC 频率增加或出现 Swap/OOM，形成性能退化闭环。

### 建议的首轮验收线（测试目标，非已验证产品规格）

| 项目 | 建议判定 |
|---|---|
| 正确性 | 无崩溃、OOM、卡死、数据错误；只读场景错误率为 0 |
| 接口性能 | P95/P99 与空闲基线比较；若无产品 SLA，先以版本间不明显退化为准 |
| PSS/RSS | 每轮停止并空闲 15 分钟后应趋于稳定；连续 3 轮回落平台不可持续线性抬高 |
| Go heap | 若可采集 pprof，GC 后活跃堆不应随等量循环持续增长 |
| goroutine | 回落到基线附近；新增 goroutine 必须能解释且不随轮次累积 |
| FD/Socket | 回落到基线附近；无与操作次数成比例的净增长 |
| 子进程 | 操作结束后无僵尸进程、无孤儿 `mdadm` / `mkfs` / `lvm` 进程 |
| SQLite/WAL | 增长与持久任务/审计记录一致；清理或 checkpoint 后不应无界膨胀 |

正式判定阈值应结合硬件配置、产品 SLA、历史稳定版本和研发可接受范围共同确认，不把以上建议值冒充产品规格。

## 6. 采样与证据

- 性能测试：默认 1 秒采样 CPU、PSS、RSS、Private Dirty、Swap、磁盘和网络。
- 长稳测试：默认 5 分钟采样资源计数，关键业务窗口额外保留 1 秒采样。
- 所有业务动作写入统一时间线：开始时间、结束时间、请求 ID、任务 ID、结果和错误码。
- 原始数据优先写 NAS `/tmp`，结束后取回本地，不长期占用数据卷。
- 只停止采集脚本，不停止或杀死被测 StorageManager 服务。

## 7. 最终交付物

1. 原始采样 CSV。
2. CPU、内存、磁盘/网络三组趋势图。
3. 峰值、均值、P95、P99 统计表。
4. 接口性能明细和并发对比。
5. 内存/资源泄漏结论：`通过`、`疑似泄漏`、`确认泄漏` 或 `证据不足`。
6. 异常时间线、日志证据和可直接提交的缺陷字段。
7. 本地 HTML 性能报告；若存在多轮数据，再生成横向汇总报告。

## 9. 推荐的通宵测试组合

适用于“下班后启动、第二天上班停止”的无人值守场景。默认只执行低风险、只读操作。

### 9.1 时间编排

1. `T+0～20 分钟`：空闲基线，只采集资源，不发送业务负载。
2. `T+20 分钟～次日停止前 30 分钟`：循环执行：
   - 10 分钟低并发只读查询；
   - 10 分钟完全空闲，观察资源回落；
   - 每 3 个循环增加一次短时并发阶梯，用于观察吞吐和 P95/P99 拐点。
3. `停止前 30 分钟`：停止业务负载，继续采集，作为最终回落窗口。
4. 用户次日说“停止/结束”后，只停止采集脚本并取回数据，不停止 StorageManager。

### 9.2 默认只读负载

- 健康检查。
- 磁盘列表与磁盘详情。
- 存储池、卷、RAID、文件系统列表与详情。
- 容量、SMART 摘要、任务列表和任务状态查询。
- 页面加载依赖的聚合接口。

接口路径、认证方式和安全频率必须从目标版本实机确认，不能套用历史 NAS 的地址或凭据。

### 9.3 默认负载强度

- 常规阶段：1 个并发，约每 2～5 秒完成一组只读查询。
- 短时阶梯：1、3、5 并发，每级 3 分钟。
- 若目标为低配置 ARM 机型或当前承担其他业务，降低为每 5～10 秒一次并取消并发阶梯。
- 在没有产品 SLA 时，不追求把机器压满，重点观察同等负载下的性能退化和资源是否回落。

### 9.4 通宵保护条件

任一条件发生时，停止业务负载但继续只读监控和保存证据：

- StorageManager 进程退出、反复重启、卡死或健康检查连续失败。
- 出现 OOM、内核 I/O Error、文件系统错误、RAID 异常或磁盘掉线。
- 可用内存持续过低并开始明显 Swap，或系统 load/IO wait 长时间无法回落。
- 只读请求连续超时，或错误率持续升高。
- `/tmp` 可用空间不足，可能影响采样文件。

保护条件的具体阈值在开测前根据 NAS 内存、CPU 和业务占用确认。无人值守期间不自动重启服务、不自动修复 RAID、不删除数据。

### 9.5 次日结论

- 对比首轮与末轮相同负载的吞吐、P95/P99、CPU 和磁盘等待。
- 对比各空闲窗口的 PSS/RSS、Go heap、goroutine、FD 和任务数回落平台。
- 判断为 `稳定`、`性能退化`、`疑似资源泄漏`、`确认资源泄漏` 或 `证据不足`。
- 生成原始 CSV、统计表、三组趋势图、HTML 报告和异常时间线。
