# 磁盘分配方案（依据 2088 条用例场景需求量化）

## 一、磁盘清单与分配

| 磁盘类型 | 磁盘大小 | 磁盘个数 | 安装机器 |
| -------- | -------- | -------- | -------- |
| SSDsata  | 120GB    | 2        | A机 F6-424MAX①（盘位5-6） |
| SSDsata  | 256GB    | 3        | 不装机：USB盒轮换 + 备用替换盘 |
| SSDsata  | 128GB    | 6        | B机 F6-424MAX②（盘位1-6 全上） |
| 狼盘     | 2T       | 1        | A机 F6-424MAX①（盘位3） |
| 狼盘     | 6T       | 1        | A机 F6-424MAX①（盘位4） |
| HDDsata  | 6T       | 1        | A机 F6-424MAX①（盘位1，系统盘） |
| HDDsata  | 3T       | 1        | A机 F6-424MAX①（盘位2，系统盘） |
| M.2 NVMe | 128GB    | 3（空闲） | B机 M.2槽×2（同型号成对做NVMe系统盘）+ A机 M.2槽×1 |
| M.2 NVMe | （F8原装） | 8        | 抽1块给A机第二M.2槽；余7块留C机 F8-SSD PLUS（+1空槽） |

> 共 15 块 SATA 盘 + 11 块 M.2：SATA 12 块装机（A机6 + B机6）、3 块 256GB 留作 USB 场景与轮换备用；
> M.2：A机2（128GB×1 + F8抽出×1）、B机2（128GB×2同型号）、C机7 + 1空槽（空槽留给新增系统盘/热插拔场景）。

## 二、A机 F6-424MAX ①：HDD 系统盘 + 狼盘 IHM + 外设主战场

| 盘位 | 磁盘 | 承担场景 |
|------|------|---------|
| 1 | HDD 6T | **系统盘1**：HDD系统盘矩阵（新增/删除/迁移/检查系统盘条件，约80条）——多块系统盘删其一、最后一块系统盘重装、系统盘任务互斥 |
| 2 | HDD 3T | **系统盘2**：与盘位1构成"2块HDD做系统盘"形态；也用于"非狼盘"对照场景（IHM测试失败类） |
| 3 | 狼盘 2T | IHM 31条（IHM信息/手动测试IHM/导出IHM日志）+ SMART任务矩阵；与盘位4可建双盘池（RAID0/RAID1/TRAID） |
| 4 | 狼盘 6T | 同上；双狼盘 RAID1 冗余移除矩阵（可移任意一块/末1盘不可移） |
| 5 | SSD 120GB | SSD TRIM 18条（TRIM仅SSD池有效）、卷模块SSD场景、"未使用的SSD安全擦除" |
| 6 | SSD 120GB | 与盘位5成对建SSD池；或做SSD缓存盘（缓存阵列中磁盘不可操作类场景，Hyper Cache模块待建时复用） |
| 外接 | USB SATA盒(装256GB SSD) + U盘 + SD/TF读卡器 | USB 41条（USB SMART/不能挂载/弹出/不能做系统盘）+ SD/TF卡4条 |
| M.2×2 | 128GB×1 + F8抽出×1 | **"系统盘是HDD选NVMe新增失败"**类型不匹配矩阵、迁移系统盘"迁出2块HDD迁入1块NVMe成功"、NVMe缓存盘场景（缓存阵列中磁盘不可操作类） |

**运行原则**：A机保持稳定，主跑正向用例与实际结果回填；`{{Ihm1_device}}` 由狼盘产出，`{{disk1_device}}`/`{{disk2_device}}` 优先指向盘位1-2。

## 三、B机 F6-424MAX ②：同型号SSD RAID矩阵 + 破坏性场景 + iSCSI服务端

| 盘位 | 磁盘 | 承担场景 |
|------|------|---------|
| 1 | SSD 128GB | **系统盘**（TOS装此盘，节省HDD） |
| 2 | SSD 128GB | 数据盘/第二系统盘（"删除非唯一系统盘"备用形态） |
| 3-6 | SSD 128GB ×4 | **同型号4盘RAID全矩阵**：RAID6(4盘)、RAID10(4盘)、RAID5(3盘)+热备盘1块、RAID0/1、TRAID/TRAID+（存储池172条+热备盘118条按级别轮换建池）；破坏性专区：损坏/降阶/拔盘/锁定盘/坏块扫描/多分区/只读（约90条） |
| M.2×2 | 128GB×2（同型号成对） | **做"2块NVMe系统盘"形态**："系统盘是NVMe选HDD新增失败"反向矩阵、"2块NVMe系统盘迁出1块迁入HDD失败"（注：此时盘位1-2的SATA SSD改为数据盘，系统装M.2） |

**兼职**：开启 iSCSI 服务，作为 A机的**同网段 iSCSI 服务端**（Apifox 变量 `{{iscsi_lan_ip}}` = B机IP），覆盖获取Target信息同网段场景 + 虚拟磁盘07-12（登录Target/LUN操作）的对端环境。

**RAID轮换执行**：4块数据盘无法同时存在多个RAID级别，按"建池→跑完该级别用例→删池→建下一级别"轮换（RAID6 → RAID10 → RAID5+热备 → TRAID+ → RAID1/0/TRAID），配合池/热备变量后置脚本自动刷新。

**破坏性说明**：损坏/降阶用SSD池拔盘模拟，全部在B机执行，不污染A机环境。

## 四、C机 F8-SSD PLUS：全闪NVMe矩阵（7块 + 1空槽）

| M.2槽 | 磁盘 | 承担场景 |
|-------|------|---------|
| 1-2 | NVMe（F8原装）×2 | **做系统盘**：NVMe系统盘内部迁移矩阵（"2块NVMe系统盘迁出1块迁入1块新NVMe成功"需第3个M.2位，仅此机能测） |
| 3-7 | NVMe（F8原装）×5 | 全闪存储池/卷、"存储池中的NVMe盘安全擦除失败"、NVMe不支持安全擦除类、迁移目标盘（disk3/disk4变量）、Hyper Cache模块（待建，全闪缓存场景） |
| 8 | **空槽** | 留给"新增系统盘选无分区磁盘"、热插拔/拔盘、新盘插入识别类场景 |

## 五、⚠️ 环境缺口（需采购或标注待测）

| 缺口 | 影响用例 | 建议 |
|------|---------|------|
| **4Kn 原生扇区盘** | 4KN盘 7条（挂载失败/建池限制） | 现有盘多为512e；可先试USB盒的4K逻辑扇区模式，不行则备注"待4Kn盘环境" |
| **即将损毁/错误状态盘** | 6条 | 无法人工构造；如有出现过SMART警告的旧盘可临时装B机专测，否则按备注"以真实响应为准" |
| USB NVMe盒 | USB NVMe型SMART矩阵（usb_nvme_*变量） | 如手头无NVMe协议USB盒可采购一个，搭配从剩余M.2中临时取盘使用 |

## 六、场景覆盖核对（对照用例统计）

| 场景需求（用例数） | 覆盖 |
|------------------|------|
| HDD系统盘矩阵（~80） | ✅ A机盘位1-2 |
| NVMe系统盘反向矩阵 | ✅ B机 M.2×2（同型号128GB） |
| NVMe系统盘内部迁移 | ✅ C机（7块NVMe+空槽） |
| 类型不匹配矩阵（HDD系统盘选NVMe） | ✅ A机 M.2×2 |
| IHM狼盘（31） | ✅ A机盘位3-4 |
| RAID0/1/5/6/10、TRAID/TRAID+（172） | ✅ B机4盘轮换 + A机双狼盘补双盘位RAID |
| 热备盘模块（118） | ✅ B机（RAID5×3盘+热备盘1块） |
| SSD TRIM/卷SSD（19） | ✅ A机盘位5-6 |
| USB/SD卡（45） | ✅ A机外接（USB盒装256GB SSD） |
| 损坏/降阶/锁定/坏块/多分区/只读（~90） | ✅ B机盘位3-6 |
| iSCSI同网段（3+后续07-12） | ✅ A机↔B机对测 |
| HyperLock-WORM（22） | ✅ 软件构造，任意机 |
| NVMe建池/擦除类（27） | ✅ C机 + 两台F6的M.2 |
| 4Kn盘（7） | ⚠️ 先试USB盒4K模式 |
| 即将损毁/错误状态（6） | ⚠️ 以真实响应为准 |
