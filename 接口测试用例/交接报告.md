## 四、职责分工（重点）

### 🧑‍💻 测试人员负责（不写代码，本人日常工作）
1. **设计测试场景**：按 8 大维度（正常/边界/参数异常/业务逻辑/认证权限/URL方法/超时/Header）覆盖每个接口。
2. **填写用例内容**：接口地址、请求方法、请求头、请求参数、用例标题、前置条件、预期结果。
3. **真实跑接口**：用有效 Cookie / Token 实际调用接口。
4. **回填实际结果**：把真实的 HTTP 状态码 + 完整 JSON 响应体填入「实际结果」列（**不可推测编造**）。
5. **校正预期**：拿到真实结果后，核对并修正「预期结果」与 Apifox 断言。

### 🤖 自动化/脚本负责（由工具/会写代码的人完成）
1. **批量处理 Excel**：补齐操作步骤、前置条件、用例ID、优先级等（Node.js 读 + PowerShell COM 写）。
2. **质量审计**：多维检查空字段、方法/路径一致性、请求体标签、ID 重复等。
3. **导入 Apifox**：把 Excel 用例一一对应生成 Apifox 单接口用例（Apifox CLI）。

> 说明："操作步骤"等格式化列可由脚本自动生成，测试人员只需填 Col3~10 关键内容 + 预期结果即可。

## 五、标准工作流（每个模块 8 步）

1. （自动化）补充接口**通用场景** + 参数/请求体覆盖
2. （测试人员）补充**业务场景**用例
3. （测试人员审查）先在对话/评审确认场景无误
4. （自动化）合并进 Excel（顺序与 Excel 一致、不跨 Sheet）
5. （自动化）用例检查（去重 + 多维审计）
6. （自动化）导入 Apifox 单接口测试
7. （自动化）补空列（用例ID/所属模块/优先级）
8. （自动化）冻结前终审（多维审计 + ID 连续/唯一）

## 七、注意事项（避坑）

- 改 Excel 前**先备份**、先关掉打开的 Excel 进程（否则保存可能不生效）。
- 「实际结果」列**必须是真实调用结果**，禁止推测填写。
- 403 响应要保留原始 HTML，不要转成 JSON 描述。
- 输出报告用**中文字段名**，不要用单元格坐标（如 C12）。
- 认证类用例的请求头必须用对应的失效/错误凭证变量，否则跑的是正常请求、测不出鉴权失败。
