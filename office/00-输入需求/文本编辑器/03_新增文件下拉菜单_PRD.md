## 一、需求背景与目标

### 1.1 当前状况与问题

当前 TOS 7.0 文本编辑器的「文件」菜单功能存在以下不足：

- 无标签页数量上限管理，打开过多文件导致内存溢出
- 无「最近打开」功能，无法快速访问历史文件
- 无「全部保存」功能，需逐个保存文件
- 编码格式不明确（UTF-8 BOM / 无 BOM）
- 新建文件命名规则不清晰
- 异常处理不完善（权限、空间、文件锁定等）

### 1.2 实现目标

| 维度 | 实现前 | 实现后 |
|------|--------|--------|
| 标签页管理 | 无上限，随意打开 | 最多 30 个标签页，超出提示 |
| 最近打开 | 不支持 | 记录最近 10 个文件，快速访问 |
| 全部保存 | 不支持 | 一键保存所有已打开文件 |
| 编码格式 | 不明确 | 明确 UTF-8 无 BOM 为默认格式 |
| 异常处理 | 不完善 | 完整覆盖权限、空间、锁定等场景 |

**竞品对比：**

| 竞品 | 标签页上限 | 最近打开 | 全部保存 | 编码 |
|------|-----------|---------|---------|------|
| 群晖 DSM 编辑器 | 未知 | 不支持 | 不支持 | UTF-8 |
| 绿联 UGOS 编辑器 | 最多 14 个 | 不支持 | 不支持 | UTF-8 |
| 飞牛 fnOS 编辑器 | 未知 | 不支持 | 不支持 | UTF-8 |
| VS Code | 受内存限制 | 支持 | 支持 | UTF-8 无 BOM |
| TOS 7.0（本次） | 30 个 | 支持（10 条） | 支持 | UTF-8 无 BOM |

### 1.3 目标用户

- **NAS 管理员**：通过 TOS Web 界面管理 NAS 设备，需要快速编辑系统配置文件（如 cron 任务、网络配置、Docker Compose 等）
- **NAS 普通用户**：在 TOS 环境中创建和编辑个人笔记、日志文件等
- **开发者/高级用户**：需要在 NAS 上直接编辑代码、脚本或配置文件

### 1.4 用户价值

- **提升效率**：通过「最近打开」和「全部保存」功能，减少重复操作步骤，提升文件操作效率
- **保障稳定性**：标签页上限管理（30个）防止内存溢出导致浏览器崩溃，提升用户体验
- **降低学习成本**：明确的编码格式（UTF-8 无 BOM）和新建文件命名规则，降低用户使用门槛
- **增强可靠性**：完善的异常处理覆盖权限、空间、锁定等全部场景，减少操作失败带来的挫败感

## 二、用户故事

1. **作为 NAS 管理员**，我希望「文件」菜单支持「最近打开」功能，以便快速访问之前编辑过的配置文件，无需每次在文件管理器中逐层查找路径。
2. **作为 NAS 管理员**，我希望编辑器能一键「全部保存」所有已打开的标签页，以便在多文件编辑场景下高效完成保存操作，无需逐个点击。
3. **作为 NAS 普通用户**，我希望新建文件时有清晰明确的命名规则（如"新建文本 1.txt"），以便快速识别和管理新建的文本文件。
4. **作为 NAS 普通用户**，我希望编辑器对标签页数量有上限控制，以便避免无意中打开过多文件导致浏览器卡顿或崩溃。
5. **作为开发者**，我希望编辑器明确使用 UTF-8 无 BOM 编码格式，以便编辑后的文件不会因为隐藏 BOM 字节引发解析错误（如 shell 脚本 shebang 行失效）。
6. **作为所有用户**，我希望在遇到权限不足、空间不足、文件锁定等异常时能获得清晰明确的提示信息，以便了解失败原因并采取相应措施。

## 三、功能清单与需求描述（EARS原则）

### 3.1 核心功能

#### 3.1.1 新建文件

| 项目 | 规格 |
|------|------|
| 功能说明 | 点击后新增一个空白文本文件标签页 |
| 文件格式 | .txt |
| 默认编码 | UTF-8 无 BOM（不添加 EF BB BF 隐藏字节） |
| 命名规则 | 新建文本 {1+n}.txt（n 为当前最大序号） |
| 未保存标记 | 标签页标题前显示 ● 标记 |

**EARS 需求表述：**

- **[Ubiquitous]** 系统应在「文件」下拉菜单中提供「新建文件」菜单项，用户点击后立即创建一个空白文本标签页，文件格式固定为 `.txt`，编码固定为 UTF-8 无 BOM。
- **[State-driven]** 当编辑器已打开的标签页数量达到 30 个上限时，系统应阻止新建文件操作，并弹出提示"文件数量已达上限，请关闭部分标签页后重试。"。
- **[Event-driven]** 当新建文件标签页创建成功时，系统应在标签页标题前显示 ● 标记，表示该文件尚未保存。
- **[Ubiquitous]** 新建文件的默认命名规则应为"新建文本 {n}.txt"，其中 n 为当前编辑器中已存在的"新建文本"文件的最大序号加 1（例如：已存在"新建文本 1.txt"和"新建文本 2.txt"，则新建文件命名为"新建文本 3.txt"）。

#### 3.1.2 打开文件

| 检查项 | 处理方式 | 提示文案 |
|--------|----------|----------|
| 权限不足 | 阻止打开，弹出提示 | 您的账户权限不足，无法执行此操作。 |
| 标签页数量已达上限 | 前置判断，阻止打开 | 文件数量已达上限，请关闭部分标签页后重试。 |
| 文件大小 > 100MB | 阻止打开 | {文件名称} 大小超出限制，请选择小于 100MB 的文件。 |
| 无法自动识别编码 | 默认使用 UTF-8 打开 | 无法自动识别文件编码，已默认使用 UTF-8 编码打开。 |

**EARS 需求表述：**

- **[Ubiquitous]** 系统应在「文件」下拉菜单中提供「打开文件」菜单项，用户点击后弹出文件选择器，允许选择文本文件进行编辑。
- **[Event-driven]** 当用户选择文件并确认打开时，系统应按以下顺序执行前置校验：标签页数量 → 文件权限 → 文件大小���任一校验不通过则阻止打开并显示对应提示。
- **[Event-driven]** 当文件的编码格式无法被自动识别时，系统应默认使用 UTF-8 编码打开文件，并弹出提示"无法自动识别文件编码，已默认使用 UTF-8 编码打开。"。
- **[Unwanted]** 如果打开的文件大小超过 100MB，系统应阻止打开操作，并弹出提示"{文件名称} 大小超出限制，请选择小于 100MB 的文件。"。

#### 3.1.3 最近打开

| 项目 | 规格 |
|------|------|
| 功能说明 | 记录最近打开的 10 个文件路径，快速访问 |
| 记录数量 | 最多 10 条，超出按时间先后顺序销毁旧记录 |
| 无记录时 | 菜单项置灰，hover 提示"暂无历史访问记录" |
| 打开条件 | 与【打开文件】完全一致（权限、上限、大小、编码） |
| 历史记录销毁时机 | 系统升级、应用重装、文件被删除时销毁；开关机不销毁 |

**EARS 需求表述：**

- **[Ubiquitous]** 系统应在「文件」下拉菜单中提供「最近打开」子菜单，展示最近打开的 10 个文件路径，按打开时间倒序排列。
- **[Event-driven]** 当用户通过「打开文件」或「最近打开」成功打开一个文件时，系统应将该文件路径添加至「最近打开」记录列表的首位。
- **[State-driven]** 当「最近打开」记录数量超过 10 条时，系统应自动删除最早的一条记录，保持最多 10 条。
- **[State-driven]** 当「最近打开」无任何历史记录时，菜单项应置灰不可点击，hover 时显示 tooltip："暂无历史访问记录"。
- **[Event-driven]** 当发生以下事件时，系统应清除对应的历史记录：系统升级、应用重装、源文件被删除。
- **[Optional]** 系统开关机不应导致历史记录被销毁。

#### 3.1.4 保存文件

| 异常类型 | 处理方式 | 提示文案 |
|----------|----------|----------|
| 源文件已删除 | 缓存原路径，保存时重新生成同名文件（先判断写入权限） | — |
| 权限不足 | 阻止保存 | 您的账户权限不足，无法执行此操作。 |
| 空间不足 | 阻止保存 | 您的可用空间不足，请清理部分文件后重试。 |
| 存储配额不足 | 阻止保存 | 您的可用空间配额不足，请清理部分文件后重试。 |
| Hyperlock 锁定文件夹 | 阻止保存 | 无法变更已锁定的文件或文件夹。 |
| 只读文件系统 | 阻止保存 | 文件系统为只读属性，无法执行此操作。 |
| 新建文件保存 | 调用【另存为】功能，选择保存路径 | — |
| 其他未知错误 | 阻止保存 | 操作失败！ |

**EARS 需求表述：**

- **[Ubiquitous]** 系统应在「文件」下拉菜单中提供「保存」菜单项，用户点击后将当前标签页内容写入原文件路径。
- **[Event-driven]** 当保存操作触发时，系统应按以下顺序执行校验：写入权限 → 文件系统只读状态 → Hyperlock 锁定状态 → 磁盘空间 → 存储配额，任一校验不通过则阻止保存并显示对应提示。
- **[Event-driven]** 当源文件已被删除时，系统应在保存时先校验写入权限，校验通过后重新生成同名文件并写入内容。
- **[Event-driven]** 当用户对新建未保存的文件执行保存操作时，系统应自动调用「另存为」流程，引导用户选择保存路径。

#### 3.1.5 另存为

| 检查项 | 处理方式 | 提示文案 |
|--------|----------|----------|
| 文件名称 | 用户自定义 | — |
| 文件类型 | 默认为 .txt，可切换其他文本格式 | — |
| 文件名重名 | 阻止保存，提示用户 | 此位置已包含同名文件。 |
| 特殊字符 | 前端实时拦截 | 文件名称不能包含冒号（:）或斜杠（/）。 |
| 文件名长度超限 | 前端校验拦截 | 文件名称最大长度为 255 个字符。 |

**EARS 需求表述：**

- **[Ubiquitous]** 系统应在「文件」下拉菜单中提供「另存为」菜单项，用户点击后弹出保存对话框，允许选择保存路径、设置文件名和文件类型。
- **[Ubiquitous]** 文件类型默认为 `.txt`，用户可切换为其他文本格式。
- **[Event-driven]** 当用户在文件名输入框中输入特殊字符（: 或 /）时，系统应实时拦截并显示提示"文件名称不能包含冒号（:）或斜杠（/）。"。
- **[Event-driven]** 当用户输入的文件名长度超过 255 个字符时，系统应在前端校验拦截并显示提示"文件名称最大长度为 255 个字符。"。
- **[Event-driven]** 当用户点击确认保存时，系统应检查目标路径是否已存在同名文件，若存在则阻止保存并提示"此位置已包含同名文件。"。

#### 3.1.6 全部保存

**EARS 需求表述：**

- **[Ubiquitous]** 系统应在「文件」下拉菜单中提供「全部保存」菜单项。
- **[Event-driven]** 当用户点击「全部保存」时，系统应按从左到右的顺序遍历所有已打开的标签页，对每个标记为"已修改"的文件执行保存操作。
- **[Event-driven]** 当全部保存操作完成后，系统应汇总保存结果：全部成功则不弹窗；存在部分或全部失败时，弹窗汇总展示失败的文件名及失败原因。
- **[Unwanted]** 如果所有标签页均未修改，系统不应执行任何保存操作，「全部保存」按钮可置灰。

#### 3.1.7 标签页管理

| 项目 | 规格 |
|------|------|
| 标签页上限 | 30 个（含新建和打开的文件） |
| 超出上限提示 | 文件数量已达上限，请关闭部分标签页后重试。 |
| 参考竞品 | 绿联最多 14 个，TOS 定为 30 个，参考文件管理上限 |

**EARS 需求表述：**

- **[Ubiquitous]** 系统应将标签页数量上限限制为 30 个，包括通过「新建文件」和「打开文件」创建的所有标签页。
- **[State-driven]** 当标签页数量达到 30 个上限时，系统应阻止「新建文件」和「打开文件」操作，并弹出提示"文件数量已达上限，请关闭部分标签页后重试。"。
- **[Event-driven]** 当用户关闭任意标签页后，系统应解除上限限制，允许继续新建或打开文件。

### 3.2 交互说明

#### 3.2.1 「文件」菜单结构

```
文件
├── 新建文件        （快捷键可选，如 Ctrl+N）
├── 打开文件        （快捷键可选，如 Ctrl+O）
├── 最近打开        （子菜单，无记录时置灰）
│   ├── /path/to/file1.txt
│   ├── /path/to/file2.log
│   └── ...
├── ─────────────  （分隔线）
├── 保存            （快捷键可选，如 Ctrl+S）

├── 全部保存        （快捷键可选，如 Ctrl+Shift+L）
├── ─────────────  （分隔线）
```

#### 3.2.2 标签页交互

- 标签页标题格式：`● 文件名.txt`（● 表示未保存，已保存的文件不显示此标记）
- 标签页支持拖拽排序
- 标签页右键菜单支持：关闭、关闭其他、关闭右侧、关闭所有
- 标签页溢出时支持左右滚动切换
- 当前激活标签页高亮显示

#### 3.2.3 提示弹窗

- 所有错误提示使用模态弹窗（Modal），包含「确定」按钮
- 提示信息使用红色/橙色图标增强可识别性
- 「全部保存」失败汇总使用列表形式展示，每行显示"文件名 — 失败原因"

### 3.3 权限规则

| 操作 | 所需权限 | 校验时机 |
|------|----------|----------|
| 打开文件 | 目标文件的读取权限 | 选择文件后、打开前 |
| 保存文件 | 目标文件的写入权限 | 执行保存前 |
| 另存为 | 目标目录的写入权限 | 执行保存前 |
| 新建文件 | 无额外权限要求（内存操作） | — |
| 最近打开 | 与「打开文件」权限一致 | 点击历史记录项时 |
| 全部保存 | 与「保存文件」权限一致 | 逐个文件保存时 |

## 四、流程与状态说明

### 4.1 业务流程图（文字描述）

#### 4.1.1 新建文件流程

```
用户点击「文件」→「新建文件」
  → 检查标签页数量 < 30
    ├── 否 → 弹出提示"文件数量已达上限..." → 结束
    └── 是 → 创建空白标签页，标题"新建文本 {n}.txt"，显示 ● 标记 → 完成
```

#### 4.1.2 打开文件流程

```
用户点击「文件」→「打开文件」
  → 弹出文件选择器
  → 用户选择文件并确认
  → 检查标签页数量 < 30
    ├── 否 → 弹出提示 → 结束
    └── 是 → 检查文件读取权限
        ├── 无权限 → 弹出提示 → 结束
        └── 有权限 → 检查文件大小 ≤ 100MB
            ├── 超限 → 弹出提示 → 结束
            └── 通过 → 尝试识别文件编码
                ├── 识别成功 → 以识别编码打开文件
                └── 识别失败 → 以 UTF-8 打开，弹出提示
              → 添加文件至标签页
              → 更新「最近打开」记录 → 完成
```

#### 4.1.3 保存文件流程

```
用户点击「文件」→「保存」
  → 判断是否为新建未保存文件
    ├── 是 → 调用「另存为」流程
    └── 否 → 检查写入权限
        ├── 无权限 → 弹出提示 → 结束
        └── 有权限 → 检查文件系统只读状态
            ├── 只读 → 弹出提示 → 结束
            └── 非只读 → 检查 Hyperlock 锁定状态
                ├── 已锁定 → 弹出提示 → 结束
                └── 未锁定 → 检查磁盘空间/配额
                    ├── 不足 → 弹出提示 → 结束
                    └── 充足 → 写入文件
                      → 移除 ● 标记 → 完成
```

#### 4.1.4 全部保存流程

```
用户点击「文件」→「全部保存」
  → 遍历所有标签页（从左到右）
  → 筛选标记为"已修改"的文件
  → 逐个执行保存流程
  → 汇总结果
    ├── 全部成功 → 静默完成
    └── 部分/全部失败 → 弹出失败汇总列表 → 完成
```

#### 4.1.5 另存为流程

```
用户点击「文件」→「另存为」
  → 弹出保存对话框（默认路径、文件名、类型 .txt）
  → 用户输入文件名（实时校验特殊字符和长度）
  → 用户选择保存路径
  → 用户点击确认
  → 检查目标路径同名文件
    ├── 存在 → 弹出提示"此位置已包含同名文件。" → 返回对话框
    └── 不存在 → 执行保存流程（权限/空间/锁定校验同保存）
        ├── 失败 → 弹出对应提示
        └── 成功 → 更新标签页标题，移除 ● 标记 → 完成
```

### 4.2 状态流转

#### 4.2.1 文件标签页状态

```
[空状态] ──新建文件──→ [未保存] ──保存成功──→ [已保存] ──内容修改──→ [未保存]
                           │                    │
                           └──另存为成功────────┘
                           │                    │
                           └──关闭（丢弃）──────┴──→ [已关闭/销毁]
```

#### 4.2.2 「最近打开」记录状态

```
[空列表] ──首次打开文件──→ [有记录] ──记录满10条+新打开──→ [最旧记录被移除]
    │                          │
    └── 无记录时菜单置灰        ├── 系统升级/重装/文件删除 → 对应记录被销毁
                               └── 开关机 → 记录保持不变
```

### 4.3 边界场景与异常处理

#### 4.3.1 边界场景

| 场景 | 处理策略 | 说明 |
|------|----------|------|
| 标签页恰好 30 个时新建/打开 | 阻止操作，弹出提示 | 严格上限，不可突破 |

### 7.3 待确认问题

1. **标签页上限 30 是否足够？** 需持续关注埋点数据中"标签页达上限"事件频率，如果触发频繁，考虑提升至 50 或加入可配置项。
2. **最近打开 10 条是否合理？** VS Code 等桌面编辑器通常不限制数量，Web 端受限存储空间暂定为 10 条，需根据用户反馈调整。
3. **文件大小 100MB 上限是否需要调整？** 需监控「文件过大拦截」埋点数据，评估是否有足够的用户需要编辑更大文件。
4. **是否需要支持文件拖拽打开？** 部分用户可能习惯从文件管理器拖拽文件到编辑器打开，需确认是否纳入后续迭代。
5. **是否需要支持文件自动保存？** VS Code 等编辑器支持自动保存功能，避免因意外关闭导致数据丢失，需确认是否后续版本规划。
6. **全部保存失败后的重试机制？** 当前设计为弹窗汇总展示失败原因，是否需要提供「重试全部失败项」按钮？
7. **「最近打开」记录的存储位置？** 需确认存储在浏览器 localStorage 还是后端用户配置中（后者支持跨设备同步但增加后端依赖）。
8. **另存为时文件类型选项范围？** 当前仅明确 .txt，其他文本格式具体包括哪些（.log、.md、.csv、.json、.xml、.yml、.sh 等）需进一步确认。
