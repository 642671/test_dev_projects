## 一、需求背景与目标

### 1.1 当前状况与问题

当前 TOS 7.0 文本编辑器已实现基础编码支持，但存在以下不足：

- 仅支持 UTF-8、GBK、BIG5 等少数几种编码（约 5 种）
- 无法覆盖 GB2312、GB18030、Shift-JIS、EUC-KR 等常见编码
- 无法处理 UTF-16、UTF-32 等 Unicode 编码变体
- 西欧语言（ISO-8859 系列）、东欧语言（KOI8 系列）等编码缺失
- 新建的文本文件另存为时不支持编码格式的选择

### 1.2 实现目标

| 维度 | 实现前 | 实现后 |
|------|--------|--------|
| 编码支持数量 | 约 5 种 | **57 种**（覆盖全球主要语言区域） |
| 编码自动识别 | 基础支持 | 基于 BOM + 内容采样的智能检测 |
| 编码切换入口 | 无 | 底部状态栏点击切换 |
| UTF-16/UTF-32 支持 | 不支持 | 完整支持 UTF-16 LE/BE、UTF-32 LE/BE |
| 西欧/东欧编码支持 | 不支持 | 完整支持 ISO-8859、Windows-125x、KOI8 系列 |
| 另存为编码选择 | 不支持 | 支持选择目标编码格式保存 |

### 1.3 目标用户

- 需要处理多语言文本文件（中文、日文、韩文、西欧语系等）的 TOS 用户
- 从其他系统迁移文件需要保留原有编码格式的用户
- 需要查看或编辑来自不同编码环境（Windows、Linux、macOS）文本文件的开发者

### 1.4 用户价值

- 解决多语言文本文件的兼容性问题，覆盖全球主要语言区域
- 降低用户因编码问题导致的乱码困扰
- 提供便捷的编码切换与保存入口，提升编辑效率
- 对齐绿联 UGOS 等竞品，超越群晖 DSM 和飞牛 fnOS

## 三、功能清单与需求描述（EARS原则）

### 3.1 核心功能

#### 3.1.1 编码自动识别（Ubiquitous + Event-driven）

- **Ubiquitous**: 系统在打开任意文本文件时，应自动执行编码检测流程：先读取文件头检测 BOM（Byte Order Mark），若检测到 BOM 则直接确定编码；若未检测到 BOM，则采样文件前 4KB 内容进行编码分析。
- **Event-driven**: 当编码检测置信度 > 90% 时，系统应使用检测到的编码打开文件并正确渲染内容。
- **Unwanted**: 当编码检测置信度 ≤ 90% 时，系统应弹出提示"无法自动识别文件编码"，默认使用 UTF-8 编码打开，同时允许用户后续手动切换编码。
- **State-driven**: 在文件打开过程中，底部状态栏应实时更新显示当前使用的编码格式。

#### 3.1.2 编码显示与切换（Event-driven + State-driven）

- **State-driven**: 底部状态栏应持续显示当前文件的编码格式（如"编码 UTF-8"）。
- **Event-driven**: 当用户点击状态栏编码区域时，系统应弹出编码选择菜单，菜单包含全部 57 种编码，采用平铺列表布局，按分组排序显示（Unicode → 中文简体 → 中文繁体 → 日文 → 韩文 → 西欧 → 东欧 → 中东 → 其他 → 遗留），分组标题仅用于视觉分隔，不做折叠/展开。
- **Event-driven**: 当用户在菜单顶部搜索框输入语言名称时，系统应实时过滤并高亮匹配的编码项。
- **Event-driven**: 当用户选择目标编码后，系统应按新编码重新解析文件内容并刷新显示，同时状态栏更新编码显示，并 Toast 提示"已切换至 [编码名称] 编码。"
- **Unwanted**: 当编码重新解析失败时，系统应保持原编码不变，并 Toast 提示"编码切换失败，请重新设置编码格式。"

#### 3.1.3 当前编码标识（Ubiquitous）

- **Ubiquitous**: 在编码选择菜单中，当前文件正在使用的编码应以高亮样式标识（如特殊背景色或 ● 标记），以便用户快速识别。

#### 3.1.4 另存为编码选择（Event-driven + Optional）

- **Optional**: 当用户使用"另存为"功能时，保存对话框中应提供"编码格式"下拉菜单，包含全部 57 种编码供用户选择。
- **Event-driven**: 当用户选择目标编码并点击"保存"后，系统应按指定编码格式保存文件。
- **Unwanted**: 当保存编码失败时，系统应停止保存操作，并提示"保存失败：[具体原因]"。

#### 3.1.5 编码支持清单（Ubiquitous）

**Ubiquitous**: 系统应支持以下 57 种编码格式，按语言区域分组：

| 分类 | 编码列表 | 数量 |
|------|----------|------|
| Unicode 系列 | UTF-8、UTF-8 with BOM、UTF-16 LE、UTF-16 BE、UTF-32 LE、UTF-32 BE、UTF-7 | 7 |
| 简体中文 | GB2312、GBK、GB18030、HZ | 4 |
| 繁体中文 | BIG5、BIG5-HKSCS、CP950 | 3 |
| 日文 | Shift-JIS、EUC-JP、ISO-2022-JP、CP932、CP943C | 5 |
| 韩文 | EUC-KR、CP949、ISO-2022-KR、JOHAB | 4 |
| 西欧语言 | ISO-8859-1 (Latin-1)、ISO-8859-2 (Latin-2)、ISO-8859-3 (Latin-3)、ISO-8859-4 (Latin-4)、ISO-8859-9 (Latin-5)、ISO-8859-10 (Latin-6)、ISO-8859-15 (Latin-9)、Windows-1250、Windows-1252、Windows-1254、MacRoman | 11 |
| 东欧/斯拉夫语言 | ISO-8859-5、KOI8-R、KOI8-U、Windows-1251、MacCyrillic | 5 |
| 中东语言（希腊/阿拉伯/希伯来） | ISO-8859-6 (Arabic)、ISO-8859-7 (Greek)、ISO-8859-8 (Hebrew)、Windows-1253 (Greek)、Windows-1255 (Hebrew)、Windows-1256 (Arabic) | 6 |
| 其他语言 | TIS-620 (Thai)、Windows-874 (Thai)、VISCII (Vietnamese)、Windows-1258 (Vietnamese) | 4 |
| 传统/遗留编码 | ASCII、ANSI、EBCDIC、Base64 | 4 |

> **合计**：57 种（7 + 4 + 3 + 5 + 4 + 11 + 5 + 6 + 4 + 4 = 57）

## 四、流程与状态说明

### 4.1 业务流程图

#### 4.1.1 自动编码检测流程

```
用户打开文本文件
        ↓
读取文件头（检测 BOM）
        ↓
是否检测到 BOM？
        ├─ 是 → 根据 BOM 确定编码（UTF-8/UTF-16 LE/BE/UTF-32 LE/BE）
        └─ 否 → 采样文件内容（前 4KB）进行编码检测
        ↓
编码检测是否有高置信度结果（>90%）？
        ├─ 是 → 使用检测到的编码打开文件
        └─ 否 → 弹出提示"无法自动识别文件编码，已默认使用 UTF-8 编码打开。"
        ↓
更新底部状态栏编码显示 → 完成
```

#### 4.1.2 编码切换流程

```
用户点击状态栏"编码 UTF-8"
        ↓
弹出编码选择菜单（57 种编码，平铺列表，分组排序）
        ↓
用户选择目标编码（如 GBK）
        ↓
系统按新编码重新解析文件内容
        ↓
解析成功？
        ├─ 是 → 更新状态栏显示"编码 GBK"，Toast 提示"已切换至 GBK 编码。"
        └─ 否 → Toast 提示"编码切换失败，请重新设置编码格式。"，保持原编码
        ↓
完成
```

#### 4.1.3 另存为编码选择流程

```
用户点击"另存为"
        ↓
弹出文件保存对话框
        ↓
用户选择保存路径
        ↓
用户从"编码格式"下拉菜单中选择目标编码（如 GB18030）
        ↓
用户点击"保存"
        ↓
系统按指定编码保存文件 → 完成
```

### 4.2 状态流转

#### 4.2.1 文件编码状态

| 当前状态 | 触发事件 | 目标状态 | 说明 |
|----------|----------|----------|------|
| 未识别 | 文件打开 | 识别中 | BOM检测或内容采样检测进行中 |
| 识别中 | BOM检测成功 | 已识别 | 根据BOM确定编码 |
| 识别中 | 内容检测置信度 > 90% | 已识别 | 使用检测结果 |
| 识别中 | 内容检测置信度 ≤ 90% | 默认编码 | 回退到UTF-8 |
| 已识别 | 用户切换编码 | 切换中 | 重新解析文件 |
| 切换中 | 解析成功 | 已识别（新编码） | 状态栏更新 |
| 切换中 | 解析失败 | 已识别（原编码） | 保持原编码，提示失败 |

#### 4.2.2 编码菜单状态

| 状态 | 说明 |
|------|------|
| 关闭 | 菜单不可见，状态栏正常显示编码 |
| 展开 | 菜单弹出，显示全部57种编码，当前编码高亮 |
| 搜索过滤 | 用户在搜索框输入关键词，菜单实时过滤匹配项 |
| 选中 | 用户点击某一编码，菜单关闭，触发切换流程 |

### 4.3 边界场景与异常处理

| 异常类型 | 处理方式 | 提示文案 |
|----------|----------|----------|
| 编码检测失败 | 默认使用 UTF-8 打开 | 无法自动识别文件编码，已默认使用 UTF-8 编码打开。 |
| 编码转换错误 | 回退到二进制模式，提示用户 | 文件编码转换失败，请手动选择正确的编码。 |
| 编码切换失败 | 保持原编码，提示用户 | 编码切换失败，请重新设置编码格式。 |
| 保存编码失败 | 停止保存，提示用户 | 保存失败：{具体原因} |
| 空文件打开 | 默认 UTF-8，无需检测 | 无提示，正常显示空白编辑器 |
| 二进制文件 | 按原编码尝试打开，失败时提示 | 文件可能为二进制格式，无法正确显示。 |
| 超大文件（>100MB） | 仅采样前4KB检测，允许用户手动切换 | 文件较大，编码检测可能不准确。 |
| 编码不支持字符转换 | 提示字符可能丢失，允许用户选择是否继续 | 目标编码无法完整表示文件内容，部分字符可能丢失。是否继续？ |
| 文件已被外部修改 | 编码信息可能不准确，重新检测 | 无额外提示，按正常流程重新检测 |
| 搜索无匹配编码 | 显示"无匹配结果"空状态 | 无匹配编码格式，请尝试其他关键词。 |
| 网络文件系统文件 | 正常执行检测，可能较慢 | 文件位于网络存储，编码检测可能耗时较长。 |

## 五、数据口径与埋点需求

### 5.1 数据指标

| 指标名称 | 说明 | 统计口径 |
|----------|------|----------|
| 编码自动识别成功率 | 编码检测置信度 > 90% 的比例 | 成功识别文件数 / 总打开文件数 |
| 编码切换次数 | 用户手动切换编码的频率 | 每日/每用户平均切换次数 |
| 热门编码TOP10 | 用户最常使用的编码格式 | 按使用频率排序 |
| 编码切换失败率 | 切换编码解析失败的占比 | 失败次数 / 总切换次数 |
| 另存为编码选择率 | 用户使用另存为时选择非默认编码的比例 | 选择编码次数 / 总另存为次数 |
| 编码搜索使用率 | 用户在菜单中使用搜索功能的比例 | 搜索次数 / 菜单打开次数 |
| 默认编码回退率 | 因检测失败回退到 UTF-8 的比例 | 回退次数 / 总打开文件数 |

### 5.2 埋点事件

| 事件名称 | 触发时机 | 关键参数 |
|----------|----------|----------|
| `editor_encode_detect` | 文件编码自动检测完成 | `source_encode`, `detected_encode`, `confidence`, `method`（BOM/采样） |
| `editor_encode_switch` | 用户手动切换编码 | `from_encode`, `to_encode`, `result`（成功/失败） |
| `editor_encode_menu_open` | 打开编码选择菜单 | `current_encode`, `trigger`（点击/快捷键） |
| `editor_encode_search` | 在菜单中使用搜索 | `keyword`, `result_count` |
| `editor_saveas_encode` | 另存为选择编码 | `from_encode`, `to_encode` |
| `editor_encode_fallback` | 检测失败回退默认编码 | `file_extension`, `file_size`, `detected_confidence` |
| `editor_encode_error` | 编码相关错误 | `error_type`, `error_message`, `encode` |

### 7.3 待确认问题

1. **编码检测算法选型**：使用哪种编码检测库/算法？建议使用 uchardet 或 chardet 库。
2. **Base64 编码的处理方式**：Base64 属于传输编码而非字符编码，是否需要在打开/保存时做特殊处理（如自动解码/编码）？
3. **ANSI 编码映射**：ANSI 在不同语言系统中有不同映射（简体中文系统映射为 GBK），需确认如何处理。

5. **UTF-7 安全性**：UTF-7 存在安全风险（XSS），是否考虑在后续版本中标记为不推荐或移除？
6. **大文件处理策略**：超大文件（>100MB）的编码检测和切换策略需进一步确认性能指标。
