## 一、需求背景与目标

### 1.1 当前状况与问题

当前 TOS 7.0 文件管理中的文本编辑功能存在以下问题：

1. **功能单一**：文本编辑器仅支持基础编辑，无多标签页管理能力。
2. **标签页管理缺失**：打开多个文件时，无法管理标签页的关闭顺序和保存状态。
3. **大文件性能差**：大文件（>50MB）全量加载，加载缓慢，甚至导致浏览器卡顿或崩溃。
4. **编码识别不准**：文件编码识别不准确，非 UTF-8 编码文件打开后出现乱码。
5. **无数量限制**：文件打开数量无限制，容易导致内存溢出和浏览器性能下降。
6. **右键菜单缺失**：右键菜单功能缺失，无法快速定位文件位置或重命名。

**技术基础**：基于 Monaco Editor（VS Code 同款编辑器库），需在此基础上扩展多标签页管理、大文件优化、文件操作等能力。

### 1.2 实现目标

| 维度 | 实现前 | 实现后 |
|------|--------|--------|
| 多标签页管理 | 不支持，一次只能编辑一个文件 | 支持多标签页，最多同时打开 30 个文件 |
| 大文件加载 | 全量加载，>50MB 易卡顿 | 分块按需加载，流畅滚动 |
| 文件编码 | 默认 UTF-8，其他编码乱码 | 自动识别编码，默认 UTF-8 兜底 |
| 关闭顺序 | 无统一规则 | 从左往右依次关闭，未保存文件弹窗确认 |
| 右键菜单 | 无 | 支持打开文件所在位置、重命名、关闭 |
| 权限控制 | 无权限校验 | 打开文件时校验权限，无权限提示 |

### 1.3 目标用户

- TOS 7.0 文件管理系统用户
- 需要通过 Web 界面编辑文本文件（.txt, .md, .log, .json, .xml, .py, .js, .html, .css 等）的用户
- 需要同时编辑多个文件的开发者和运维人员
- 需要查看和编辑大日志文件的用户

### 1.4 用户价值

- 支持同时编辑多个文件，提升工作效率。
- 大文件打开流畅，不卡顿。
- 文件编码自动识别，减少乱码问题。
- 灵活的关闭顺序和保存提示，避免内容丢失。
- 右键快捷操作（打开位置/重命名/关闭），提升操作效率。

## 三、功能清单与需求描述（EARS原则）

### 3.1 核心功能

#### 3.1.1 标签页管理

| 功能点 | EARS类型 | 需求描述 |
|--------|----------|----------|
| 打开文件 | Event-driven | 当用户从文件管理打开文件时，如果文件尚未打开，系统应当新增标签页；如果文件已打开，系统应当切换到对应标签页，不重复打开。 |
| 标签页顺序 | Ubiquitous | 标签页应当始终按打开顺序从左到右排列，新打开的标签页始终出现在最右侧。 |
| 标签页切换 | Event-driven | 当用户点击标签页时，系统应当切换编辑内容到对应文件，并将当前编辑的标签页高亮显示。 |
| 当前编辑指示 | State-driven | 当标签页处于编辑状态时，系统应当显示下划线或高亮背景，与其他非活跃标签页区分。 |
| 未保存标记 | State-driven | 当文件内容已修改但未保存时，系统应当在标签页标题旁显示"●"标记（或 * 号），提示用户内容未保存。 |
| 标签页数量限制 | Unwanted | 当已打开文件数量达到 30 个上限时，系统应当阻止打开新文件，并提示："文件数量已达上限，请关闭部分标签页后重试。" |

#### 3.1.2 关闭功能

| 功能点 | EARS类型 | 需求描述 |
|--------|----------|----------|
| 单个关闭 | Event-driven | 当用户点击标签页关闭按钮时，系统应当关闭当前标签页。 |
| 关闭顺序 | Ubiquitous | 关闭标签页时，系统应当始终从左往右依次关闭（区别于 VS Code 的从右往左），符合国内用户阅读习惯。 |
| 全部关闭 | Event-driven | 当用户执行"全部关闭"操作时，系统应当从左往右遍历所有标签页逐个关闭。 |
| 关闭最后一个标签 | Event-driven | 当用户关闭最后一个标签页时，系统应当退出整个文本编辑器应用。 |
| 未保存文件关闭 | Event-driven | 当用户关闭到未保存的文件时，系统应当弹出保存确认弹窗，提供"不保存"、"保存"、"取消"三个选项。 |
| 不保存操作 | Event-driven | 当用户选择"不保存"时，系统应当不做保存，关闭此文件标签页，继续关闭下一个。 |
| 保存操作 | Event-driven | 当用户选择"保存"时，如果是新建文件，系统应当调出路径选择组件，保存后关闭；如果是已有文件，系统应当直接保存后关闭。 |
| 取消操作 | Event-driven | 当用户选择"取消"时，系统应当关闭提示弹窗，中断关闭流程，保留所有未关闭的标签页。 |

#### 3.1.3 打开文件校验

| 检查项 | EARS类型 | 需求描述 |
|--------|----------|----------|
| 权限不足 | Unwanted | 当用户尝试打开无读取权限的文件时，系统应当阻止打开，并弹出提示："您的账户权限不足，无法执行此操作。" |
| 文件数量上限 | Unwanted | 当已打开 30 个文件且用户尝试打开新文件时，系统应当阻止打开新文件。 |
| 文件大小超限 | Unwanted | 当用户尝试打开大于 100MB 的文件时，系统应当阻止打开，并提示："{文件名称} 大小超出限制，请选择小于 100MB 的文件。" |
| 文件大小 50-100MB | Optional | 当文件大小在 50-100MB 之间时，系统可以允许打开，但应当采用分块加载策略。 |
| 编码识别失败 | Event-driven | 当系统无法自动识别文件编码时，应当默认使用 UTF-8 编码打开，并提示："无法自动识别文件编码，已默认使用 UTF-8 编码打开。" |

#### 3.1.4 大文件性能优化

| 功能点 | EARS类型 | 需求描述 |
|--------|----------|----------|
| 分块策略 | Ubiquitous | 针对 50MB+ 文件，系统应当按行或按块拆分，首次仅加载可视区域内容（当前屏幕显示的 50-100 行）。 |
| 分块大小 | Ubiquitous | 每个分块大小应当为 1000 行或 1MB。 |
| 预加载机制 | State-driven | 当用户滚动文件时，系统应当预加载下一个可视块（提前加载屏幕下方 200 行），避免滚动时出现空白或卡顿。 |
| 内存管理 | Ubiquitous | 超出可视区域较远的块应当从内存中卸载，仅保留最近访问的 5-10 个块。 |
| Monaco Editor 配置 | Ubiquitous | 系统应当启用 `largeFileOptimizations: true` 和 `renderWhitespace: "boundary"` 等参数进行优化。 |

#### 3.1.5 右键菜单

| 菜单项 | EARS类型 | 需求描述 |
|--------|----------|----------|
| 打开文件所在位置 | Event-driven | 当用户右键点击标签页并选择"打开文件所在位置"时，系统应当在文件管理器中定位并高亮当前文件。新文件（未保存）无此选项或置灰。 |
| 重命名 | Event-driven | 当用户右键点击标签页并选择"重命名"时，系统应当弹出重命名弹窗，输入新名称后保存并更新标签页标题。新文件需先保存路径。 |
| 关闭 | Event-driven | 当用户右键点击标签页并选择"关闭"时，系统应当关闭当前标签页。未保存时触发保存确认弹窗。 |

#### 3.1.6 新建文件

| 功能点 | EARS类型 | 需求描述 |
|--------|----------|----------|
| 默认文件名 | Ubiquitous | 新建文件时，默认文件名应当为"New file.txt"，并进入重命名状态。 |
| 未保存状态 | State-driven | 当新建文件未保存时，标签页标题应当显示"● 新建文本文档.txt"。 |
| 保存操作 | Event-driven | 当用户点击保存时，系统应当调出路径选择组件，选择保存位置后写入磁盘。 |
| 取消保存 | Event-driven | 当用户取消保存时，文件应当仍保留在内存中，不写入磁盘。 |
| 连续新建 | Ubiquitous | 连续新建文件时，文件名应当递增，命名方式与文件管理新建文件相同。 |

### 3.2 交互说明

#### 3.2.1 弹窗规范

所有弹窗都需添加遮罩层（支持暗黑模式和常规模式）：

| 弹窗类型 | 触发条件 | 按钮选项 |
|----------|----------|----------|
| 保存确认弹窗 | 关闭未保存的文件 | 不保存 / 保存 / 取消 |
| 权限不足提示 | 打开无权限文件 | 确定 |
| 文件数量上限提示 | 已打开 30 个文件，尝试打开新文件 | 确定 |
| 文件大小超限提示 | 打开 >100MB 的文件 | 确定 |
| 编码识别失败提示 | 无法自动识别文件编码 | 确定（默认 UTF-8 打开） |

#### 3.2.2 前端入口

- 文件管理 → 右键菜单 → 打开方式 → 文本编辑器
- 文件管理 → 双击文件（.txt, .md, .log, .json, .xml, .py, .js, .html, .css 等）
- 文件管理工具栏 → 新建文件 → 文本文档

#### 3.2.3 应用位置

- TOS 桌面 → 文本编辑器应用

### 3.3 权限规则

| 场景 | 规则 |
|------|------|
| 打开文件 | 打开文件时校验读取权限，无权限则阻止打开并提示 |
| 保存文件 | 保存时校验写入权限，无权限则保存失败并提示 |
| 重命名文件 | 重命名时校验修改权限 |
| 新建文件 | 新建文件时校验目标目录写入权限 |

## 四、流程与状态说明

### 4.1 业务流程图

#### 4.1.1 打开文件流程

```
用户触发打开文件
    │
    ├─ 权限校验 ─── 无权限 ──→ 弹出提示"您的账户权限不足，无法执行此操作。" → 结束
    │
    ├─ 文件大小校验 ─── >100MB ──→ 弹出提示"文件大小超出限制" → 结束
    │
    ├─ 标签页数量校验 ─── 已达30个 ──→ 弹出提示"文件数量已达上限" → 结束
    │
    ├─ 文件是否已打开？
    │   ├─ 是 → 切换到对应标签页 → 结束
    │   └─ 否 → 继续
    │
    ├─ 编码识别
    │   ├─ 成功 → 使用识别到的编码加载
    │   └─ 失败 → 默认 UTF-8 打开，提示用户
    │
    ├─ 文件大小 50-100MB？
    │   ├─ 是 → 分块加载策略
    │   └─ 否 → 正常加载
    │
    └─ 新增标签页（最右侧），显示内容 → 结束
```

#### 4.1.2 关闭流程（含未保存文件处理）

```
用户触发关闭操作
    │
    ├─ 单个关闭 → 关闭当前标签页
    ├─ 全部关闭 → 从左往右逐个关闭
    └─ 关闭最后一个标签 → 退出应用
    │
    └─ 遍历标签页（从左往右）
        │
        ├─ 文件已保存？── 是 ──→ 直接关闭 → 继续下一个
        │
        └─ 否 → 弹出保存确认弹窗
            ├─ 不保存 → 关闭此文件 → 继续下一个
            ├─ 保存 ─── 新建文件？→ 调出路径选择 → 保存 → 关闭 → 继续下一个
            │                      已有文件？→ 直接保存 → 关闭 → 继续下一个
            └─ 取消 → 中断关闭流程，保留所有未关闭标签页 → 结束
```

#### 4.1.3 大文件分块加载流程

```
打开大文件（50-100MB）
    │
    └─ 初始化编辑器
        │
        ├─ 首次加载可视区域内容（50-100行）
        │
        └─ 监听滚动事件
            │
            ├─ 向上滚动 → 加载上方可视块
            │
            ├─ 向下滚动 → 加载下方可视块 + 预加载下方 200 行
            │
            └─ 超出可视区域较远的块 → 从内存卸载
                └─ 保留最近访问的 5-10 个块
```

### 4.2 状态流转

#### 4.2.1 标签页状态

```
[空闲] ── 用户编辑内容 ──→ [已修改未保存]（显示 ● 标记）
[已修改未保存] ── 用户保存 ──→ [已保存]（● 标记消失）
[已修改未保存] ── 用户关闭 ──→ 弹出保存确认弹窗
[已保存] ── 用户关闭 ──→ [已关闭]
```

#### 4.2.2 新建文件状态

```
[新建] ── 默认文件名 "New file.txt" ──→ [内存中未保存]（显示 ● 标记）
[内存中未保存] ── 用户保存 ──→ 选择保存路径 ──→ [已保存到磁盘]
[内存中未保存] ── 用户关闭 ──→ 弹出保存确认弹窗
[内存中未保存] ── 取消保存 ──→ [仍在内存中]
```

### 4.3 边界场景与异常处理

#### 4.3.1 异常处理表

| 异常情况 | 处理方式 | 提示文案 |
|----------|----------|----------|
| 文件读取失败 | 弹出错误提示，标签页不打开 | 文件读取失败，请检查文件是否损坏。 |
| 文件内容为空 | 正常打开，显示空白编辑器 | （无提示，正常显示） |
| 保存时磁盘空间不足 | 保存失败，保留编辑器内容 | 保存失败！可用不足。 |
| 保存时路径无写入权限 | 保存失败 | 保存失败！您的账户权限不足，无法写入此位置。 |
| 重命名时文件名含非法字符 | 阻止重命名，弹窗提示 | 文件或文件夹名称不能包含冒号（:）或斜杠（/）。 |
| 重命名时文件名已存在 | 阻止重命名，弹窗提示 | 此位置已包含同名文件。 |
| 网络中断（远程文件） | 阻止打开/保存，提示重试 | 网络连接失败，请检查网络后重试。 |
| 编辑器初始化失败 | 降级使用原生 textarea | 编辑器加载失败，已切换到基础模式。 |

#### 4.3.2 补充边界场景

| 边界场景 | 处理策略 |
|----------|----------|
| 快速连续点击打开同一文件 | 防抖处理，仅在文件未打开时新增标签页，已打开则切换到对应标签页 |
| 在保存确认弹窗期间，其他标签页被操作 | 保存确认弹窗为模态弹窗（含遮罩层），阻止其他操作 |
| 分块加载中大文件被外部修改 | 提示用户文件已被外部修改，询问是否重新加载 |
| 浏览器刷新/关闭时未保存内容 | 利用 `beforeunload` 事件提示用户有未保存的更改 |
| 标签页标题过长 | 标签页标题截断显示，末尾显示省略号，hover 时显示完整标题 Tooltip |
| 同时打开多个大文件 | 内存中只保留当前活跃标签页的完整内容，非活跃标签页仅保留摘要和修改状态 |
| 新建文件后未保存即关闭浏览器 | 内存数据丢失，不保留（新建文件仅在保存后才写入磁盘） |
| 右键菜单在编辑器区域触发 | 显示编辑器原生右键菜单（剪切/复制/粘贴/查找等），仅在标签页标题区域触发自定义右键菜单 |

## 五、数据口径与埋点需求

### 5.1 数据指标

| 指标名称 | 口径定义 | 目标值 |
|----------|----------|--------|
| 文本编辑器日活用户数 | 每日打开文本编辑器的独立用户数 | 待定 |
| 多标签页使用率 | 打开 ≥2 个标签页的会话数 / 总会话数 | 待定 |
| 大文件打开成功率 | 50MB+ 文件成功打开数 / 50MB+ 文件打开请求总数 | ≥95% |
| 大文件首次加载时间 | 50MB+ 文件从点击到可视区域内容显示的时间 | ≤1秒 |
| 编码识别准确率 | 正确识别编码的文件数 / 总打开文件数 | ≥95% |
| 未保存文件丢失率 | 因未保存关闭导致内容丢失的事件数 / 总关闭事件数 | 趋近于0 |

### 5.2 埋点事件

| 事件ID | 事件名称 | 触发时机 | 关键参数 |
|--------|----------|----------|----------|
| text_editor_open | 打开编辑器 | 进入文本编辑器 | entry_source（入口来源） |
| text_editor_file_open | 打开文件 | 成功打开一个文件 | file_size, file_type, encoding, open_duration |
| text_editor_tab_switch | 切换标签页 | 点击切换标签页 | tab_count, switch_from, switch_to |
| text_editor_tab_close | 关闭标签页 | 关闭单个标签页 | close_reason（手动/全部关闭/关闭最后一个） |
| text_editor_save | 保存文件 | 执行保存操作 | file_size, is_new_file, save_duration |
| text_editor_save_confirm | 保存确认弹窗 | 弹出保存确认弹窗 | user_action（不保存/保存/取消） |
| text_editor_large_file_load | 大文件加载 | 加载 50MB+ 文件 | file_size, load_duration, chunk_count |
| text_editor_encoding_fail | 编码识别失败 | 编码自动识别失败 | file_name, file_extension |
| text_editor_error | 异常事件 | 各类异常发生 | error_type, error_message |
