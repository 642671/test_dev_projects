## 一、需求背景与目标

### 1.1 当前状况与问题

当前 TOS 7.0 文本编辑器**不支持查找与替换功能**，用户在处理长文档或代码时存在以下痛点：

- 无法快速定位关键词位置，需手动浏览全文查找
- 无法批量替换文本内容，需逐处手动修改
- 无正则表达式支持，复杂文本匹配无法完成
- 大文档中定位困难，影响编辑效率

本次需求旨在从零构建完整的查找与替换功能，对齐主流编辑器的体验标准。

### 1.2 实现目标

| 维度 | 实现前 | 实现后 |
|------|--------|--------|
| 查找功能 | 不支持 | 支持实时检索（防抖 300ms）+ 高亮显示 |
| 替换功能 | 不支持 | 支持替换当前/全部替换 + 保留大小写 |
| 查找范围 | 不支持 | 支持全文查找 / 选区查找 |
| 正则表达式 | 不支持 | 支持正则语法 + 捕获组引用 + 错误提示 |
| 大文档性能 | 不支持 | Web Worker 分片检索，不阻塞 UI |
| 只读文件 | 不支持 | 只读模式下替换功能禁用，查找可用 |

### 1.3 目标用户

- **开发者**: 编辑代码文件时需要快速定位和批量修改变量名、函数名等
- **运维人员**: 查看和编辑大型日志文件时需要定位关键错误信息
- **普通用户**: 编辑长文本时需要快速查找特定内容并替换
- **文档管理员**: 编辑只读配置文件时需要查看但不能修改

### 1.4 用户价值

- **效率提升**: 实时检索 + 高亮显示，无需手动浏览全文
- **批量操作**: 全部替换功能支持一键修改大量内容，支持 Ctrl+Z 撤销
- **精准匹配**: 正则表达式、全词匹配、区分大小写等多维度筛选
- **性能保障**: 10万行以上大文档通过 Web Worker 分片检索，UI 不卡顿
- **体验对标**: 对齐 VS Code、Sublime Text 等主流编辑器标准

## 二、用户故事

1. 作为**开发者**，我希望使用正则表达式批量替换代码中的日期格式，以便快速完成代码重构
2. 作为**运维人员**，我希望在大型日志文件中实时高亮关键词，以便快速定位 ERROR 级别的日志
3. 作为**普通用户**，我希望在选中区域内精确替换文本，以便仅修改特定段落的内容而不影响其他部分
4. 作为**文档管理员**，我希望在只读配置文件中仍能使用查找和高亮功能，以便查看配置项但不会被误修改
5. 作为**所有用户**，我希望查找替换面板支持快捷键操作，以便提升操作效率

## 三、功能清单与需求描述（EARS原则）

### 3.1 核心功能

#### 3.1.1 查找功能

| 编号 | EARS类型 | 需求描述 |
|------|----------|----------|
| F-01 | Ubiquitous | 系统应提供查找输入框，支持用户输入关键词后进行实时检索和高亮显示 |
| F-02 | Event-driven | 当用户在查找框中输入内容时，系统应在300ms防抖后自动触发检索，无需回车确认 |
| F-03 | Event-driven | 当查找框内容被清空时，系统应清除所有高亮标记，计数显示为"0 of 0"，替换按钮置灰 |
| F-04 | Ubiquitous | 系统应将当前选中的匹配项（第N项）以强化高亮样式（如橙色背景）显示，其余匹配项以弱化高亮样式（如灰色背景）显示 |
| F-05 | State-driven | 当区分大小写、全词匹配或正则模式开关状态变更时，系统应同步更新高亮结果 |
| F-06 | Event-driven | 当用户点击"上一个"或"下一个"切换匹配项时，编辑器视口应自动滚动，确保当前项处于可视区域中心 |
| F-07 | Event-driven | 当用户在文档末尾点击"下一个"时，系统应自动循环跳转至第1个匹配项 |
| F-08 | Event-driven | 当用户关闭查找面板时，系统应清除所有高亮与状态 |
| F-09 | Ubiquitous | 计数显示最大值参考 VS Code 标准，超过 199999 时显示 "199999+" |

#### 3.1.2 替换功能

| 编号 | EARS类型 | 需求描述 |
|------|----------|----------|
| R-01 | Event-driven | 当用户点击"替换当前"时，系统应仅替换当前聚焦的第N个匹配项，替换后焦点自动跳转至下一个匹配项，N值保持不变，总数M减1 |
| R-02 | Event-driven | 当"替换当前"操作完成后，系统应更新计数显示 |
| R-03 | Event-driven | 当用户点击"全部替换"时，系统应对当前范围内所有匹配项执行批量替换 |
| R-04 | Event-driven | 当"全部替换"操作完成后，系统应弹出轻提示（Toast）："已替换 X 处" |
| R-05 | Event-driven | 当用户执行"全部替换"后按 Ctrl+Z 时，系统应支持一键撤销全部替换操作 |
| R-06 | Event-driven | 当大文档执行全部替换时，系统应显示操作进度 |

#### 3.1.3 正则表达式支持

| 编号 | EARS类型 | 需求描述 |
|------|----------|----------|
| RE-01 | Ubiquitous | 系统应支持在替换框中使用 `$1`, `$2` 等语法引用捕获组 |
| RE-02 | Ubiquitous | 系统应支持使用 `$&` 引用完整匹配字符串 |
| RE-03 | Ubiquitous | 系统应支持 `\n`（换行）、`\t`（制表符）等转义字符 |
| RE-04 | Ubiquitous | `$` 和 `\` 为保留字符，若用户需输入字面量应使用 `\$` 或 `\\` 进行转义 |
| RE-05 | Event-driven | 当正则表达式语法无效时，输入框边框应标红，提示"正则表达式无效，请检查语法。"，不崩溃 |
| RE-06 | Event-driven | 当用户修正正则表达式后，系统应自动恢复高亮和计数 |

#### 3.1.4 模式开关

| 编号 | EARS类型 | 需求描述 |
|------|----------|----------|
| SW-01 | Event-driven | 当用户开启"区分大小写"开关时，系统应在匹配时区分字符大小写 |
| SW-02 | Event-driven | 当用户开启"全词匹配"开关时，系统应仅匹配完整单词，不匹配单词内部子串 |
| SW-03 | Event-driven | 当用户开启"正则表达式"开关时，系统应将查找框内容解析为正则表达式进行匹配 |
| SW-04 | Event-driven | 当用户开启"选区查找"开关时，系统应仅在当前选中的文本范围内执行查找和替换 |
| SW-05 | Event-driven | 当用户开启"保留大小写"开关时，系统应在替换时保留原词的大小写格式（仅当正则模式关闭时生效，与正则互斥） |
| SW-06 | Event-driven | 当用户同时开启"正则表达式"和"保留大小写"时，系统应自动关闭"保留大小写"并置灰禁用，或阻止"保留大小写"开启并提示"正则模式下无法使用保留大小写" |
| SW-07 | State-driven | 当首次打开或重置面板时，所有模式开关默认均为关闭状态，查找框默认为空（如有选区内容则自动填充选区文本），替换框默认为空 |

#### 3.1.5 大文档性能优化

| 编号 | EARS类型 | 需求描述 |
|------|----------|----------|
| PF-01 | State-driven | 当文档行数超过10万行时，系统应自动启用 Web Worker 或后台线程进行分片检索，UI 线程不阻塞 |
| PF-02 | Event-driven | 当检索进行中时，计数应显示"Searching..."或加载动画 |
| PF-03 | Ubiquitous | 系统应对高亮结果进行分批次渲染，避免一次性渲染过多 DOM 节点导致白屏 |
| PF-04 | Unwanted | 若分片检索超过10秒，系统应显示提示"检索时间较长，是否继续？"，用户可选择中断 |

#### 3.1.6 只读文件处理

| 编号 | EARS类型 | 需求描述 |
|------|----------|----------|
| RO-01 | State-driven | 当文件为只读属性时，替换输入框及替换按钮应置灰禁用 |
| RO-02 | State-driven | 当文件为只读属性时，查找和高亮功能仍应保持可用 |
| RO-03 | Event-driven | 当用户在只读文件中尝试保存替换结果时，文件系统应返回提示 |

### 3.2 交互说明

#### 3.2.1 入口位置

- **入口位置**: 编辑器顶部工具栏 → 新增"查找"放大镜图标按钮
- **快捷键**: `Ctrl+F` 打开查找面板，`Ctrl+H` 打开替换面板，`ESC` 关闭面板
- **关闭方式**: 编辑器右上角可点击 × 按钮关闭面板

#### 3.2.2 面板交互

- 面板打开期间保留开关状态和输入内容（短期记忆）
- 关闭面板后清除所有高亮与状态
- 查找框为空时，替换按钮置灰
- 正则表达式无效时，替换按钮置灰
- 只读文件时，替换输入框和替换按钮置灰

#### 3.2.3 高亮样式

- **当前选中项（第N项）**: 强化高亮（如橙色背景）
- **其余匹配项**: 弱化高亮（如灰色背景）
- 高亮与模式开关（区分大小写、全词匹配、正则）同步更新

#### 3.2.4 模式开关互斥逻辑

```
用户点击"正则表达式"开关
↓
正则模式 = 开启
↓
检查"保留大小写"是否开启？
├─ 是 → 自动关闭"保留大小写"并置灰禁用
└─ 否 → 直接置灰禁用
↓
用户点击"保留大小写"开关
↓
检查正则模式是否开启？
├─ 是 → 提示"正则模式下无法使用保留大小写"，阻止开启
└─ 否 → 正常开启
```

### 3.3 权限规则

- 所有用户均可使用查找功能（包括在只读文件上）
- 替换功能仅对可读写文件可用
- 只读文件：查找可用，替换输入框及按钮置灰
- 无特殊角色权限限制，所有登录用户享有相同功能权限

## 四、流程与状态说明

### 4.1 业务流程图（文字描述）

#### 4.1.1 查找流程

```
用户输入关键词
    ↓
防抖等待 300ms
    ↓
判断查找框是否为空？
├─ 是 → 清除所有高亮，计数 0 of 0 → 结束
└─ 否 → 继续
    ↓
判断是否启用正则模式？
├─ 是 → 验证正则表达式有效性
│   ├─ 无效 → 标红提示，清除高亮 → 结束
│   └─ 有效 → 继续
└─ 否 → 继续
    ↓
判断查找范围（全文/选区）
    ↓
执行检索（普通/正则/全词/大小写敏感）
├─ 大文档 → Web Worker 分片检索
└─ 小文档 → 主线程检索
    ↓
高亮所有匹配项（弱高亮）
    ↓
定位第一个匹配项（强化高亮）
    ↓
更新计数显示（当前N / 总数M）→ 完成
```

#### 4.1.2 替换流程

```
用户点击"替换当前"或"全部替换"
    ↓
替换前校验
├─ 文件只读？→ 保存时提示
├─ 正则模式 + 保留大小写开启？→ 提示冲突，阻止替换
├─ 正则表达式无效？→ 标红提示，阻止替换
└─ 全部通过 → 继续
    ↓
【替换当前】流程：
├─ 仅替换当前聚焦的第 N 个匹配项
├─ 替换后焦点自动跳转至下一个匹配项
├─ N 值保持不变（总数 M 减 1）
└─ 更新计数显示
    ↓
【全部替换】流程：
├─ 对当前范围内所有匹配项执行批量替换
├─ 显示进度（大文档时）
├─ 完成后 Toast 提示"已替换 X 处"
└─ 支持 Ctrl+Z 一键撤销 → 完成
```

### 4.2 状态流转

#### 4.2.1 面板状态机

| 当前状态 | 触发事件 | 目标状态 | 说明 |
|----------|----------|----------|------|
| 关闭 | 点击工具栏图标 / Ctrl+F | 查找面板打开 | 查找框自动聚焦 |
| 关闭 | Ctrl+H | 替换面板打开 | 替换框自动聚焦 |
| 查找面板打开 | Ctrl+H | 替换面板打开 | 切换为替换面板，保留查找框内容 |
| 替换面板打开 | Ctrl+F | 查找面板打开 | 切换为查找面板 |
| 面板打开 | ESC / 点击× | 关闭 | 清除所有高亮与状态 |
| 面板打开 | 切换文件 | 面板关闭后重新打开 | 根据新文件状态重置 |

#### 4.2.2 查找框状态

| 状态 | 高亮 | 计数 | 替换按钮 |
|------|------|------|----------|
| 空 | 清除 | 0 of 0 | 置灰 |
| 有效输入（普通） | 显示 | N of M | 可用 |
| 有效输入（正则） | 显示 | N of M | 可用 |
| 正则无效 | 清除 | -- | 置灰 |
| 检索中（大文档） | 分批次渲染 | Searching... | 置灰 |

### 4.3 边界场景与异常处理

| 异常类型 | 触发条件 | 处理方式 | 提示文案 |
|----------|----------|----------|----------|
| 正则表达式无效 | 正则模式开启，输入非法正则 | 输入框边框标红，清除高亮，禁用替换按钮 | 正则表达式无效，请检查语法。 |
| 正则+保留大小写冲突 | 同时开启正则和保留大小写 | 自动禁用保留大小写，或阻止开启 | 正则模式下无法使用保留大小写。 |
| 只读文件保存 | 文件为只读属性 | 保存时提示 | 文件为只读属性，无法保存替换结果。 |
| 大文档检索超时 | 分片检索超过10秒 | 显示提示，用户可选择中断 | 检索时间较长，是否继续？ |
| 查找框为空 | 查找框无内容 | 清除高亮，替换按钮置灰 | （无提示，正常状态） |
| 选区查找无选区 | 开启选区查找但未选中文本 | 自动降级为全文查找 | 未选中文本，已切换为全文查找。 |
| 查找无结果 | 全文/选区中无匹配项 | 计数显示 "0 of 0"，替换按钮置灰 | （无提示，正常空状态） |
| 替换当前在最后一项 | 当前N项为最后一项且执行替换当前 | 替换后N保持不变，总数M减1，跳转到下一个（即原N+1变为新N） | -- |
| 全部替换无匹配 | 当前范围无匹配项 | Toast提示替换数为0 | 已替换 0 处 |
| 大文档全部替换 | 文档超过10万行且匹配项超过1000处 | 显示进度条，支持中断 | 正在替换 X/Y 处... |
| 撤销全部替换 | 用户按 Ctrl+Z 撤销全部替换 | 一次性撤销所有替换，恢复原始文本 | -- |
| 文件编码异常 | 文件包含非标准编码字符 | 查找和替换正常执行，按字符码点匹配 | -- |

## 五、数据口径与埋点需求

### 5.1 数据指标

| 指标名称 | 口径说明 | 用途 |
|----------|----------|------|
| 查找功能使用次数 | 用户打开查找面板并执行检索的次数 | 评估功能使用率 |

| 只读文件查找次数 | 在只读文件上执行查找的次数 | 评估只读场景 |

### 5.2 埋点事件

| 事件名称 | 触发时机 | 上报参数 |
|----------|----------|----------|
| `find_panel_open` | 打开查找/替换面板 | `trigger`: 工具栏/快捷键/菜单, `mode`: find/replace |
| `find_search_input` | 查找框输入内容（防抖后上报） | `keyword_length`, `has_regex`, `has_case_sensitive`, `has_whole_word`, `has_selection` |
| `find_search_result` | 检索完成 | `match_count`, `scope`: full/selection, `duration_ms`, `is_large_doc` |
| `find_navigate` | 切换匹配项（上一个/下一个） | `direction`: prev/next, `current_n`, `total_m` |
| `replace_current` | 执行替换当前 | `match_count_before`, `match_count_after` |
| `replace_all` | 执行全部替换 | `match_count`, `scope`: full/selection, `duration_ms`, `is_undone`: true/false |
| `find_regex_error` | 正则表达式无效 | `error_message` |
| `find_mode_toggle` | 切换模式开关 | `mode`: case_sensitive/whole_word/regex/selection/preserve_case, `new_state`: on/off |
| `find_panel_close` | 关闭面板 | `close_method`: esc/button/file_switch |
| `find_timeout` | 大文档检索超时 | `doc_lines`, `search_duration_ms`, `user_action`: continue/cancel |
| `find_no_result` | 查找无结果 | `keyword_length`, `scope`, `modes` |

## 六、验收标准

### 6.1 功能验收

| 验收项 | 验收标准 |
|--------|----------|
| 实时检索 | 输入关键词后 300ms 内开始检索，高亮渲染无明显延迟 |
| 计数准确 | N of M 计数准确，当前选中项序号正确 |
| 空状态 | 查找框为空时，清除所有高亮，计数显示 0 of 0 |
| 替换当前 | 仅替换当前聚焦匹配项，替换后焦点自动跳转至下一个 |
| 全部替换 | 对当前范围内所有匹配项执行批量替换，Toast提示替换数量 |
| 全部替换撤销 | 支持 Ctrl+Z 一键撤销全部替换操作 |
| 选区查找-替换范围 | 选区查找模式下，替换操作绝不溢出选区范围 |
| 选区查找-计数范围 | 开启选区查找后，计数仅统计选区内的匹配项 |
| 保留大小写 | 替换时保留原词的大小写格式（如 "User" → "Admin"） |
| 正则-错误提示 | 正则错误时，输入框标红提示，不崩溃，修正后自动恢复 |
| 正则-语法支持 | 支持 `$&`、`\n`、`\t`、`$1`、`$2` 等正则语法 |
| 正则-保留字符转义 | `$` 和 `\` 需通过 `\$` 或 `\\` 转义输入字面量 |
| 模式开关-默认状态 | 首次打开面板时所有开关默认关闭 |
| 模式开关-选区填充 | 如有选区内容，打开面板时自动填充选区文本到查找框 |
| 模式开关-互斥 | 正则+保留大小写冲突时自动处理并提示 |
| 大文档-不卡顿 | 10万行文档检索时 UI 不卡顿，计数显示"Searching..." |
| 大文档-分片渲染 | 高亮分批次渲染，无明显白屏 |

| 全部替换（大批量） | 匹配项 > 1000 处时，显示进度条，不阻塞 UI |

| 面板打开 | 面板打开响应时间 < 100ms |
| 检索超时 | 分片检索超时阈值 10 秒，超时后提示用户 |
