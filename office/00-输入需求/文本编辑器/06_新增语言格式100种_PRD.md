## 一、需求背景与目标

### 1.1 当前状况与问题

当前 TOS 7.0 文本编辑器已实现基础语法高亮，但存在以下不足：

- 仅支持约 10 种基础语言的语法高亮（JavaScript、HTML、CSS 等）
- 不支持 Python、Java、Go、Rust、Ruby、Swift 等主流编程语言的高亮
- 不支持配置文件格式（JSON、YAML、TOML、Dockerfile 等）
- 不支持数据库查询语言（SQL、GraphQL 等）
- 不支持标记语言（Markdown、LaTeX 等）
- 无法根据文件扩展名自动识别语言类型

当前使用的是 Monarch 语法高亮引擎，该引擎对复杂语言的支持能力有限，且缺乏成熟的语言包生态，导致无法快速扩展语言支持范围。

### 1.2 实现目标

将文本编辑器的语法高亮引擎从 Monarch 迁移至 TextMate Grammar，实现 100+ 种编程语言、标记语言、配置文件格式及数据库查询语言的语法高亮支持，并对齐竞品（绿联 UGOS Pro 已支持 70+ 种），在语言覆盖数量上实现超越。

| 维度 | 实现前 | 实现后 |
|------|--------|--------|
| 语法高亮引擎 | Monarch（支持有限） | **TextMate Grammar** |
| 支持语言数量 | 约 10 种 | **100+ 种** |
| 语言自动识别 | 不支持 | 根据文件扩展名自动识别 |
| 语言切换入口 | 无 | 底部状态栏点击切换 |
| 配置文件格式支持 | 不支持 | 完整支持 JSON、YAML、TOML、Dockerfile 等 |
| 数据库语言支持 | 不支持 | 完整支持 SQL、GraphQL 等 |
| 标记语言支持 | 不支持 | 完整支持 Markdown、LaTeX 等 |

### 1.3 目标用户

- **开发者用户**: 使用 TOS 7.0 文本编辑器查看和编辑各类代码文件的 NAS 用户
- **运维人员**: 需要通过 Web 编辑器修改 NAS 上配置文件（Dockerfile、YAML、JSON 等）的用户
- **技术写作者**: 使用 Markdown、LaTeX 等标记语言编写文档的用户
- **数据库管理员**: 查看和编辑 SQL 脚本文件的用户

### 1.4 用户价值

- **提升代码可读性**: 通过正确的语法高亮，帮助用户快速理解代码结构，减少阅读错误
- **降低切换成本**: 用户无需下载文件到本地编辑器即可在 Web 端获得接近 IDE 的代码阅读体验
- **扩展使用场景**: 支持 100+ 种语言后，覆盖更多用户群体的文件编辑需求
- **提升产品竞争力**: 对齐并超越绿联 UGOS Pro，在语法高亮维度建立差异化优势

状态栏位于编辑器底部，包含以下信息：


- 纯文本模式下不执行任何高亮规则，无需特殊权限

## 四、流程与状态说明

### 4.1 业务流程图

#### 流程一：语言自动识别流程

```
用户打开文件
    ↓
获取文件扩展名
    ↓
查找扩展名映射表
    ↓
是否匹配到语言？
    ├─ 是 → 自动切换到对应语言的语法高亮
    └─ 否 → 默认使用纯文本模式
    ↓
更新底部状态栏语言显示
    ↓
完成
```

#### 流程二：语言切换流程

```
用户点击状态栏"语言 Python"
    ↓
弹出语言选择菜单（100+ 种语言，分组排序）
    ↓
用户选择目标语言（如 Java）
    ↓
系统加载对应的 TextMate 语法规则
    ↓
重新渲染语法高亮
    ↓
更新状态栏显示"语言 Java"
    ↓
完成
```

### 4.2 状态流转

#### 编辑器语言状态

```
[自动识别成功] → 语言模式（状态栏显示语言名称，语法高亮启用）
[自动识别失败] → 纯文本模式（状态栏显示"纯文本"，语法高亮禁用）
[用户手动选择] → 语言模式（覆盖自动识别结果）
[用户选择纯文本] → 纯文本模式
```

#### 语法高亮加载状态

```
[打开文件] → 加载中（显示加载提示）
    ├─ [加载成功] → 高亮渲染中 → 渲染完成
    └─ [加载失败] → 降级纯文本模式（显示降级提示）
```

### 4.3 边界场景与异常处理

| 编号 | 场景类型 | 场景描述 | 处理方式 | 提示文案 |
|------|----------|----------|----------|----------|
| EX-01 | 异常 | 语法文件加载失败 | 降级到纯文本模式，禁止语法高亮，允许正常编辑 | 语法高亮加载失败，已切换到纯文本模式。 |
| EX-02 | 异常 | 语言识别失败（无扩展名或未知扩展名） | 默认使用纯文本模式，状态栏显示"纯文本" | 无法识别文件类型，已使用纯文本模式，请手动选择语言。 |
| EX-03 | 异常 | 语法高亮解析超时（大文件或复杂语法） | 显示加载提示，继续后台解析，不阻塞编辑操作 | 正在解析语法高亮，请稍候... |
| EX-04 | 边界 | 大文件高亮性能（文件 > 100 MB） | 禁用语法高亮，仅提供基础编辑功能 | 文件较大，已禁用语法高亮以提升性能。 |
| EX-05 | 边界 | 文件扩展名映射冲突（同一扩展名对应多种语言） | 按映射表优先级选择默认语言，用户可手动切换 | 无提示（静默处理） |
| EX-06 | 边界 | 用户快速切换语言 | 取消上一次未完成的加载请求，仅加载最新选择的语言 | 无提示（静默处理） |
| EX-07 | 边界 | 编辑器同时打开多个文件 | 每个标签页独立维护语言状态，互不影响 | — |
| EX-08 | 异常 | TextMate 语法文件解析失败 | 降级到纯文本模式，记录错误日志 | 语法高亮加载失败，已切换到纯文本模式。 |
| EX-09 | 边界 | Dockerfile 无扩展名识别 | 根据文件名精确匹配（Dockerfile、Dockerfile.dev 等）自动识别 | — |
| EX-10 | 边界 | Makefile 识别 | 根据文件名精确匹配（Makefile、GNUMakefile）自动识别 | — |
| EX-11 | 边界 | 搜索过滤无匹配结果 | 显示空状态提示"未找到匹配的语言" | 未找到匹配的语言 |
