
# 重启系统后，未完成的 Hyper Cache 创建和删除操作继续进行

---

## 一、目前是什么状况？

当前 Hyper Cache 创建和删除操作**不支持系统重启后的任务恢复**。

当用户执行 Hyper Cache 创建或删除操作过程中，系统发生重启：

**原问题（已修复）**：

未完成的 Hyper Cache 操作状态会残留，导致：

- Hyper Cache 一直显示"创建中"或"删除中"
- 操作无法继续执行
- 用户无法重新操作或取消任务

> 关联 Bug：【hypercache 创建中重启 NAS 导致状态位残留】
> <https://www.tapd.cn/tapd_fe/58480755/bug/detail/1158480755001037397>

**当前状态（Bug 修复后）**：

系统重启后，未完成的 Hyper Cache 创建 / 删除任务状态不会继续显示。表现为：

- 创建任务未完成，但 Hyper Cache 不存在对应状态
- 删除任务未完成，但删除状态丢失
- 用户无法确认任务是否继续执行

---

## 二、通过实现需求达到什么目的？

完善 Hyper Cache 创建和删除任务流程，使系统具备**重启后的任务继续进行**的能力。

| 目标 | 说明 |
|------|------|
| **任务识别** | 系统重启后能够识别未完成的 Hyper Cache 操作 |
| **自动恢复** | 自动恢复执行未完成任务 |
| **状态可见** | 页面显示真实任务状态 |

---

## 三、在哪一个版块 / 位置上实现？

> **Hyper Cache**

---

## 四、详细功能要求

重启系统后，未完成的 Hyper Cache 的创建和删除操作继续进行。

### 4.1 创建 Hyper Cache 任务恢复

| 步骤 | 操作 |
|------|------|
| 1 | 用户创建 Hyper Cache |
| 2 | 创建过程中系统发生重启 |
| 3 | 系统启动完成 |
| 4 | 系统检测是否存在未完成创建任务 |
| 5 | 自动继续执行创建流程 |
| 6 | 完成后更新 Hyper Cache 状态 |

### 4.2 删除 Hyper Cache 任务恢复

| 步骤 | 操作 |
|------|------|
| 1 | 用户删除 Hyper Cache |
| 2 | 删除过程中系统发生重启 |
| 3 | 系统启动完成 |
| 4 | 检测未完成删除任务 |
| 5 | 自动继续删除流程 |
| 6 | 删除完成后更新状态 |
