# 支持存储池后台任务期间连续创建存储池

> 文档状态：已根据人工修订后的84条正式测试用例反向补充，当前为需求完善版，仍保留少量技术实现待确认项。

---

## 一、目前是什么状况？

当前 TOS 存储管理前端限制用户一次只能创建一个存储池。创建一个存储池后，即使存储池已经完成创建并进入耗时较长的阵列同步阶段，用户仍需等待相关任务结束后才能继续创建下一个存储池。

设置该限制的原始原因是防止同时处理多个存储池任务时占用过多 CPU、内存和磁盘 I/O，导致系统卡顿或死机。

该限制增加了运维人员批量部署多个存储池时的等待时间和操作成本。

---

## 二、通过实现需求达到什么目的？

1. 提升批量部署多个存储池时的运维效率。
2. 存储池仍然一次创建一个，不允许多个存储池同时处于“创建中”。
3. 一个存储池完成创建并进入允许并行的后台任务状态后，可以继续创建新的存储池。
4. 多个存储池可以同时执行阵列同步等后台任务，但各存储池的任务、进度和结果必须相互独立。
5. 在提高效率的同时控制系统资源占用，避免系统过载、卡顿或死机。
6. 创建、删除等互斥规则不仅在页面按钮层生效，后端也必须拒绝冲突请求，避免绕过页面限制后产生重复任务、假成功或磁盘残留占用。
7. 删除存储池后的列表序号可复用，但必须始终唯一，并优先复用当前最小空洞序号。
8. 创建或删除任务失败、超时重试及异常断电后，任务记录、存储池真实状态、互斥锁和资源占用必须可恢复。

---

## 三、在哪一个版块 / 位置上实现？

> **存储管理 > 存储池**

涉及页面元素：

- 存储池列表。
- 页面左上角“＋”创建存储池按钮。
- 创建按钮置灰后的悬停提示。
- 存储池状态、任务进度及通知展示。

## 四、核心业务规则

### 4.1 创建任务仍然串行执行

- 任意时刻最多只允许一个存储池处于“创建中”。
- 当当前存储池完成创建并离开“创建中”状态后，再根据其后续状态决定是否允许创建下一个存储池。
- 本需求不是同时发起多个创建任务，而是允许已创建的存储池在后台同步期间继续创建下一个存储池。

### 4.2 创建按钮状态判断

创建按钮是否可用，需要全局检查存储池列表中所有存储池的状态。

| 存储池状态 | 是否允许创建新存储池 | 说明 |
| --- | --- | --- |
| 创建中 | 否 | 防止同时执行多个创建任务 |
| 删除中 | 否 | 删除任务执行期间禁止新建存储池 |
| 可用池挂载中 | 否 | 可用池挂载任务执行期间禁止新建存储池 |
| 损坏池挂载中 | 否 | 损坏池挂载任务执行期间禁止新建存储池 |
| 同步中 | 是 | 允许继续创建新存储池 |
| 添加磁盘中 | 是 | 允许继续创建新存储池 |
| 修复中（阵列修复任务触发） | 是 | 阵列修复操作执行期间，页面状态显示“修复中”，允许继续创建新存储池 |
| 修复中（热备盘自动补位触发） | 是 | 热备盘补入冗余存储池并恢复冗余期间，页面状态同样显示“修复中”，允许继续创建新存储池 |
| 更换磁盘中 | 是 | 允许继续创建新存储池 |
| 迁移中 | 是 | 允许继续创建新存储池 |
| 重建中 | 是 | 允许继续创建新存储池 |
| 数据清理中 | 是 | 允许继续创建新存储池 |
| 正常 | 是 | 没有其他限制条件时允许创建 |
| 已降阶 | 是 | 当前需求未将单纯已降阶列为禁止创建状态；仍需满足磁盘资源等其他创建条件 |
| 损坏 | 是 | 阵列已经损坏的存储池不会单独阻止创建新存储池；仍需与“损坏池挂载中”区分 |

判断优先级：

- “创建中、删除中、挂载中”属于禁止状态，优先级高于所有允许状态。
- 只要列表中任意一个存储池处于禁止状态，创建按钮就必须置灰。
- 即使其他存储池同时处于同步中、修复中或迁移中等允许状态，也不能覆盖禁止状态。
- 禁止状态结束后，如果没有其他禁止创建的条件，创建按钮应自动恢复可用。

示例：存储池 A 正在同步，存储池 B 正在创建。由于列表中存在“创建中”，创建按钮必须置灰。存储池 B 完成创建并进入同步中后，如果列表中不存在创建中、删除中或挂载中的存储池，创建按钮恢复可用。

状态名称说明：

- 阵列修复任务和热备盘自动补位修复是两种不同的业务触发来源，但人工修订后的用例均要求页面状态显示“修复中”。
- 测试时通过操作入口、目标存储池、任务记录和触发来源区分两类修复过程，不再依赖“阵列修复中”与“修复中”两个不同界面状态名称进行区分。
- 两类修复过程都属于允许创建新存储池的状态，且各自任务和进度不得串池。
- “损坏”表示存储池阵列已经损坏，该静态健康状态允许创建新存储池。
- “损坏池挂载中”表示正在对损坏池执行挂载任务，属于禁止创建状态。损坏池尚未发起挂载时，不能因为其“损坏”状态将创建按钮置灰。

### 4.3 创建按钮置灰提示

当创建按钮因为存在创建中、删除中或挂载中的存储池而置灰时，悬停显示：

> 系统正在处理其他存储池的创建或删除操作，请稍后再试

挂载中的使用场景较少，本需求保持现有提示语不变，不增加“挂载”相关描述。

### 4.4 删除按钮状态判断

- 任一存储池处于“创建中”时，其他存储池的删除按钮置灰，不能进入删除确认流程，后端不得新增删除任务。
- 任一存储池处于“删除中”时，其他存储池的删除按钮置灰，任意时刻最多只允许一个存储池处于删除中。
- 其他存储池处于可用池挂载中或损坏池挂载中时，不单独禁止删除目标存储池；挂载任务与删除任务必须保持独立。
- 创建中或删除中任务结束后，如果目标用户具备删除权限且不存在其他删除限制，删除按钮应在当前页面自动恢复，无需退出页面或手动刷新。

### 4.5 后端互斥闸门

页面置灰不能作为唯一保护。使用两个独立管理员会话或自动化方式在临界窗口提交请求时，后端至少需要满足：

1. 已存在删除中任务时，新的创建请求被明确拒绝。
2. 已存在创建中任务时，新的创建请求被明确拒绝，任意时刻最多一个有效创建任务。
3. 已存在创建中任务时，删除其他存储池的请求被明确拒绝。
4. 已存在删除中任务时，删除其他存储池的请求被明确拒绝，任意时刻最多一个有效删除任务。
5. 损坏池挂载中时，新的创建请求被明确拒绝。
6. 建池与删池请求在同一临界窗口到达时，响应结果必须与实际受理任务一致；未受理请求不能返回假成功。
7. 被拒绝或冲突的请求不得生成多余存储池记录、重复任务、重复磁盘占用或残留锁。

当前用例未将“可用池挂载中时绕过页面直接提交创建请求”作为独立后端验收项。该状态在页面层仍属于禁止创建状态；是否同时纳入后端硬闸门，需要结合技术方案确认后再补充专项用例。

### 4.6 本次测试范围

- 本次以存储管理页面的功能测试为主，验证页面状态、创建按钮、存储池列表、任务进度、通知、中断恢复和系统稳定性。
- 不验证接口状态字段、状态码与页面状态之间的映射关系。
- 包含两个独立管理员会话或自动化方式触发的后端互斥、临界并发、幂等和超时重试验证，但不固定接口路径、错误码或幂等标识；具体实现以技术方案为准。
- 页面主流程仍通过存储管理页面执行，后端专项只验证请求是否被正确受理或拒绝、任务与响应是否一致、是否存在重复记录和资源残留。
- 当前不包含“可用池挂载中绕过页面直接建池”和“挂载中直接提交删除其他池”两项独立后端专项用例。

## 五、新建存储池的状态流转

### 5.1 创建完成后直接进入正常状态

以下阵列在完成创建后不进入阵列同步，存储池直接变为“正常”：

- Single。
- JBOD。
- RAID0。
- 单盘 TRAID。

状态流转：

`创建中 → 正常`

### 5.2 创建完成后进入同步状态

使用多块磁盘创建且需要建立冗余数据的阵列，在完成创建阶段后进入“同步中”。

状态流转：

`创建中 → 同步中 → 正常`

有冗余且需要同步的阵列从“创建中”进入“同步中”后，只要列表中不存在其他创建中、删除中或挂载中的存储池，就允许继续创建新的存储池。Single、JBOD、RAID0、单盘 TRAID 等无冗余阵列完成创建后直接进入“正常”，此时同样允许继续创建新的存储池。

### 5.3 列表展示要求

- 正常、已降阶、损坏以及所有任务中的存储池均应继续显示在存储池列表中。
- 多个存储池同时执行同步、阵列修复、热备盘修复、迁移等任务时，每个存储池应独立显示自己的状态和进度。
- 不允许出现任务中的存储池从列表消失、状态串池、进度串池或页面刷新后状态丢失。
- 新创建的存储池加入列表后，不应覆盖、隐藏或错误刷新已有存储池。

### 5.4 热备盘补位状态流转

冗余存储池发生磁盘缺失或故障并触发热备盘自动补位后，存储池进入“修复中”。

典型状态流转：

`已降阶 → 修复中 → 正常`

处于“修复中”时，存储池应继续显示在列表中，并允许创建新的存储池。阵列修复任务和热备盘自动补位修复均使用“修复中”作为界面状态名称，但必须通过任务对象和触发来源正确对应，不能串池，也不能因为该状态单独将创建按钮置灰。

## 六、通知要求

1. 存储池进入已降阶状态时，应产生存储池降阶通知。
2. 存储池同步完成时，应产生同步完成通知。
3. 后续测试必须验证同步完成通知，不得只验证存储池最终变为正常。
4. 多个存储池同时同步时，每个存储池完成后应生成与对应存储池匹配的通知。
5. 本需求重点验证对应事件发生后存在相应通知，并且通知对应正确的存储池；不检查通知的准确文案、通知级别、展示位置、顺序和去重规则。

---

## 七、异常处理要求

### 7.1 同步异常与任务隔离

- 多个存储池同时同步时，单个存储池发生成员盘异常不能影响其他存储池的同步。
- 其他存储池的任务不得被连带停止、标记失败、重置进度或变成错误状态。
- 各存储池的任务记录、进度和最终状态应保持独立。

同步过程中成员盘异常处理：

- 常见异常方式为用户在存储池同步过程中手动拔出阵列成员盘。
- 拔出冗余阵列中的一块成员盘后，应产生存储池降阶通知；当前同步任务继续执行，同步完成后存储池进入“已降阶”状态。
- 如果阵列的全部成员盘都被拔出，存储池进入“损坏”状态。
- 处于已降阶或损坏状态的存储池仍应显示在存储池列表中，并且不会单独阻止创建新的存储池。
- 上述异常不能影响其他存储池正在执行的同步或后台任务。

### 7.2 网络中断恢复

- 网络中断需要同时覆盖两种情况：管理端与 NAS 之间的网络连接中断，以及 NAS 自身网络连接或网络服务中断。
- 网络中断后，NAS 本地正在执行的任务不应仅因为网络连接异常而丢失。
- 网络恢复并重新进入存储池页面后，任务列表和原任务记录应保留。
- 未完成任务应继续执行，并展示当前真实状态和进度。
- 不得生成重复任务，也不得把进行中的任务错误显示为成功、失败或不存在。

### 7.3 异常断电恢复

- 存储池任务执行过程中异常断电，NAS 重新启动后，任务列表和原任务记录必须保留，这是本需求的主要验收要求。
- 重启后存储池通常会进入“重建中”，页面应展示重启后的真实任务和存储池状态。
- 本需求不重点验证断电前同步进度是否从原百分比继续，也不要求精确判断从哪个内部阶段恢复。

删除任务执行过程中异常断电时：

- 不得生成重复删除记录，也不得把未完成删除显示为假成功。
- 重启后存储池列表必须展示后台当前真实状态。
- 原删除任务记录必须保留，并按恢复设计继续执行或进入明确失败状态。

### 7.4 任务失败恢复

- 创建或删除任务失败后必须保留明确失败记录，不能长期停留在创建中、删除中或其他处理中状态。
- 页面刷新、重新进入存储池页面或重新登录后，应展示后台当前真实状态，不能回退为错误缓存值。
- 失败任务必须释放对应互斥锁、候选磁盘占用及其他临时资源，不得持续阻塞后续允许操作。
- 排除失败原因后，相同业务操作可以重新提交；重试只产生一个新的有效任务，不复用错误的旧任务状态。
- 失败注入方式及失败后的目标状态以技术方案为准，只能在无重要数据的专用测试环境执行。

### 7.5 幂等与超时重试

- 两个独立会话同时使用同一组磁盘和等价参数创建存储池时，只允许一个有效任务占用该组磁盘。
- 另一个请求必须返回明确的重复或冲突结果，不得返回假成功。
- 客户端等待超时不能直接等同于NAS端处理失败；必须能通过任务记录确认首次请求是否已被受理。
- 对等价创建请求进行超时重试时，应复用既有结果或返回明确冲突，不得产生第二个有效任务、第二条存储池记录或重复磁盘占用。

### 7.6 存储池序号分配

- 每个当前存在的存储池序号必须唯一。
- 删除存储池后，其序号成为可复用空洞；新建存储池优先使用当前最小空洞序号。
- 存在多个空洞时，后续新建存储池按空洞序号从小到大依次复用。
- 复用空洞不能改变其他现存存储池的序号和列表记录。
- 并发创建场景下，即使只有一个请求被受理，也不得产生相同序号、序号冲突或响应成功但无对应任务的情况。
- 序号的具体界面展示形式以当前产品设计为准，本需求只约束唯一性和最小空洞复用规则。

### 7.7 权限要求

- 无创建权限用户不能因为允许后台任务并行而获得创建能力。
- 无删除权限用户不能因为当前不存在互斥任务而获得删除能力，也不能通过直接请求绕过页面权限限制。
- 权限拒绝后目标存储池记录和数据保持不变，不产生创建或删除任务。

### 7.8 国际化与文案

- 创建中、删除中、两类挂载中及所有允许状态的界面文案必须与被测TOS版本对应的语言包一致。
- 中文、英文及产品支持的其他语言中，不得裸露语言键、`{0}`、`%s`、`{{name}}` 等未替换占位符，也不得混入其他语言文本。
- 切换语言后，状态、按钮提示和任务记录文案应更新为目标语言；不得因为语言切换新建、终止或复制后台任务。
- 状态名称以当前语言包为准。中文标准名称包括“迁移中”“已降阶”“损坏”；阵列修复任务和热备盘自动补位修复的界面状态均按人工修订用例使用“修复中”。

## 八、资源监控与稳定性要求

多个存储池同时执行后台任务时，需要实时监控系统资源，防止任务并发造成系统过载。

当前指标要求：

- CPU 使用率在整个监控期间必须低于 80%。
- 内存使用率在整个监控期间必须低于 90%。
- 持续观察磁盘 I/O 使用情况和响应延迟。

CPU 80% 和内存 90% 是不可触碰的验收红线，不是触发限流、排队、禁止创建或任务降速的条件。本需求不定义达到或超过红线后的产品操作；测试中一旦达到或超过红线，即判定该项不通过，并提交开发重新优化。

当前不预设同时同步或执行后台任务的存储池数量上限。测试应在磁盘和环境条件允许的范围内逐步增加任务数量，观察功能和稳定性。如果发现系统卡顿、死机、任务异常、资源达到红线等重大问题，再与产品共同评估并制定合理的数量上限。

性能与稳定性测试直接使用测试人员当前具备的 NAS 设备和磁盘环境，不要求预先指定统一的 NAS 型号或硬件配置。执行时记录实际测试环境，作为结果分析依据。

除数值指标外，还应确认：

- TOS 页面可正常访问和操作。
- 存储管理服务无崩溃、重启或长时间无响应。
- 系统无明显卡顿、死机或任务长期停滞。
- 各存储池任务进度能够持续更新。
- 高负载期间创建按钮状态判断仍然准确。

## 九、功能验收标准

1. 创建中、删除中以及两类挂载中状态均能使创建按钮置灰。
2. 正常、已降阶、损坏、同步中、添加磁盘中、修复中、更换磁盘中、迁移中、重建中、数据清理中不会单独导致创建按钮置灰；阵列修复任务与热备盘自动补位修复均按“修复中”验收。
3. 禁止状态与允许状态同时存在时，以禁止状态为准。
4. 禁止状态结束后，创建按钮能够根据最新列表状态及时恢复。
5. 新的存储池创建完成后，根据阵列类型正确进入“正常”或“同步中”。
6. 多个任务中的存储池均在列表中正确展示，状态和进度互不干扰。
7. 同步过程中拔出一个成员盘后同步继续，完成后存储池进入已降阶；拔出全部成员盘后存储池进入损坏，其他存储池任务不受影响。
8. 存储池降阶和同步完成时均有对应通知，并对应正确的存储池。
9. 两类网络中断恢复后任务记录保留并继续展示；异常断电重启后任务记录保留，存储池展示重启后的真实状态。
10. 多任务执行期间 CPU 始终低于 80%、内存始终低于 90%，系统和存储管理服务保持稳定；任一指标达到红线即不通过。
11. 创建中或删除中任务存在时，其他存储池的删除按钮按规则置灰；挂载中不会单独禁止删除其他存储池；互斥任务结束后删除按钮自动恢复。
12. 后端对创建、删除冲突请求给出明确受理或拒绝结果，响应与实际任务一致，不产生重复任务、假成功、序号冲突或资源残留。
13. 删除后的存储池序号按最小空洞复用，多个空洞按从小到大顺序复用，其他现存池序号不变。
14. 创建或删除失败、客户端超时重试及删除中异常断电后，真实状态和任务记录可追溯，锁与资源正确释放，允许安全重试。
15. 无创建或删除权限的用户不能绕过页面或后端限制；状态和提示文案与当前语言包一致，切换语言不影响后台任务。

## 十、后续测试重点

### 10.1 P0：创建按钮互斥逻辑

- 分别构造创建中、删除中、可用池挂载中、损坏池挂载中，验证按钮置灰和提示语。
- 分别构造同步中、添加磁盘中、修复中、更换磁盘中、迁移中、重建中、数据清理中，验证仍可创建新池。
- 分别通过阵列修复任务和热备盘自动补位构造“修复中”，验证两类任务来源与目标池对应正确，界面均显示“修复中”且不会使创建按钮置灰。
- 单独构造阵列已经损坏但未执行挂载的存储池，验证仍可创建新池；随后发起损坏池挂载，验证进入“损坏池挂载中”后创建按钮立即置灰。
- 构造一个允许状态与一个禁止状态同时存在，验证禁止状态优先。
- 验证禁止状态开始和结束时按钮自动切换，不依赖退出页面或手动刷新。
- 验证列表为空、全部正常、存在已降阶池以及无空闲磁盘等边界；区分“任务互斥置灰”和其他置灰原因。

### 10.2 P0：阵列类型与状态流转

- 验证 Single、JBOD、RAID0、单盘 TRAID：`创建中 → 正常`。
- 验证多盘冗余阵列：`创建中 → 同步中 → 正常`。
- 验证有冗余阵列进入同步中、无冗余阵列进入正常后，创建按钮恢复，并可以创建下一个存储池。
- 验证创建阶段尚未结束时不能再次创建。
- 通过存储管理页面验证状态切换过程中没有短暂误开放、重复提交或出现两个创建中任务；不扩展到接口直接并发测试。

### 10.3 P0：多存储池任务展示与隔离

- 多个存储池同时同步时，列表、状态、进度、名称和任务结果一一对应。
- 同步任务与阵列修复、热备盘补位修复、迁移、添加磁盘、更换磁盘、重建、数据清理等任务组合执行。
- 同步过程中拔出一个阵列成员盘，验证产生降阶通知、当前同步继续、同步完成后存储池变为已降阶，并且其他同步任务继续执行。
- 同步过程中拔出全部阵列成员盘，验证存储池变为损坏，其他存储池任务不受影响。
- 验证已降阶和损坏状态不会单独使创建按钮置灰，仍可继续创建新存储池。
- 页面刷新、切换版块、退出后重新登录，任务展示仍与实际状态一致。

### 10.4 P0：中断恢复

- 多任务同步过程中断开管理端与 NAS 的网络连接，恢复后验证任务记录保留并继续展示。
- 中断 NAS 自身网络连接或网络服务，恢复后验证任务记录保留并继续展示。
- 多任务同步过程中异常断电，开机后重点验证任务记录仍然存在，并正确展示重建中等实际状态。
- 在创建中、刚进入同步中、同步接近完成等不同时间点执行中断。
- 断电测试不要求同步进度必须从原百分比继续，也不重点验证内部恢复阶段。

### 10.5 P1：通知

- 每个存储池同步完成后存在对应的同步完成通知。
- 存储池进入已降阶状态后存在对应的降阶通知。
- 多个存储池同时或先后发生相关事件时，验证每个存储池都有对应通知且池标识正确。
- 本需求不检查通知的准确文案、通知级别、展示位置、顺序和去重规则。

### 10.6 P1：性能与稳定性

- 不预设并行任务数量上限，在可用磁盘和环境允许的范围内逐步增加同时同步或执行后台任务的存储池数量，监控 CPU、内存和磁盘 I/O。
- 验证整个监控期间 CPU 始终低于 80%、内存始终低于 90%；达到任一红线即判定不通过并提交开发优化。
- 观察峰值、持续高占用、页面响应和服务稳定性。
- 如果测试中发现系统卡顿、死机、任务异常或资源达到红线等重大问题，记录可稳定复现的问题规模，并与产品共同评估是否需要制定并行任务数量上限。

### 10.7 P0：删除互斥与后端闸门

- 验证创建中、删除中分别禁止删除其他存储池，挂载中不单独禁止删除其他存储池。
- 验证创建或删除任务结束后，删除按钮在当前页面自动恢复。
- 使用两个管理员会话或自动化方式验证创建与创建、创建与删除、删除与删除的临界冲突，响应和实际任务保持一致。
- 验证损坏池挂载中时绕过页面提交创建请求仍被后端拒绝。
- 当前不把可用池挂载中直接建池、挂载中直接删除其他池作为独立后端专项；需要技术方案确认后再决定是否补充。

### 10.8 P0：序号、幂等与失败恢复

- 删除一个或多个存储池后，新建存储池按最小空洞规则复用序号，现存池序号保持不变。
- 两个会话同时创建不同存储池时，已创建记录序号唯一，不出现假成功。
- 两个会话使用同一组磁盘提交等价请求时只产生一个有效任务。
- 客户端超时后重试等价请求时，不产生第二个有效任务或重复占用。
- 创建、删除任务失败后状态恢复真实值，保留明确失败记录，释放锁和资源，并可重新提交。
- 删除中异常断电后任务记录保留，重启后按恢复设计继续执行或明确失败。

### 10.9 P1：权限与国际化

- 无创建权限和无删除权限用户均不能绕过现有权限限制。
- 中文、英文及其他受支持语言下，状态和提示与对应语言包一致，不裸露占位符或语言键。
- 任务进行中切换语言后文案及时更新，后台任务标识和真实状态保持不变。

## 十一、当前结论

本需求的核心不是取消所有创建限制，而是把限制范围从“存在任何存储池后台任务就禁止创建”缩小为：

> 只有存在创建中、删除中或挂载中的存储池时禁止创建；正常、已降阶、损坏及其他允许状态不会单独阻止创建，后台任务可以按规则与后续存储池创建并行执行。

人工修订后的正式测试用例共84条，编号为`STO-POOL-01~STO-POOL-84`。本版需求已经补入删除互斥、后端闸门、序号复用、幂等、失败恢复和国际化规则。

当前仍需后续确认并与用例同步的事项：

1. `STO-POOL-07`的前置条件、输入数据和预期结果已使用“修复中”，但操作步骤仍写有“查看阵列修复中存储池”；`STO-POOL-76`仍将“阵列修复中”和“修复中”列为两个界面状态。本需求暂以07、08的人工修改方向为准，后续应把07的操作步骤及76的状态清单、预期结果统一为“修复中”，并通过触发来源区分任务。
2. 可用池挂载中时绕过页面直接提交创建请求，是否必须由后端硬闸门拒绝，当前没有独立保留用例，需要产品和技术方案确认。
3. `bug`列统一填写的“21”按测试资产关联信息处理，不作为功能规则写入需求正文。
