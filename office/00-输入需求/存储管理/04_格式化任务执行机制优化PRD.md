
# 格式化任务执行机制优化

---

## 一、目前是什么状况？

当前用户对**卷 / USB 共享文件夹**执行格式化操作时，如果正在进行文件上传、下载、复制等 I/O 操作，系统**设置 2 分钟超时**。

由于采用固定超时机制：

- 若当前 I/O 操作在超时时间内结束，则格式化成功执行
- 若 I/O 操作未结束，则格式化失败，需要用户重新发起格式化

该机制导致格式化结果**具有随机性**，用户无法预期格式化是否能够成功完成，影响使用体验。

**Windows 行为参考**：

上传文件时执行格式化，上传不会被打断，上传过程中状态一直是"格式化中"，等上传完毕后会立即执行格式化。

**已知 BUG**：

> 【在文件上传中执行卷的格式化操作后结果不唯一】
> <https://www.tapd.cn/tapd_fe/58480755/bug/detail/1158480755001038171>

---

## 二、通过实现需求达到什么目的？

优化格式化的执行机制，当卷 / USB 共享文件夹存在正在执行的文件操作时，格式化任务**进入等待状态**，而不是固定等待 2 分钟后超时失败。

系统应等待当前已开始的文件操作正常完成，在卷 / USB 共享文件夹满足格式化条件后**自动执行格式化**，无需用户再次操作。

**实现后可带来以下价值**：

| 价值 | 说明 |
|------|------|
| **提高成功率** | 避免因固定超时导致失败 |
| **保证数据传输** | 已开始的数据传输正常完成，避免人为中断文件传输 |
| **符合用户预期** | 提升用户体验，使格式化行为更加符合用户预期 |
| **降低重复操作** | 减少用户重复执行格式化操作的成本 |

---

## 三、在哪一个版块 / 位置上实现？

- **卷 → 格式化**
- **USB 设备 → 格式化**

---

## 四、详细功能要求

### 4.1 格式化请求

用户点击"格式化"后，系统首先检测当前卷 / USB 共享文件夹是否存在正在执行的文件 I/O 操作。

| 情况 | 行为 |
|------|------|
| **情况一：无任何 I/O** | 立即开始格式化 |
| **情况二：存在正在执行的 I/O** | 系统不立即格式化，也不进行固定时间等待。格式化任务进入等待状态，界面保持"格式化中"（或新增"等待当前文件操作完成"状态） |

### 4.2 等待期间

- 已开始的文件操作**允许继续执行**直至完成
- 不允许新的文件写入任务进入该卷（如可实现）
- 用户**无需再次点击**格式化

### 4.3 I/O 完成

- 系统持续检测卷占用状态
- 当所有影响格式化的 I/O 操作结束后：
  - **自动开始格式化**
  - 无需用户再次确认或重新点击格式化

### 4.4 等待超时（可选，超时时间可配置）

若卷长时间处于占用状态（例如持续存在文件操作或系统进程占用）：

- 可提示用户：

  > 当前卷仍存在正在执行的文件操作，请稍后重试。

- 超时时间建议研发评估，可配置
