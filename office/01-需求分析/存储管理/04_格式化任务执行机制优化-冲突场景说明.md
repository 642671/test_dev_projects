# 与格式化冲突的场景说明

> 适用 PRD：`04_格式化任务执行机制优化PRD.md`
> 说明：本文档梳理“卷 / USB 共享文件夹”执行文件系统格式化时，哪些场景会与格式化发生冲突（占用），以及这些占用通常可中断还是不可中断。由于后端尚未给出可中断/不可中断的判定清单，本文档的“初判可中断性”仅用于测试设计参考，最终以研发/技术方案与实际环境实测为准。

## 一、为什么格式化会冲突

格式化卷或 USB 共享文件夹，本质是把对应文件系统重新初始化，要求目标在格式化期间能够被安全卸载（unmount / 释放占用）。只要下面任一条件成立，目标就处于“被占用”状态，格式化无法立即执行：

1. 目标上仍有正在进行的文件读写（上传、下载、复制、移动、删除）。
2. 目标被外部协议客户端持续连接并占用（SMB、NFS、AFP、FTP、WebDAV 等）。
3. 目标被服务、应用或容器挂载使用，或存在进程持有打开句柄（文件句柄 / 挂载点 busy）。
4. 目标正承载系统任务（快照、备份、同步、复制、迁移等）。
5. 目标处于特殊状态，如只读、降阶、损坏、文件系统异常，导致格式权限受限。

当目标处于占用状态时，后端按 PRD 的机制处理：

- 能安全中断的 I/O → 中断后立即格式化。
- 不能安全中断的 I/O → 等待占用解除后立即格式化，且无固定超时，一直等待。

## 二、场景分类与初判可中断性

下表按占用来源分类，给出冲突原因、前端表现与可中断性初判。

| 编号 | 场景 | 冲突原因 | 前端表现 | 初判可中断性 | 建议验证点 |
| --- | --- | --- | --- | --- | --- |
| S1 | Web 文件管理器上传 / 下载 / 复制 / 移动 / 删除 | 前台文件任务占用目标 | 任务显示处理中或格式化等待中 | 通常可中断 | 发起格式化后任务是否被取消、文件是否被中断、格式化是否自动执行 |
| S2 | SMB / NFS / AFP / FTP / WebDAV 客户端读写 | 远程客户端保持连接并在读写 | 格式化进入等待状态 | 大概率不可中断 | 客户端是否被强制断连、读写是否继续、释放后是否自动格式化 |
| S3 | 媒体服务 / 缩略图扫描 | 媒体库索引或缩略图生成占用卷 | 格式化等待或明确提示占用 | 视实现（部分可暂停） | 扫描是否被中止、完成后是否自动格式化 |
| S4 | Docker / 容器挂载卷 | 容器 bind mount 或数据目录占用 | 格式化等待或提示占用 | 大概率不可中断 | 容器是否被强制结束、释放后格式化是否可执行 |
| S5 | 快照创建 / 删除 / 回滚 | 快照子系统持有卷 | 格式化等待或提示冲突 | 视实现 | 快照任务是否被中断、完成后是否自动格式化 |
| S6 | 备份 / 同步 / 复制 / 迁移任务 | 系统任务持有卷或 USB | 格式化等待或提示占用 | 视实现 | 任务是否正常完成、格式化是否随后自动执行 |
| S7 | 目标已挂载 / 存在挂载点 busy | 文件系统无法卸载 | 格式化失败或进入等待 | 不可中断（需先释放挂载） | 是否存在 “target is busy” 等后台报错、界面提示是否清晰 |
| S8 | 目标只读 / 降阶 / 损坏 / 文件系统异常 | 目标处于受限状态 | 格式化按钮受限或明确报错 | 不可格式化或需先修复 | 按钮是否置灰、是否有明确原因、是否存在残留 |

## 三、可中断 / 不可中断的判断口径（初判）

由于后端未给出明确清单，建议按“占用 I/O 是否由系统可靠管理、能否安全取消”来初步划分：

- **可中断**：系统内部可管理、可安全取消的任务，例如 Web 文件管理器发起的上传/下载/复制等文件任务。
- **不可中断**：外部进程或远程会话持有的 I/O，系统无法安全强制结束，例如 SMB/FTP 客户端正在写入、容器挂载、内核持有的 busy 挂载点。
- **视实现**：媒体服务扫描、快照、备份/同步等系统任务，是否可中断取决于具体实现，需与后端确认。

## 四、测试建议

1. 为每个冲突场景构造真实的“占用”状态，而不是只靠提示。
2. 观察并记录三层表现：页面（是否需要等待/是否提示占用）、API（任务状态与返回）、Linux 后台（`mount`、`lsof`、`fuser`、`df -h`、`lsblk`、`/proc/mdstat` 等）。
3. 对“不可中断”场景重点验证：等待期间占用不被强制打断，占用释放后格式化自动执行。
4. 对“可中断”场景重点验证：被中断的文件处理结果是否干净，无残留、无半格式化状态。
5. 验证前端提示、API 返回、后台实际状态三者一致，避免“前端提示失败但后台已经执行”或“前端成功但后台未执行”。

## 五、待确认项

- 等待状态的具体文案。
- 可中断 / 不可中断服务的完整判定依据（哪些进程/任务可中断）。
- 媒体服务、快照、备份/同步任务是否可中断。
- 加密选项是否适用于“整个硬盘”以及只针对分区。
- 只读 / 降阶 / 损坏等特殊状态下，格式化入口的可用性。
